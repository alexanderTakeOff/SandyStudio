## Settings (screen 18) — ⭐ Reference design pattern

Director's call-out: «one of the more pleasant pages». Why — and what to reuse on the other pages.

### What works in Settings (patterns):

1. **Wide cards, full screen width** — no narrow drawer
2. **Section headers + small contextual description** (`PROVIDERS · Global tier — applies to every episode unless overridden per-stage`)
3. **Theme cards with visual preview** (gradient swatches) — visual scan faster than text
4. **Per-row 3-column layout**: name+desc · dropdown · LIVE pill + toggle
5. **LIVE pill consistent** with other pages — single visual language
6. **Minimal info per row**: label + 1-line context + control. No redundancy.
7. **Auth.md §5 note small** at the end of AMBIENT BACKGROUND — doesn't distract

### 🎯 Settings design doctrine — port to other surfaces

| Surface | Settings gives the pattern → apply like this |
|---|---|
| **Inbox cards (Dashboard + /inbox)** | Convert from narrow card blocks into Settings-style wide rows: thumbnail + filename · APPROVE/REVISE/REJECT on the right. 1 row = 1 item. |
| **Pipeline DAG (Episode page)** | Settings-style stage rows: emoji + role name + status pill on the right. Optional collapse of approved cluster. |
| **Episode header** | Settings-style top section: title + one metro line (status · mode · budget). Actions in overflow `…` |
| **Drawer detail (EREF / Asset / Brief)** | Settings-style sections, not fixed-width — full screen modal with shared columns |
| **Activity feed item** | Settings-style row: agent emoji + title + meta + time (right) |

This becomes a **Wave 1 supplement**: «anything that doesn't look like Settings — align to it». Wave 2 (layout) and Wave 3 (visual) extend the same language.
