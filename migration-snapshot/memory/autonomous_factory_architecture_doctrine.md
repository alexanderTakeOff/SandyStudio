**Согласованная архитектура автономной фабрики (Director + Тео, 2026-07-03, после E14 live run).**
Это North-Star целевой архитектуры Mode-3. Отчёт: `C:\SandyStudio\RUN-REPORT-E14.md` §3–4.

**Главное открытие:** проблема автономии — НЕ «кто жмёт кнопку», а **чёткое понимание СОСТОЯНИЯ**.
Кто угодно (код ИЛИ сильный агент), кто ясно видит состояние и знает цель — дойдёт. Сегодняшняя
фабрика = линейный конвейер со слабым состоянием → любое вмешательство теряет контекст и гонит
заново (дубли/перерасход/тупик). Все находки прогона F1–F8 — ОДНО это явление, не 8 багов.

**Роли ОС:** матрица состояния (данные, инвариант, + рычаг стоимости мозга) → **дирижёр** (сильный
LLM/Opus: читает матрицу, мало высокоуровневых решений, держит нестандарт) → **мышцы** (код:
approve-после-PASS, фанаут, стич, ретрай, музыка — детерминированно, бесплатно) → **чувства**
(тонкий агент: следит, наполняет матрицу, будит дирижёра) → **гейты** (человек/делегат: reserved +
хард-лимиты, сдерживают ошибки дирижёра).

**6 принципов:** (1) состояние=инвариант, драйвер=выбор; (2) дирижёр ДЕЛЕГИРУЕТ механику коду,
не микро-менеджит; (3) вмешательство инвалидирует ТОЛЬКО downstream-конус, остальное reused —
stale-anchor это примитив в зачатке, ОБОБЩИТЬ не патчить; (4) **ВЕСТИ≠ЧИНИТЬ** (Полина-оператор
ведёт эпизоды; Тео-инженер только на правку кода фабрики); (5) Полина-дирижёр справится при 3
условиях — сильная модель + дана матрица + ошибки сурфейсятся человеческим языком; (6) стоимость:
генерация ~90% (архитектурно-независима), мозг ~10% → сажать сильнейший мозг в дирижёры.

**Кто был кем в E14:** Тео играл Директора И тонкого-агента-драйвера (держал состояние вручную,
~20 нуджей); Полина = только руки; авто-watchdog отсутствовал. → тестировали «сильный драйвер +
чёткое состояние», НЕ «Полина self-drive». Подтверждено: Полина-на-Opus + эта конфигурация +
стабильная фабрика справилась бы как Тео, за ~$10 мозг/серия.

**Дорожная карта (PR по порядку):** 1) матрица состояния (SSOT + обобщённый freshness/downstream-
инвалидация); 2) код-механика над матрицей (Tier-0 auto-advance в границах плана+хард-лимитов +
self-heal); 3) сурфейс ошибок человеческим языком; 4) Полина→сильная модель как дирижёр. Первый
быстрый PR: F8 музыка ([[backlog_td_stitch_gate_music_and_exclude_retrigger]]).
