# ТЗ — узел EREF в pipeline-view: под-этапы по кадру + версионность

Director 2026-06-19: «как мне увидеть кто на какой стадии, отдельно запустить дизайнера/
критика/артиста, разобраться с версиями — какой-то бардак, вложенность». Корень: UI не
показывает под-цепочку EREF по кадрам; «plan»(дизайнер+критики) и «image»(артист) сливаются;
версии и regen-cap невидимы; ошибки приходят пересказом Полины, не дословно. Связь:
[[backlog_td_pipeline_full_process_surface]], наблюдаемость.

## Истинная цепочка EREF (по коду — НЕ вложенность, а последовательность)
`Раскадровка APPROVED → (WCHK) → ДИЗАЙНЕР пишет ПЛАН → КРИТИК EPREV проверяет план →
КРИТИК CREAD (читаемость плана) → [аппрув плана] → АРТИСТ (execute-from-plan) → КАРТИНКА(якоря)`
- exec-eref-designer.nextEvent → exec-eprev/review-plan
- exec-eprev.nextEvent → exec-cread/review-ref-plan
- exec-eref(execute-from-plan).nextEvent = **null** (артист никого назад не зовёт)
Артист — ПОСЛЕДНИЙ отдельный шаг, не родитель критиков.

## Три уровня узла

### L1 — карточка стадии EREF (свёрнуто)
- Заголовок «Episode References (EREF)».
- Прогресс: «3/32 кадра с якорем · 1 заблокирован · 2 на ревью · 1 capped».
- Общий чип состояния + chevron «развернуть».

### L2 — строки по КАДРУ (развёрнуто)
Одна строка на shot (SH01, SH02 …), по порядку. В строке:
- shotId + thumbnail текущего APPROVED-якоря (или плейсхолдер).
- **Горизонтальная мини-цепочка из 4 пилюль:** `[Designer]→[EPREV]→[CREAD]→[Artist]`, слева
  направо (чтобы порядок был очевиден, без иллюзии вложенности). Каждая пилюля = цвет статуса
  + иконка: pending / running / PASS / REVISE / FAILED / APPROVED.
- Сводка: «Plan v04 · REVISE · якоря нет» либо «Plan v03 APPROVED · anchor#2 REVIEW».
- **Индикатор regen-cap:** «regens 4/5» или красный «CAPPED» (делает невидимый блок видимым —
  именно cap молча застопорил SH01).

### L3 — раскрыть кадр → детали (ДВЕ РАЗДЕЛЬНЫЕ дорожки)
Ключевое решение UX: **Plan-track и Image-track визуально разделены** — убивает путаницу
«plan vs image».

**Plan-track (Дизайнер + Критики):**
- Версии v01..vN списком. Каждая: статус (DRAFT/REVIEW/REVISION/APPROVED/INVALIDATED),
  вердикт EPREV (PASS/REVISE + failed-checks по ховеру), вердикт CREAD, производитель
  (агент + МОДЕЛЬ, напр. «EXEC-EREF-DESIGNER · gemini-2.5-flash»), таймстемп.
- ОДНА помечена CURRENT/APPROVED; superseded/INVALIDATED — приглушены, но ВИДНЫ (нет скрытых
  версий — лечит «путаницу версий»).
- Клик → контент плана (промпт), чтобы можно было ПРОЧИТАТЬ (а не гадать причину).

**Image-track (Артист):**
- Попытки якорей (start/end), каждая: статус, thumbnail, ИЗ КАКОЙ версии плана сгенерён,
  approved/superseded.

**Действия — РАЗДЕЛЬНО (прямой ответ на «как запустить каждого отдельно»):**
- «Re-author plan» (Дизайнер) → новая версия плана; критики авто-следом (новый план обязан
  пройти ре-ревью — это by design). Кнопка ЗАблокирована если capped — с подписью причины.
- «Re-review plan» (EPREV/CREAD) → перепроверить ТЕКУЩИЙ план, без новой версии.
- «Approve plan» → открывает артиста.
- «Generate image» (Артист) → только из APPROVED-плана; ЗАблокирована если нет approved-плана
  (с подписью почему) — отдельная кнопка от «plan», чтобы не путать.
- «Reset regen-cap» (Director-only) → разблокировать запоротый кадр.

## Жёсткие UX-правила (из боли этой сессии)
1. **Plan ≠ Image — разные кнопки и дорожки.** Источник путаницы «ретригер артиста запустил
   дизайнеров»: на деле жалась plan-кнопка (дизайнер+критики), не image. Развести.
2. **Версии явные**, current/approved подсвечена, superseded видны и приглушены.
3. **Regen-cap виден** на строке кадра; capped-кадр явно помечен + причина.
4. **Вердикты инлайн** (EPREV/CREAD PASS/REVISE) + failing-checks по ховеру.
5. **Ошибки — ДОСЛОВНО** на нужной под-стадии (текст agent_failed), НЕ пересказ ассистента
   (лечит F18/F22: gemini-домыслы про «scene_master»). «requires shotId», «regen cap reached»
   должны быть видны как есть.
6. **Провенанс везде**: агент+модель на каждом артефакте → «кто написал» всегда очевидно.
7. **Никакой вложенности** в рендере: 4 под-стадии — строго слева-направо, артист последний.
