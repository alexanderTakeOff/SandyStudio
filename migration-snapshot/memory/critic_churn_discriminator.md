**Critic Churn Discriminator — the factory's FIRST slow-loop (adaptation) sensor.**
Shipped 2026-07-15 (master `44dffb11`, ===5===). Sibling of `computeScorecard` (the
reflex sensor). Answers, per critic, per episode: was the churn the **critic too
hard/noisy** (false-rejects) or the **producer weak** (work that legitimately
failed)? — and proposes the fix.

**Where it lives (subtract-first, 0 migrations):**
- `webapp/lib/agents/scorecard/critic-discriminator.ts` — `computeCriticDiscriminator`
  (pure read) + `proposeCalibration` (pure zone policy).
- Rides the EXISTING `episode_scorecard.metrics` JSONB (`metrics.critic_discriminator`)
  and the EXISTING `sandystudio/exec-pub/published` trigger (`episode-scorecard.ts`).
  No new table, no new hook — computed inside `computeScorecard`.
- Escalation in `refreshScorecard` (`persist-scorecard.ts`): `escalate`-zone
  proposals → Director Inbox as `rule_proposal` (idempotent on signature,
  **published-phase only** so snapshots/backfills stay quiet). `auto_safe` stays
  in metrics with **no Director touch** (the Director's trap: self-improvement must
  not become a 7th human touch). `none` = healthy.
- PART C: `/factory` page (`app/(studio)/factory/page.tsx`) + `/api/factory` +
  sidebar entry — North-Star trends across episodes.

**THREE axes, never one (this is the whole point):**
1. **Critic churn** = REVISE bounces per artifact VERSION (not runs/shot).
2. **Producer first-pass reject rate** = Director-rejected first-pass creative / shot.
3. **Paid regens** = superseded (INVALIDATED) plan versions.

**The metric-artifact lesson (why axis 1 is defined that way).** E28 read "CREAD
2.45×/shot" — looked like critic churn, was a **measurement artifact**: 54 runs,
only **3 REVISE** (94.5% first-pass PASS). The "churn" was idempotent re-checks of
ref_plans the **Director regenerated by HAND** (`approval_revision` → Designer
re-authors → re-check; proven in `activity_events`), not the critic bouncing work.
**Naive runs/shot mis-diagnoses every episode with re-trigger waves.** Verify
against runtime rows, collapse tool-expanded events — [[overlay_agent_reports_on_server_logs]].

**The sensor beat the hand-forensic.** My manual PART A (CREAD only) said "critic
healthy, 3 REVISE." Running the sensor across ALL critics surfaced a bigger gap I
missed: **EXEC-VPREV (video critic) 13 REVISE on V04/V11/V12** = producer gap on
the Animator, larger than storyboard-R02. OPEN follow-up: separate forensic on
whether VPREV V04/V11/V12 is producer-weak or critic-too-hard.

**R02 fix pattern (anti-additivity).** The "false-success beat is its own shot"
hard-rule ALREADY existed in `storyboarder-situational-comedy`. Adding more text =
useless. The real gap was the **pre-submit self-check didn't enforce it** → added
one self-check step + a QA row in `agents/exec/storyboarder.md` so EXEC-SB catches
R02 itself, before the critic. Rule exists but not in the final gate = the pattern.
