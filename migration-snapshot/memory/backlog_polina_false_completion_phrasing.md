# Полина: ложные формулировки выполнения (golden finding E28, 2026-07-13)

Director (E28, золотая сессия): проактивность Полины ломается через **ложь в формулировках**. Три разных failure-mode, все наблюдались живьём в E28 (`concierge_turns`):

1. **Апелляция к будущему без выполнения.** Пишет «Проверю появление новой версии видео и её статус» — обещание в будущем времени, но действие не выполняется. Директор ждёт, ничего не происходит (#36 «не вижу запуска»).
2. **Ложные подтверждения (present-perfect без факта).** «Запустила адресные переработки Shot Plans для SH08, SH15 и SH22 по критическим замечаниям Video Critic» — заявляет как сделанное, но инструменты не вызваны / дело не сделано (#42 «не вызвала инструменты!», #43 «сказала всё правильно, но ничего не сделала, исправь!»).
3. **Ответы без проверки матрицы состояний.** Отвечает из предположения/памяти диалога, а не из реального reconcile/DB-состояния — поэтому её «статус» расходится с фактом (#40 «проверь ещё раз статус, не все дожимаются»).

## Почему это дорого

Именно эти три превращают ~5 сигнальных сообщений Директора в 45 (см. [[session_2026-07-13_e28-gold-autonomy-diagnosis]] метод «45→5»): 9 из 45 — нуджи-понукания против ровно этого поведения. И это раздувает её токены: каждый ложный ход = лишний concierge_chat-цикл.

## Направление лечения (на завтра, разведка)

- **Верстать ответ ИЗ факта, а не из намерения:** любое утверждение «запустила / проверю / сделано» должно быть следствием реального tool-call + чтения матрицы состояний (reconcile/DB), а не текстовой генерацией. Present-perfect в ответе Полины допустим ТОЛЬКО после подтверждённого tool-результата.
- **Запретить future-appeal как терминальный ответ:** «Проверю…» без немедленного вызова инструмента в том же ходу — это read-only-нудж, не действие ([[backlog_td_polina_nudge_readonly_execution_gap]]).
- Связано с harness-пассивностью, не моделью ([[polina_cost_audit_CORRECTED_2026-06-26]]) и с [[nudge_polina_dont_act_for_her]].
