# Полина — лог сопротивления и структурных блоков (E07 smoke, 2026-06-11)

Контекст: Director приказал прогнать E07 smoke полностью «через Полину» от его имени
(Тео замаскирован под «Александр» в team-chat), упирания фиксировать сюда и
проталкивать через базу, разбор потом.

## Случай 1 — отказ createEpisode (НЕ её вина, структурный)

- Запрос «Александра»: создай E07 на базе брифа E06, 16:9, $15.
- Её ответ: проверила серию/эпизоды корректно (E07 нет, E06 есть), затем:
  «Сейчас мутацию делать нельзя: автономный триггер прямо запрещает createEpisode.
  Director должен явно подтвердить» — и стала ждать.
- Причина: тред был mode 1 без episode_id → auto-react отдаёт ей READ-ONLY
  поверхность инструментов (q9-дизайн: bold-инструменты только в mode 3/4,
  mode берётся из episodes.governance_mode треда). Плюс verbal-approval
  сканирует только role='director' ходы — посты через /api/team-chat/post
  идут role='system' (kind=claude_message) и одобрением НЕ считаются.
- Вердикт: поведение ПРАВИЛЬНОЕ по её контракту. Это не упрямство.
  Системный вывод: канал claude_message не может дать Полине ни одобрение,
  ни bold-режим в эпизодно-несвязанном треде. Разруливается линковкой треда
  к mode-4 эпизоду (сделано: thread 0d5de76a → E07).

## Дефект 2 — q9 bold-mode был МЁРТВ из-за middleware (исправлено 44958ec)

- Все мутационные тулзы Полины ходят в Director-only роуты по HTTP с
  Bearer EXEC_DIR_AI_TOKEN (auto-react не имеет cookie Director).
- middleware.ts редиректил ЛЮБОЙ запрос без Supabase-cookie на /login (307 → HTML)
  ДО route-handler'а → requireDirector с bearer никогда не достигался.
- Значит вся q9-автономия (Polina-boldness, 2026-06-09) ни разу не могла
  выполнить мутацию server-to-server: E03 mode-4 прогон ехал на factory
  auto-chain, не на её инструментах. Латентный дефект класса
  [[backlog-observability-failures-not-surfaced]].
- Фикс: middleware пропускает /api/* с Authorization-заголовком до route-guard'ов
  (невалидный токен → честный 401). Commit `44958ec` master.

## Дефект 4 — EXEC-SREV double-fire (E07, 12:38)

- REV-script_qa v1 (12:38:24) и v2 (12:38:41), оба PASS, оба claude-sonnet-4-6,
  одинаковый input (28693 tok), лишние ~$0.12.

  но та же ветка).
- Mid-run не чинил. TODO следующего спринта: вынести SREV из computeNextEvents
  по образцу 4ff5262 + тест по образцу next-events-readability.test.ts.

## Дефект 4b — SREV-дубль каскадирует: ДВЕ APPROVED раскадровки (12:4x)

- Два REV-script_qa апрува → два запуска EXEC-SB → STB-storyboard v1 И v2,
  обе APPROVED (~$0.5-1 лишних). Класс «two APPROVED storyboards» = тот же,
  что ломал E02 final-cut (stale .find()).
- Каждая раскадровка тянет свой critic chain (CREAD×2 → WCHK×2 ожидаемы).
  Решение в моменте: НЕ делать DB-хирургию mid-flight; точка защиты от
  двойной ПЛАТНОЙ траты — hasJob(EXEC-EREF-DESIGNER) на REV-world_check ветке.
- Урок: фикс «критики только через critic chain» (4ff5262) надо завершить для
  ВСЕХ исполнителей в computeNextEvents — SCR→SREV ветка осталась двойной
  (producer spec.nextEvent + rich router), и дубль size растёт вниз по цепи
  лавинообразно. Корневой фикс один: ЛЮБОЙ агент должен иметь ровно ОДИН
  диспатч-источник.

## Дефект 5 — gemini anchors: квадрат + изометрия + «честность» метаданных

- Факт 1: anchors v1/v2 вышли 1024×1024, а metadata/description заявляли
  1536×1024 (провайдер репортил НОМИНАЛЬНЫЙ size-hint). Фикс d4c02de:
  imageConfig.aspectRatio (16:9/9:16/1:1 по семантике size-ключа) + реальные
  размеры из PNG IHDR.
- Факт 2 (Director, 2026-06-11): стиль кадра — «чистая ИЗОМЕТРИЯ», а не canon
  flat 2D (Тео сперва оценил кадр как чистый — ошибка). Gemini тянет в
  изометрическую перспективу даже при flat-2D промпте и refs. Пока НЕ чиним
  (директива «оставь как есть»), кандидат в negative-список eref-designer
  skill: no isometric perspective.
- Факт 3: cost_usd=0 у gemini (free tier) → бюджет эпизода не двигается на
  anchors; при переходе на платный tier кост-модель надо включить.
