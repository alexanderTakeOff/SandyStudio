## Зачем этот прогон

Директор усомнился в парадигме студии: «много дешёвых мелких моделей + харнесс-обвязка»
даёт сложную, негибкую, сильно формализованную и потому хрупкую конструкцию. Решение
«переделывать студию или строить новое» **нельзя принять рассуждением** — нужны числа.

Этот прогон их даёт. Он же закрывает долг, записанный в `PLANET.md`: *«производственная
автономность НЕ протестирована; закрывается первым чистым эпизодом бриф→финал»*. То есть
это **не дрейф с текущей планеты, а её обязательный пункт**.

## Правила прогона

- **Веду прямыми вызовами.** Агентов-посредников между замыслом и промптом нет: промпт
  пишет тот, кто держит замысел. Инструменты (генерация, монтаж, загрузка) — используются.
- **Лист ожиданий пишется ДО генерации.** На каждую единицу работы — «приму, если»,
  три-пять проверяемых пунктов. Это же лист приёмки. Доктрина §8–§11.
- **Каждый шаг записывается сразу**, не в конце сессии.
- **Директор утверждает** темы, деньги, публикацию. Остальное — моё, с показом результата.

## Что меряем — приборы прогона

| Прибор | Как снимать | Зачем |
|---|---|---|
| **Время** | от первого действия до готового к публикации | сравнение с конвейером |
| **Деньги: генерация** | `budget_log`, как раньше | себестоимость продукта |
| **Деньги: разум** | токены по тарифам API, НЕ по подписке | честная себестоимость |
| **Работа против трения** | доля ходов на работу vs на борьбу с системой | смета на будущий пульт |
| **Решения человека** | число содержательных решений Директора | автономность |
| **Дефекты до траты** | сколько поймал лист ожиданий ДО генерации | проверка доктрины §8 |

## Две гипотезы под проверку

1. **Слепая приёмка.** Тот же ум, чистый контекст, только артефакт + лист ожиданий + канон,
   без истории создания. Найдёт ли то же, что нашёл бы Директор?
   **Убьёт гипотезу:** пропустит дефекты, которые человек видит сразу.
2. **Лист ожиданий вперёд.** Писать «приму, если» до генерации.
   **Убьёт гипотезу:** доля дефектов, пойманных до траты, окажется незначимой.

## Первые шаги, когда Директор даст старт

1. Выбрать серию и тему (**решение Директора**) и назвать потолок трат.
2. Написать лист ожиданий на эпизод: «приму, если» — до всякой генерации.
3. Дальше по методу: замысел словами → лист ожиданий по кадрам → канон-минимум по
   ПРОЧТЕНИЯМ → пилотные кадры → веер → движение → сборка → упаковка → публикация.
4. Записывать приборы по ходу, не в конце.

## Что решает Директор до старта

- Серия и тема эпизода.
- Потолок трат на прогон.
- Публиковать ли результат по-настоящему (иначе цепочка обрывается на упаковке и
  дистрибуционная часть замера остаётся неизмеренной).
