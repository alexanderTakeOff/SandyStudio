## A. Прибито гвоздями к песочным часам

Наследие одного сериала, вылезшее при втором. Все пункты подтверждены чтением кода.

### A1 🔴 Тема = «visual gag engine» в словаре инструмента Полины

`webapp/lib/concierge/tools/themes.ts` — оба описания тула определяют тему как
«reusable visual gag engine», а `proposeTheme` требует «mechanism, escalation, why it
fits the series». Для SS-S17 тема — это **тезис-карточка** (Bible §34 Stage 2: тезис ·
личная призма · границы применимости · практическое следствие · хук · источники · риск
банальности). Полина, читая это описание на Pragmatico, будет авторить комедийные
движки против библии канала.

**План:** описание тула сделать нейтральным — «episode engine, форму которого объявляет
Библия серии», а конкретную форму подмешивать из Библии в системный промпт (там уже
есть per-series контур, `system-prompt-builder`). НЕ плодить второй тул для эссе.

### A2 🟡 Тот же протёк в слое хранения

`webapp/lib/api/series-themes.ts`, шапка файла: «A theme is a reusable visual gag engine
for an episode». Комментарий, но именно из него следующий агент выведет форму.
**План:** переписать шапку в терминах роли, не жанра.

### A3 🔴 Пара скилл-тем построена на gag engine

`.claude/skills/series-episode-theme-generation` + `-selection`: объект — gag engine,
гейты отбора включают «gag-engine capacity», «silent readability», «character physical
fit». Для голосового эссе-канала без героя это чужая форма — шоураннер PRAGMATIC не
смог ими воспользоваться и собрал портфель руками.
**План:** уже висит отдельной задачей (`task_69938c0e`): абстрагировать пару, объект →
«движок эпизода», гейты разделить на универсальные и объявленные Библией. Anti-additivity:
абстракция существующей пары, НЕ второй скилл для эссе.

### A4 🟡 Дефолт формата — landscape

`webapp/lib/agents/delivery-targets.ts:53` — фолбэк `['youtube_landscape']`. Для
shorts-first канала нейтральный дефолт оказывается ландшафтным (наследие Sandy-эпохи).
Сейчас обойдено: `series.metadata.delivery_targets = ['youtube_shorts']` у SS-S17.
**План:** решить, остаётся ли ландшафт студийным дефолтом или дефолт переезжает в
паспорт канала. Не менять молча — у Sandy есть long-form.

### A5 🟡 Категория заливки по умолчанию — Comedy

`specs/distribution/youtube.md` §43: фолбэк `categoryId '23'` (Comedy). Для эссе-канала
неверно; обойдено `publish_defaults.category_id = '22'` (People & Blogs) в паспорте.
**План:** снять жанровый фолбэк на уровень паспорта, в коде оставить «нет значения →
не отправлять поле».

## C. Структурные дыры (модель данных, не инструмент)

### C1 🔴 У сырья (Thought Capture) нет дома в БД

Bible §34 Stage 1–2 требует, чтобы тезис жил в системе от заметки до экспорта. Сырьё
Александра легло в `FILMS/Pragmatico/thought_bank.md` — Tier-2, локально, не в git,
Полина туда не достанет. Значит Stage 1 у эссе-канала вне системы.
**План:** дать сырью тот же приём, что темам — свой `file_type` (например
`SPC-thought_{slug}`, series-scoped, вне `SBL-%` и вне канон-гейтов, ровно по образцу
`series-themes.ts`). Ноль миграций, если префикс уже разрешён CHECK-констрейнтом; иначе
одна миграция. Переиспользовать поверхность тем, а не строить вторую.

### C2 🔴 Портфеля как объекта не существует

Порядок слотов, тестируемая переменная, класс стоимости, баланс explore/exploit живут
только текстом внутри `content`. Запросить «покажи портфель по порядку» нечем; шоураннер
кодирует это в заголовке «Слот 1 …», то есть соглашением, а не полем.
**План:** добавить в `metadata` темы несколько полей (`portfolio_slot`,
`tested_variable`, `cost_class`, `stance: explore|exploit`) — metadata уже свободная
(`theme_status` там же живёт), миграция не нужна. Тогда портфель = сортировка списка.

### C3 🟡 Авторство темы искажается

`POST /api/series/[id]/themes` требует Director-сессию и штампует `agent_id: 'Director'`
плюс `created_by_kind: 'director'` из `requireDirector()`. Тема, предложенная Полиной,
выглядит созданной Директором → завышает его касания в scorecard. Совпадает с известным
`backlog_scorecard_polina_mislabel`.
**План:** прокидывать фактического автора (Полина / шоураннер / Директор) в провенанс.
Шоураннер в этой сессии писал напрямую в БД и проставил
`created_by: 'showrunner:PRAGMATIC (Тео)'`, `created_by_kind: 'agent'` — то есть модель
данных это УЖЕ умеет, дыра только в роуте.

### C4 🟡 Журнал канала пишется только из CLI

`hog_memory` пополняется скриптом `webapp/scripts/hog-memory-append.mts` из headless-CLI.
Вебапп в журнал не пишет — значит решения, принятые в чате с Полиной, в память канала
не попадают.
**План:** тонкая ручка поверх той же таблицы с тем же ограничением по `kind` (см. B4).

## D. Что сработало как задумано

Фиксируем, чтобы не переделывать здоровое.

- **Каскад брендинга** `series → channel → нейтрал` (`lib/agents/branding.ts`) — второй
  канал завёлся без единой строки кода.
- **`publish_defaults` per-channel** (Фаза 4e) — тоже данные, не код.
- **Поверхность тем per-series** как ассеты `SPC-theme_{slug}` — вне канон-гейтов,
  без миграций, статус курации в metadata. Второй сериал лёг в неё как родной.
- **`delivery_targets` как единый сигнал формата** — один ключ развернул Storyboarder
  в вертикально-безопасный кадр, EREF в 1024×1536, Animator в 9:16. Проверено прогоном
  резолверов на живых строках.
- **Разделение «студия ↔ канал ↔ серия»** — паспорт канала, серия, Библия серии не
  протекли друг в друга.

## E. Порядок работ для кодера (черновик, приоритет сверху)

1. **A1 + A2** — расжанрить словарь тем (описание тула + шапка слоя). Дешевле всего,
   а без этого Полина на Pragmatico будет авторить не то.
2. **B1 + B2** — тул паспорта канала поверх готового PATCH-роута. Открывает Полине
   всю кастомизацию канала.
3. **C2** — поля портфеля в `metadata` темы. Без миграции, превращает список тем в
   портфель.
4. **B4 + C4** — чтение уроков и запись решений в журнал канала. Без этого шоураннер
   в вебаппе слеп и беспамятен.
5. **C1** — дом для сырья (`SPC-thought_*`), по образцу тем.
6. **C3** — честное авторство в роуте тем.
7. **B5** — тул запаса эфира.
8. **A4 + A5** — снять жанровые дефолты в паспорт (требует решения Директора, у Sandy
   есть long-form).
9. **A3** — абстракция скилл-пары тем (уже отдельной задачей).
10. **B6 + B7** — брендинг канала и генерация ассетов. Ниже всех: делается один раз на
    канал, ручной обход дешёвый.
