## §1. ЧТО ПРОВЕРЯЕТ ЭТОТ ПРОГОН

**Премисса.** Новая парадигма — один полный ум прямыми вызовами вместо конвейера ролей —
работает и оставляет за собой ВИДИМЫЙ эпизод: студия показывает кадры, клипы, ленту,
тайминги, деньги; блок дистрибуции проходится штатно.

**Опровергатель.** Прогон провалился, если хоть одно верно:
- ведущий ум лез в исходники, чтобы узнать, чем и как вызвать инструмент (маршрут §8-тер и
  `--help` обязаны это закрывать);
- изделие произведено, а в студии его нет (след должен оставляться сам);
- плотность гэгов не пережила раскадровку;
- Директору пришлось объяснять то, что уже записано в маршруте.

**Мера.** Считать: незапланированные касания Директора · сколько раз пришлось читать код ·
минуты · доллары. Сравнивать с E37: 108 минут, $21,46, ноль касаний, но **40 минут на чтение
исходников** — именно эти сорок минут и должны исчезнуть.

## §2. ЗАДАНИЕ

1. **Тема** — из банка тем серии либо назначается Директором. Не выдумывать: тема = движок
   гэгов, судится скиллом `series-episode-theme-selection`.
2. **Эпизод** — следующий по счёту в S15 (`ensure-episode` покажет).
3. **Хронометраж** — 30–45 с, вертикаль. Из него ВЫВОДИТСЯ план плотности: 30 с → ~10 кадров
   по 3 с → ≥10 РАЗЛИЧНЫХ гэгов. Директор может переопределить через `gag_plan` в паспорте.
4. **Потолок бюджета** — решение Директора, спросить до первой траты.
5. **Лист ожиданий** — ДО первой генерации, покадрово, по шаблону
   `docs/plans/_expectations-template.md`.

## §4. ПОРЯДОК

Маршрут `ss-run` — нормативный. Кратко: якоря → бриф → тема → замысел словами → **гейт
Директора** → лист ожиданий покадрово → канон-минимум → плиты локаций пустыми → кадры (начинать
с `--quality low`) → клипы → сборка → слепая приёмка чистым контекстом → правки → публикация
(хард-лимит Директора).

**`sync-episode` вызывать ДО приёмки, а не после публикации** — он собирает раскадровку,
аниматик, бриф и сценарий из факта и сводит деньги; без него мертвы лента и весь блок
дистрибуции.
