## 2. РЕШЕНИЕ — два читателя разделяются секцией в тексте, не новой сущностью

Статья Библии обслуживает человека (зачем) и модель (что рисовать). Сегодня одно поле, и
человеческая половина отравляет машинную.

**Принято:** соглашение о секциях внутри `content`.

```
<канон-проза — документ человека, как сейчас>

## RENDER
<3-8 предложений, только рисуемое: форма, материал, палитра, кадрирование, свет.
 Без canon id, без версий, без ролей, без производственных объяснений.>
Refs: bathyscaphe_turnaround, s20_style_canon_v1

## NEGATIVE
- porthole rim
- human figure
- text or signage
```

**Почему не JSON в `metadata`:** невидим человеку — и это воспроизводит ровно тот дефект,
который мы чиним, этажом ниже. Канон говорит «блистер», невидимый блоб говорит «обод», и на
экране расхождения не видно.
**Почему не отдельная строка-ассет:** удваивает строки и церемонию LOCK, которую Полина
выполнить не может вообще (разрыв D5).

**Обратная совместимость по конструкции:** нет секции `## RENDER` → парсер возвращает null →
сборщик берёт `description.slice(0, 2400)`, то есть сегодняшнее поведение байт в байт.
Пятьдесят залоченных ассетов Sandy не мигрируются и не трогаются.

**Это ВЫЧИТАНИЕ, а не добавление:** семь строк прозаических запретов из `bible-author.ts`
переезжают в дефолтный массив негатива по секциям. Запреты перестают конкурировать с описанием
за внимание и становятся одной хвостовой фразой, которую провайдер уже умеет подклеивать.

## 3. ЦЕПОЧКА ОТВЕТСТВЕННОСТИ — Полина администратор, писатель пишет

| Звено | Кто | Где живёт поведение |
|---|---|---|
| Замысел | Директор | разговор → `seedDescription` |
| Канон-текст | **EXEC-BIBLE-AUTHOR** | `bible-author.ts` |
| Блок `## RENDER` | **EXEC-BIBLE-AUTHOR**, тем же вызовом | тот же |
| `## NEGATIVE` | писатель + дефолты секции | сборщик |
| Финальный промпт | **сборщик, детерминированный, без LLM** | `series-canon-refs.ts` |
| Диспетчеризация, статусы | **Полина** | `concierge/tools/series.ts` |
| LOCK, деньги, публикация | **Директор** | без изменений |

**Один вызов Sonnet, не два.** Render-блок — секция того же документа, поэтому её пишет та же
модель, что только что решила канон. Второй вызов «перескажи для картинки» — второй шанс
разойтись с текстом. Это тот же класс дефекта, что «критик подменял план».

**Пишущую машинку убираем, а не сторожим:** `prompt` в `regenerateBibleImage` становится
**необязательным**. Опущен → маршрут собирает промпт из `## RENDER` сам. Явный `prompt`
остаётся только для ручной правки Директора из UI.

## 4. НЕ ПРОТИВОРЕЧИТЬ УЖЕ НАПИСАННОМУ — кормить и проверять

**Кормить.** `loadSeriesContext` уже собирает стиль-якорь и общую идею — там же собирается
дайджест существующего канона: **только блоки `## RENDER`**, LOCKED впереди APPROVED, 400
символов на запись, 6000 всего. Обрезали — дайджест всё равно **называет пропущенные слаги**.
Пропустить невозможно не потому, что помним, а потому что нет пути в `buildDescriptionPrompt`
мимо этой функции.

**Проверять.** `runStyleCheck` уже есть и уже умеет блокировать. Две узкие правки: звать его и
из рождения тоже (сегодня асимметрия — исправление проверяется, создание нет), и расширить его
вход дайджестом **только когда `assetType` начинается с `SBL-`**, чтобы путь кадра не изменился
ни на байт.

**Противоречие → HALT, никогда молча.** `FAIL` на Bible-ассете: прервать ДО траты на картинку,
DRAFT оставить живым, записать `blocker_raised` с **обоими** id и **обеими** конфликтующими
фразами. Код победителя не выбирает — выбирает Директор.

## 5. АУДИТ — минимум, чтобы ответить «видела ли модель героя»

Четыре **необязательных** поля в `ImagePromptHistoryEntry` (JSONB, миграции нет, старые строки
остаются валидны):

- `provider_id` + `model` — какая ветка отработала;
- `references_used` — тип переиспользуем из `shot-reference.ts`, второй формы не заводим;
- **`references_dropped`** — самое ценное: сегодня референс с непрочитанными байтами пропадает
  молча, и «не было» неотличимо от «был и не открылся»;
- `negative` — какие запреты реально действовали.

Оба места **уже вычисляют** это и выбрасывают. Шаг в основном про то, чтобы перестать выбрасывать.

## 6. СКОУП РЕФЕРЕНСОВ — объявляется автором, по умолчанию только стиль

Сегодня каждой генерации Библии прикладываются 4 произвольных персонажа. У `openai-edits-multi`
**весов референсов нет** — значит посторонняя тварь влияет на кадр кабины ровно столько же,
сколько стиль-якорь.

**Принято:** автор объявляет референсы строкой `Refs:` в блоке `## RENDER`, слагами.
**По умолчанию — только стиль-якорь.** Для нового персонажа чужое лицо это загрязнение, а не
якорь. Для локации и объекта нужные соседи ровно те, кого автор назвал: интерьер объявляет
экстерьер аппарата — и сегодняшнего противоречия «блистер против обода» не случилось бы.

Порядок детерминированный: объявленные, стиль последним. Объявленный референс, который не
открылся, — **HALT**, а не тихая деградация: автор назвал его несущим.

Честная оговорка: это **единственный шаг, меняющий поведение существующей серии** — записи без
`Refs:` теряют четыре бесплатных персонажных референса. Но какие именно четыре, никогда не было
определено, так что контрактом это не было.

`studio_version < 1.0` легаси-эпизоды обратной совместимости не заслуживают, а фолбэк её и не
требует.

## 8. ЧЕГО НЕ ДЕЛАЕМ И ПОЧЕМУ

1. Нового провайдера или модели — механизм есть и работает.
2. Отдельной строки-ассета под render-бриф — удваивает LOCK, который Полине недоступен.
3. Зеркала `metadata.render_brief` — вторая копия, способная разойтись с первой, и невидимая человеку.
4. Нового критика согласованности канона — `runStyleCheck` закрывает ~80% и уже умеет блокировать.
5. Нового инструмента Полине — разрыв D1 реален, но это другая задача.
6. Миграций и новых колонок — соглашение в markdown плюс необязательные поля JSONB.
7. Машины состояний канона (разрыв D3) — проектируется из завершённого прогона, не из этого дефекта.
8. Удаления фолбэка `description.slice(0, 2400)` — он И ЕСТЬ гарантия совместимости.
9. Второго вызова LLM под render-блок — два вызова, два шанса разойтись.
10. Удаления модалки `bible/generate-image` — она живая, её подключаем к общему сборщику.
