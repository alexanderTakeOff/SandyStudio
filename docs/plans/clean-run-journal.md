## Разрывы инструмента — записываются номерами, НЕ чинятся в прогоне

**D35 — гейт режима читает противоположное тому, что написано.**
`mode-validator.cjs` берёт первую строку `Mode:` из PLAN.md и вытягивает из неё `===5===`
нежадным матчем. Живая строка: `Mode: Mode 1 — MANUAL. ===5=== выдан 29.07.` — текст
объявляет Mode 1, гейт при этом **разрешает записи**. Класс: тишина вместо отказа
(доктрина §17–18). Найдено 13:33, чтением хука перед использованием, не по факту аварии.

**D36 — у прибора «деньги разума» нет носителя.**
Харнесс не отдаёт счётчик токенов ни хуку, ни ассистенту. Оценка возможна только как
число ходов × средний объём контекста, вилка ~2,7×. Против цели $15 такая вилка решения
не даёт. Это ограничение **прибора**, а не прогона: без него весь §19 доктрины (разделять
работу и трение в деньгах) считается на глазок.

**D44 — обложку Short'а фабрика поставить не может в принципе.**
Метод установки обложки в Data API **возвращает ошибку для Short'ов**; в интерфейсе студии
загрузка произвольной обложки открыта только участникам партнёрской программы и только с
24–25 июля 2026. Значит наш генератор тумбнейлов (`viral-thumbnail-design`) для вертикали
производит артефакт, **который некуда прикрепить**. Пока это так, обложкой служит кадр из
самого ролика → требование переезжает в раскадровку (алгоритм Ш22), а не в дистрибуцию.

**D43 — музыка в фабрике не генерируется вообще.**
`EXEC-MGEN` («Композитор») есть в реестре агентов, ему назначен тип задачи `music` и
артефакт `AUD-music`, но **исполнителя нет**: в `factory.ts` рядом с ним стоит `mock for
now`, ни одного провайдера музыки в `lib/agents/providers/` не заведено, раннера
`runners/*music*` не существует. Музыка во всех прошлых эпизодах приходила **загрузкой
руками**. Для «фабрики, которая ведёт бриф→публикацию без няньки» это дыра в цепочке:
звук — не отделка, а часть замысла, и на этом эпизоде он несёт пуант (грохот заслонки).

**D42 — пятый персонаж в кадре не опознаётся, сколько бы референсов ни дали.**
Директор усомнился в семи референсах, сказав, что помнит потолок «не больше четырёх», и
указал на доказательство: Наковальня похож на себя, но нарисован ПО ОПИСАНИЮ, а не по
канону. Проверены обе гипотезы порознь:

| Прогон | Порядок референсов | Результат по Наковальне |
|---|---|---|
| v01 | style → location → 5×identity | не канон: высокий, узкий, без синей верхней грани |
| v02 | location → 5×identity → style | **не канон, то же самое** |
| v03 | location → 4×identity → style | четверо названных — канон; модель **дорисовала пятого сама** |

**Вывод: дело в ЧИСЛЕ, а не в порядке.** Четыре опознаваемых персонажа в кадре — потолок;
пятый приходит выдуманным. В коде такого предела нет вовсе (провайдер держит 16, комментарий
конвейера называет 6–7 «спокойно под потолком») — предел **поведенческий**, и Директор помнил
его правильно, а код молчал.

**Попутно найдено настоящее нарушение контракта.** TD-53 в `episode-references.ts`
предписывает порядок **локация → личности → стиль**: провайдер считает ранние референсы
приоритетными, и локация обязана идти первой как канонический макет. Прямые вызовы прогона
слали стилем вперёд. Порядок теперь навязывается самим инструментом, а не написанием вызова.

**D41 — леджер НЕ УМЕЕТ записать трату, сделанную мимо конвейера агентов.**
`budget_log.job_id` связан внешним ключом с таблицей `jobs`. У прямого вызова строки job
нет, поэтому вставка отвергается — а мой скрипт не проверял ошибку, и **леджер молча
оставался пустым, пока деньги тратились**. Обход: `job_id = NULL` проходит. Ошибка вставки
теперь проверяется и валит скрипт с кодом 2.

**Почему это важнее обхода.** Единственный прибор денег **конструктивно привязан к тому
самому слою агентов, который путь C предлагает перестать вызывать.** Прямой вызов — это
не экзотика, это и есть предлагаемая архитектура; значит учёт спроектирован против неё.
В пульт это переносится как отдельный факт: **леджер должен принимать трату от кого угодно,
а не только от задачи конвейера.**

**D40 — мой генератор кадров выбросил две оплаченные картинки. ПОЧИНЕН (прибор).**
`scripts/run/gen-frame.ts` проверял `res.status !== 'success' || !res.image_b64` — таких
полей у `MultiImageGenResult` нет вовсе (там `b64_data` / `cost_usd`, а отказ приходит
исключением). Провайдер отработал успешно оба раза, скрипт объявил отказ и не записал ни
файла, ни строки в леджер. **Потеряно ~$0,50 при нулевом артефакте.** Урок вписан в
алгоритм Ш5-бис: новый тратящий деньги инструмент обкатывается на `--quality low`.

**D39 — вертикаль 9:16 недостижима, хотя провайдер её умеет.**
`clampSize()` в `openai-edits-multi.ts` схлопывает всё, кроме трёх размеров gpt-image-1, а
gpt-image-2 принимает свободные размеры (до 3840 по большей стороне, кратно 16). Реальные
1080×1920 сейчас недоступны, кадры делаются 1024×1536 (2:3) и переформатируются ниже по
течению. Комментарий в коде до сих пор утверждает, что 9:16 «невалиден для провайдера» —
это устарело. Не чиню: это система, а не прибор.

**D38 — счётчик записей не видел новых файлов. ПОЧИНЕН (прибор, не система).**
`git diff --numstat HEAD` не показывает неотслеживаемые файлы, поэтому три только что
написанных файла прогона читались как `+0` и получали `⚠`. Прибор, врущий ровно про то,
ради чего заведён. Починен в тот же ход: не отслеживаемый git файл считается целиком.
Правило «разрывы не чинятся по ходу» относится к **измеряемой системе**, не к
**измерительным приборам** — см. `clean-run-algorithm.md` Ш3-тер.

**D37 — банк тем не знает, что уже снято.**
Из 30 тем банка `used_in_episodes` проставлен у двух, при том что снято минимум семь тем
из списка (качалка, лента, автомат, тяжёлый друг, малыш-таймер, одолжи, лифт). Отбор темы
пришлось делать сверкой руками по названиям эпизодов. Класс: у повторяющейся вещи нет
единственного источника (доктрина §14).
