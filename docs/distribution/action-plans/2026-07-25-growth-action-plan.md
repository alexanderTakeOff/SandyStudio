## Track D — Аналитическая память и свёртки · РЕШЕНО 26 июл, СТРОИТ КОДЕР
*Зачем: механизм должен не «уведомлять, что отчёт пришёл», а анализировать, накапливать
аналитику и корректировать поведение — своё и канала.*

### D1 · Хранилище — БАЗА, не Drive (решение Директора q13a)
Причины: закон проекта «markdown в базе, бинарники на Drive» (`provider_strategy.md:284`);
в коде НЕТ API шаринга Drive (`webViewLink` требует авторизации → с телефона не открыть);
Drive — самый ненадёжный слой (28 медиа с `drive_file_id=NULL`). Рендеры остаются в git,
ссылка — секретный gist + githack. Drive допустим только как витрина, не источник правды.

### D2 · Иерархия свёрток
День → **неделя** → **месяц**. Железное правило: каждый следующий период читает **ТОЛЬКО
предыдущую свёртку**, а не всю историю — иначе контекст растёт бесконечно.

### D3 · Что копить — аналитику, НЕ статистику
Статистика уже льётся в `channel_snapshots`. Копить «журнал гипотез»: гипотеза + статус
(PENDING / ПОДТВЕРЖДЕНА / ОПРОВЕРГНУТА + дата разблокировки) · опровергнутое (чтобы не
предлагать по третьему кругу) · эксперименты (что менялось, одна ли переменная) · медианы
канала (пересчёт раз в неделю) · решения и их последствия.

### D4 · ПЕРЕИСПОЛЬЗОВАТЬ, не строить заново (разведка по коду 26 июл)

  (карточки-гипотезы, разведка/эксплуатация, детектор просадки удержания).
  **Его выход СЕЙЧАС ВЫБРАСЫВАЕТСЯ** — используется только дашбордом. Сохранять его, а не писать новый.
- **Skill Editor** (`.claude/skills/*` + `lib/concierge/tools/skills.ts` + `lib/skills/select-skills.ts`)
