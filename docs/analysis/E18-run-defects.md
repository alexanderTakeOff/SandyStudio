## DEFECTS

### D1 — Writer (EXEC-SW) пытается запуститься ДО Casting · HIGH

- **Время:** ~17:41 (Полина, старт E18).
- **Симптом:** `EXEC-SW` (Writer) диспатчится/пытается бежать раньше, чем существует
  `SPC-episode_cast`.
- **Что происходит по коду:** гейт `EXEC-SW` требует ≥1 approved `SPC-episode_cast`
  ([gate.ts:60-72](../../webapp/lib/agents/gate.ts)) → попытка корректно отбивается
  («found 0 cast»). Но сам **факт попытки** — дефект ордеринга: Brief APPROVED не
  должен вести к Writer, пока не пройден Casting. Casting в дизайне — TOOL-ONLY шаг
  без Inngest-исполнителя ([next-events.ts:332-355](../../webapp/lib/agents/next-events.ts)),
  поэтому он не стоит явным узлом между Brief и Writer.
- **Severity:** HIGH (обход есть — гейт держит; но ложная попытка = шум + путаница).

### D2 — Mode 1: каст НЕ попадает Директору на аппрув · CRITICAL (тупик)

- **Время:** 17:41. Полина подтвердила: *«Mode 1 — MANUAL. Director approves every
  creative gate (Brief, Script, Storyboard, Canon check, References …)»* — **Casting
  в этом списке ОТСУТСТВУЕТ**.
- **Симптом:** каст рождается в статусе REVIEW (fix A+C `63890fc`), но **не выводится
  в очередь одобрения** Директора в Mode 1. Директор не видит гейт → не может одобрить.
- **Следствие:** Writer-гейт требует approved cast → без видимого аппрув-сюрфейса каст
  остаётся REVIEW → **пайплайн встаёт после Brief** (deadlock). Это открытый пункт B
  из `backlog_td_casting_draft_deadend` (readiness-preflight / casting как first-class
  гейт).
- **Severity:** CRITICAL (тупик пайплайна — эпизод не двигается дальше брифа без
  ручного вмешательства).

### D3 — Reference Artist стартует на PASS критика, а не на аппруве борда · HIGH

- **Время:** наблюдение Директора по ходу прогона.
- **Симптом:** референс-артист (EREF Designer) запускается **после утверждения
  вердикта критиков сториборда**, а надо — **после того как сам сториборд утверждён**
  Директором.
- **Что по коду:** триггер цепочки — `REV-world_check` (вердикт Continuity Critic),
  а не `STB` APPROVED ([next-events.ts:530](../../webapp/lib/agents/next-events.ts)).
  Борд лишь подтягивается через `findLatestApprovedAssetId('STB-storyboard')`
  ([:544](../../webapp/lib/agents/next-events.ts)).
- **Историческая причина (не случайность):** EREF и MGEN намеренно оба идут после
  `world_check` параллельно, чтобы аниматик превьюил тайминг с музыкой (Director
  directive 2026-05-08 q3b, [:524-529](../../webapp/lib/agents/next-events.ts)).
- **Интент Директора:** платная генерация референсов должна гейтиться на ЕГО аппруве
  борда, а не на прохождении критика. Критик — вход для решения, не триггер трат.
- **Фикс (НЕ применяю):** триггер EREF-Designer перевести с `REV-world_check` на
  `STB` APPROVED; развязать от MGEN-тайминга (проверить, что превью музыки не ломается).
- **Severity:** HIGH (преждевременная платная работа / неверный гейт; не тупик —
  gate EXEC-EREF всё равно требует approved STB, но триггер стоит не там).

### Общий корень D1+D2 (systemic, НЕ два независимых)

**Casting — несущий гейт** (и Writer, и Storyboard требуют approved
`SPC-episode_cast`), но реализован как **невидимый tool-only side-step**, а не
first-class узел пайплайна с местом в очереди одобрения. Оба симптома падают из
этого одного факта:
- невидим как узел → Writer стреляет «мимо» него (D1);
- невидим в очереди → Директор не может его одобрить в Mode 1 (D2).

Фикс (НЕ применяю сегодня — только фиксирую): вынести Casting в first-class
approval-node между Brief и Writer, чтобы (а) он стоял явным шагом до Writer и
(б) появлялся в Director approval queue во всех ручных режимах.

### D12 — ⭐ ГЛАВНЫЙ: retry-лимиты НЕ контролируют диспатч — переавторинг плана ПОСЛЕ APPROVED · CRITICAL

- **Наблюдение Директора:** «лимиты и их реальный контроль — лимиты превышены».
- **Верифицировано по БД, таймлайн SH11 (`SPC/REV-shot_plan`):**
  ```
  14:43:45  SPC v03 → APPROVED         ← план утверждён
  14:44:09  REV v03 → PASS
  14:44:57  SPC v04 создан (REVIEW)    ← новый план ПОСЛЕ утверждения
  14:45:37  REV v04 → HALT
  14:47:26  SPC v05 создан (REVIEW)    ← ещё один
  14:48:12  REV v05 → HALT
  ```
- **Root cause:** петля «критик REVISE → переавторинг плана» НЕ имеет terminal-state/идемпотентного
  гейта. После `v03 APPROVED` стейл/дубль REVISE-события продолжили дёргать автора → v04, v05.
- **Почему cap «не контролирует»:** `applyCriticVerdict` ([critic-loop.ts:125](../../webapp/lib/agents/critic-loop.ts))
  — ПОСТ-ФАКТУМ коэрсинг (`REVISE→HALT` при `version-1 ≥ cap`), а НЕ гейт на диспатч. Он стемпит HALT
  ПОСЛЕ того как лишний план сгенерён и критик отработал — деньги уже потрачены. И лепит ложные HALT
  на уже-APPROVED эпизод (шум + фальш-эскалация).
- **Цена:** каждый спурьёзный v04/v05 = 1 LLM-генерация плана + 1 прогон критика = деньги на ветер,
  на каждом таком шоте. SH01/SH02 та же болезнь мягче (лишний PASS-прогон после первого PASS).
- **Семейство:** D8/D11 — fire-and-forget, нет идемпотентности/реконсиляции (`inngest_dev_router_unreliable`,
  fanout machine-gun). Лекарство: terminal-state guard («план шота APPROVED → не переавторить») +
  идемпотентный диспатч (state-matrix сверяет терминал перед ре-фаером).
- **Severity:** CRITICAL (неконтролируемый расход денег; лимиты Директора не имеют реальной силы).

## PROPOSED REDESIGN — Mode 3 critic-driven auto-advance (обсуждается, НЕ применяю)

Директор 2026-07-08: в Mode 3 не гонять Полину зря —
- **critic PASS** → сразу флип REVIEW→APPROVED + запуск следующего (код, не Полина);
  касается и референсов, и видео;
- **critic FAIL/REVISE** → подключается Полина (наблюдает, ведёт revise-loop);
- **≥ cap исправлений** (`critic_revision_cap`) не починил план → в Mode 3 эскалация на
  **Полину** (вместо Директора);
- **убрать «пилотные кадры» как класс**; вместо этого универсальный авто-стоп: фабрика
  сама встаёт после первых **2 референсов** (sequential) или **2 реф + 2 видео**
  (parallel), и ждёт, пока Директор глазами оценит и толкнёт дальше.

Замечание Тео: 80% этой логики УЖЕ есть в `reconcile.ts` (PASS→approve; FAIL/cap→halt).
Правки при фиксе: (1) привязать к governance Mode 3, не к env-флагу; (2) заменить
reserved-pilots на position-стоп «после 2»; (3) закрыть слепую ветку авто-аппрува
картинок без критика (reconcile.ts:165). Систематизировать в spec ПОСЛЕ подтверждения.
