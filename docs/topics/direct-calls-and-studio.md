# Тема: Прямые вызовы и студия

> Изделие становится ЭПИЗОДОМ не когда файл лёг на диск, а когда строка `assets` носит тот
> префикс, который студия сопоставляет со стадией. Витрина не знает, кто выложил товар —
> конвейер ролей или один ум; она читает ярлык.

*Потолок 80 строк — он же механизм удаления. Устаревшее выкидывать, не копить.
Разбор дня: `docs/plans/cold-run-algorithm.md` шаги 15–19.*

## РЕШЕНО

- **Новый интерфейс для новой парадигмы НЕ нужен** (05.08). `buildPipelineSnapshot(статус,
  ассеты, задания)` красит стадию зелёной по наличию APPROVED-ассета нужного типа; задания
  нужны лишь для «крутится/упало». Ни Inngest, ни агенты для ОТОБРАЖЕНИЯ не требуются.
  Переписывать надо ярлыки в инструментах и список ролей `ROW_DEFINITIONS`
  (`pipeline-stages.ts:198`), а не витрину. Новый GUI = месяцы; конвенция + правка списка = день.
- **Стадия выводится из ПРЕФИКСА `file_type`** — `STAGE_FROM_ASSET` (`pipeline-stages.ts:230`).
  Не совпал префикс — ассета для конвейера не существует. Рабочие пары: `SPC-brief` ·
  `SPC-episode_cast` · `SCR` · `STB` · `IMG-episode_ref` · `AUD-music` · `VID-animatic` ·
  `VID-shot` · `VID-final_cut` · `SPC-metadata` · `SPC-thumb_plan` · `IMG-thumbnail` · `REV-publish`.
- **Лента требует ДОКУМЕНТА, а не картинок.** Строится из `VID-animatic` APPROVED либо из
  `STB` APPROVED с JSON-блоком ```acts[].shots[]``` в `content`. Ячейка связывается с изделием
  через `metadata.shot_reference.shot_id` (кадр) и `metadata.shot_id` (клип).
- **Тайминги живут ТОЛЬКО в `VID-animatic`.** `PATCH /api/assets/[id]/animatic-timing`
  принимает исключительно этот тип с контрактом `animatic_v1`; скелет из раскадровки в коде
  помечен READ-ONLY. Нет аниматика → правки Директора некуда сохранять, теряются молча.
- **Адрес берётся ИЗ ЗАПИСИ, а не строится из имени.** `filename` — каноническое имя ассета,
  а не имя файла на диске: загрузка музыки (`ingest-music.ts:119`) кладёт байты с хеш-суффиксом
  и держит адрес в `drive_path`. URL, собранный из `filename`, указывает в пустоту.
- **Идемпотентность допустима для машинного, ручное — только дополняется.** «Строка есть —
  обновлю» стёрло 10 правок таймингов и загруженный трек. Перед записью: чей объект я
  перезаписываю целиком?
- **Два леджера денег, оба настоящие.** `budget_log` — итемизированный (пишут инструменты),
  `episodes.budget_spent` — резервационный (читает шапка эпизода и атомарный RPC). Прямой
  вызов заполнял только первый → «$0.00» над эпизодом за $25.
- **`register-canon` не проставлял `drive_path`** → канон-плиты показывали «no preview» при
  живом файле в кэше. Резолвер (`asset-preview-resolver.ts`) строит ссылку по признаку Drive,
  хотя роут `/api/media/[id]` прекрасно отдаёт из тёплого локального кэша.

## ОПРОВЕРГНУТО

- **«Материалы E35 были и пропали»** (05.08, зонд по базе). Ноль строк по `episode_id`, ноль по
  имени файла, ни одной сироты. Их не было НИКОГДА: из семи инструментов прямого вызова строку
  `assets` заводил ровно один — `register-canon`. Директор видел плиты локаций, и видел верно.
- **«Стадии стартуют и тихо умирают»**. `activity_events` пишет по каждому нажатию пару
  `manual_trigger` → `agent_failed` с точной причиной за 1–2 с. События есть — до Директора не
  доходят. Дефект ДОСТАВКИ, не исполнения.
- **«Медиа не отдаётся»** — проверка curl'ом бессмысленна: `middleware.ts` пропускает мимо
  авторизации только картинки (`png|jpg|jpeg|gif|webp|svg`), видео уходит на `/login` с 307.
  Проверка, которая одинаково валит заведомо рабочее и новое, проверяет не то.

## ОТКРЫТО

- **Гейт проверяет МЕНЬШЕ исполнителя.** `EXEC-COPY`: гейт спрашивает только `SCR`
  (`gate.ts:229`), раннер требует ещё `SPC-brief` с непустым `content`
  (`runners/copywriter.ts:205`) и падает после старта. Половинчатый гейт хуже отсутствующего —
  создаёт ложную уверенность. Искать сплошным сравнением `gate.required` против
  `findApprovedAsset` во всех раннерах.
- **Доставка событий Директору** (решение 05.08: «13 not today»). Причины пишутся полностью и
  мгновенно, узнаёт он о них, только открыв ассеты руками.
- **Журнал правок не хранит ЗНАЧЕНИЯ.** Событие пишет «9 длительностей, итог 31,25» — по этому
  нельзя восстановить ни одного кадра. Спасло то, что кат уцелел и тайминги сняты с него
  детектором сцен. Журнал, по которому нельзя восстановить состояние, — уведомление.
- **`prod.log` не пишется с 31.07** — сервер жив, файл мёртв. Правило «читай логи перед
  выводами» держится на существовании логов; живой журнал фабрики — таблица `activity_events`.
- **Прямой прогон не производит документов**, которых ждёт студия: брифа, сценария,
  раскадровки, аниматика. Сегодня они собраны ИЗ ФАКТА (`sync-episode`) — раскадровка из
  длительностей готовых клипов, бриф и сценарий из листа замысла. Это работает задним числом;
  для новой парадигмы вопрос открыт — производить их по ходу или оставить синтез.
