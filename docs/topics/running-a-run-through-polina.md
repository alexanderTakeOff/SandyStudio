## РЕШЕНО — плумбинг

- **Канал — БАЗА, не HTTP** (Ф2 миграции): строка в `concierge_turns` с
  `metadata.for_bridge=true`, мост подхватывает и ведёт ход. Из консоли —
  `npx tsx scripts/mind-say.ts --episode <uuid> "текст"` (ждёт ответ), с телефона — пульт
  `@sandystudio_bot`. Старый `team-chat-post` и ролевой токен EXEC-DIR-AI — прошлый слой.
- **Модель ума — из Studio Settings** (`app_config`, `providers/concierge_provider`), мост читает
  её перед КАЖДЫМ ходом; `MIND_BRIDGE_MODEL` — только фолбэк (`CLAUDE.md §11 п.9`, сторож
  `__tests__/lib/mind-model-source.test.ts`). Правка модели в `.env` запрещена.
- **У ума ДВЕ руки:** `Bash` и `PowerShell` (13.08). Одна кавычка ломала Bash на всю сессию, и
  без второй руки он терял исполнение целиком. Хард-лимиты держат обе (`polina-pretool.cjs`).
- **«Новый ли билд» — вопрос к серверу, не к уму:** `curl :3001/api/health` отдаёт
  `build=<git sha>`, метку ставит `start-stack.ps1 -Build` в момент сборки.
- **Идёт ход или встал — смотреть ЗАМОК** `concierge_threads.mind_session.busy`, а не
  `bridge.log`. Мост слепнет тихо: 12.08 он 39 минут не видел новых строк при живом процессе.
- **MCP Supabase `execute_sql` запрещён** («You do not have permission»). База — только
  node/tsx-скриптом с ручным чтением `.env.local`.
- **Одноразовая диагностика — `scripts/diag-*.ts`**: уже в `.gitignore`. Не плодить `probe-*`,
  их там 14 и все мёртвые.
- **Стек — адрес НИКОГДА не вбивать руками.** `:3000/:8288` — порты МАСТЕРА; рабочее дерево
  живёт на `:3001/:8388`. Брать из `webapp/.env.local` (`NEXT_PUBLIC_APP_URL`, `INNGEST_BASE_URL`):
  стук в `:3000` даёт `000` и читается как «стек лежит» — ложный вывод, стоил хода 12.08.
  `inngest.log` содержит NUL-байты — читать через `tr -d '\000'`, иначе grep молчит.

## РЕШЕНО — чем управлять, а не что писать

- **Канон-ассет заводится маршрутами приложения, кода писать не нужно** (30.07). Цепочка для
  УЖЕ готового кадра: `POST /api/series/{id}/bible` (DRAFT + текст) →
  `POST /api/assets/{id}/upload` (multipart, поле `file`) →
  `npx tsx scripts/backfill-uploaded-canon.ts <assetId>` → `POST .../bible/{id}/lock`.
- 🔧 **Правка канона — ШТАТНАЯ** (`802dcc10`): `enrichBible(assetId, notes)` — с `notes` писатель
  не сочиняет заново, а правит, текущая статья уходит ему неприкосновенной БАЗОЙ. Запись может
  объявить **саму себя** на строке `Refs:` — тогда прежний кадр служит базой и компоновка
  переживает правку. Четыре правки подряд, каждая с первого сообщения.
- 🚫 **«Возьми свой текст и замени в нём» по-прежнему НЕЛЬЗЯ** — вставала трижды за вечер (второй
  `getAsset` с той же подписью → сторожок, предел 6 раундов). Правка идёт `notes`, не просьбой.
- **Готовый файл с диска** становится референсом, только став ассетом: `bible` → `upload` →
  `backfill-uploaded-canon.ts`, дальше слаг объявляется в `Refs:`. Черновик тоже годится.
- **ЛОВУШКА: `upload` ставит `drive_file_id = null`.** Байты остаются локальными, и агентский
  media-preflight позже падает HALT'ом «Media unreachable» — так убился E16. Лечится не правкой,
  а третьим шагом цепочки: `backfill-uploaded-canon.ts` перекладывает файл через `persistBinary`
  в канонический кэш и Drive. Пропуск виден только на запуске агента, то есть поздно.
- `upload` / `regenerate-image` / `copyAssetImage` **отказываются работать по LOCKED** — поэтому
  LOCK всегда последним. `upload` сам бампает `image_prompt.current_version`, иначе браузер
  держит stale immutable-кэш.
- **Скрипт мимо приложения не оставляет следа** ни в `budget_log`, ни в матрице состояний, ни
  в Drive-раскладке. Директор поймал это на $1.58 первого мудборда — их до сих пор нет в леджере.
- **`images/generations` физически не тянет референс.** Каждый следующий ассет рисуется с
  чистого листа и расходится с предыдущим — это и есть давняя причина дрейфа канона Sandy.

  контекстом.** Факты: `origin` клона Полины — **моё рабочее дерево** `C:\SandyStudio-nx`, не

  поэтому обмен односторонний: она `pull` из меня, я — `git fetch C:\SandyStudio-polina` +
  merge. За сутки разошлось: её 13 против моих 26, ff стал невозможен, потребовался rebase.
  Итог 13.08: rebase → merge ко мне → ff у неё, оба на `50371130`. Варианты: (а) общий
  bare-remote как origin обоим; (б) её клон как `git worktree` того же репо; (в) инбокс не в
  git, а в базе — тогда расходиться нечему. Цена бездействия: она уходит в эпизод старым кодом.
- **Стоячего одобрения на этапе завода СЕРИАЛА нет:** `updateWorkPlan` привязан к эпизоду, а
