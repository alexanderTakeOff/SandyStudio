# `/ss-run` — маршрут прогона

Это путь, а не список ошибок. Ошибки живут в `docs/plans/showrunner-tooling-gaps.md`.
Позиция текущего прогона — `docs/plans/series-bootstrap-run-notes.md` §0.

**Актор:** Тео, от имени Директора. **Управление — через Полину**, где она может:
скрипт мимо приложения не оставляет следа ни в леджере, ни в матрице состояний.
Прямые события и правки в БД — только там, где приложение закрыто для headless.

## 2. Что обязано быть ДО первого шага

Пропуск любого пункта останавливает конвейер позже и дороже.

1. **Жанр серии заведён и у него есть движки.** `series.genre` должен совпадать со
   скиллами `readability-<genre>` (иначе `EXEC-CREAD` HALT'ит каждую раскадровку),
   `storyboarder-<genre>` и `eref-prompt-<genre>`. Проверка — загрузчиком, не глазами:
   `getAgentSkillManifest({agentId:'EXEC-CREAD', genre})` должен вернуть `mandatory`.
2. **`delivery_targets` эпизода выставлены.** Они управляют размером референсов и
   включают вертикально-безопасную композицию у сценариста и раскадровщика. Выставлять
   ДО запуска сценариста — иначе он пишет вслепую и всё придётся переписывать.
3. **Потолок бюджета эпизода = решение Директора**, не дефолт.
4. **Канон-минимум покрывает ПРОЧТЕНИЯ, а не объекты.** Если эпизод показывает A,
   которое оказывается B, нужны две несхожие плиты: «как выглядит A» и «как выглядит B».
5. **Локация есть.** Нет конкретного места — заводится `empty_background` (плоская
   заливка, генерится не моделью, а ffmpeg'ом: чистый фон модели не отдают).

## 3. Как узнать состояние за секунды

Не спрашивать Полину и не ждать. Идти в источник.

- **Стадии и ассеты** — один запрос к `assets` по `episode_id` с сортировкой по
  `created_at`: имя, статус, версия. Это вся картина конвейера.
- **Матрица по шотам** — `getEpisodeStateMatrix(sb, episodeId)` из
  `lib/agents/state-matrix.ts`: `ref_plan / ref_image / shot_plan / video` на каждый шот.
- **Что реально запускалось** — таблица `jobs` (`agent_id, status, error_message,
  started_at, completed_at`). Лента событий теряет часть падений, `jobs` — нет.
- **Что происходит прямо сейчас** — Inngest GraphQL, без авторизации:
  ```bash
  curl -s -X POST localhost:8288/v0/gql -H "Content-Type: application/json" \
    -d '{"query":"{ stream(query:{limit:20}) { trigger createdAt runs { status function { name } } } }"}'
  ```

### 4-бис. Прямые вызовы — путь C

Когда эпизод ведётся **мимо слоя агентов** (два последних прогона шли так), станции
запускаются скриптами `webapp/scripts/run/*`. Хранилище, провайдеры, медиа-кэш и леджер
переиспользуются — не вызывается только слой ролей. Запускать из `webapp/`.

| Что нужно | Инструмент | Когда брать |
|---|---|---|
| завести эпизод в базе | `run/ensure-episode.ts` | до любой генерации; выдаёт `episodeId` для всего остального |
| сгенерировать кадр | `run/gen-frame.ts` | один кадр за вызов; **промпт читается из файла** — длинный промпт не переживёт шелл |
| закрепить кадр как канон | `run/register-canon.ts` | когда принятый кадр должен стать единственным источником: копирует в медиа-кэш и заводит строку `assets`, дальше кадры цепляют его по slug |
| оживить кадр | `run/gen-video.ts` | добивает реф до истинного 9:16 своим цветом стены, потом img2vid Seedance |
| собрать эпизод | `run/stitch.ts` | склейка клипов по порядку, один энкод, чёрный хвост |
| опубликовать | `run/publish.ts` | заливка на канал серии, упаковка из паспорта канала, запись id на строку эпизода |
| достать медиа ассета глазами | `run/_peek.ts <slug>` | быстрый взгляд на то, что реально лежит в базе, а не на статус |

**Что инструментами НЕ является, хотя лежит рядом:** `_ledger.ts`, `_sum.ts`, `_music.ts`,
`_music2.ts` — одноразовые огрызки прошлого прогона с **захардкоженным `episode_id` E35**.
Читать как образец запроса можно, запускать на новом эпизоде — нельзя. Итог по деньгам
берётся запросом к `budget_log` по своему эпизоду.

**Чего в прямом пути нет вовсе:** музыки (EXEC-MGEN — заглушка) и обложки для Shorts
(API её поставить не может). Оба места закрываются руками.

**Обязательное окружение.** Все инструменты берут эпизод из `RUN_EPISODE_ID` и **без него
отказываются работать** — умолчания нет намеренно: захардкоженный id молча писал траты
нового эпизода в строку старого (2026-08-04). Ставится один раз на сессию из вывода
`ensure-episode`.

**Порядок работ, проверенный на E36 (41 с, 10 кадров, $18,4):**

1. `ensure-episode` → id. Экспортировать.
2. **Плиты локаций — ПУСТЫМИ, отдельной генерацией.** Плита, снятая из кадра с героем,
   тащит героя в каждый следующий кадр как часть фона. Лишние $0,018 дешевле этого.
   **Приёмка плиты в два шага** (решение Директора 26, 06.08): `APPROVED` — сразу после
   проверки глазами, `LOCKED` — только после первого кадра, где в этой плите постоял герой.
   Половину дефектов видно на пустой плите и дёшево (коралловое пятно без обходной дорожки в
   E37 стоило $0,018 вместо девяти кадров и девяти клипов); вторую половину — масштаб, линию
   горизонта, куда встают ноги — видно ТОЛЬКО в композиции с героем. Два шага разводят
   дешёвую проверку и дорогую, не теряя ни одной.
3. Кадры: `gen-frame` по одному, промпт в файле. Референсы указывать как
   `slug:kind`; порядок в командной строке не важен — инструмент сам сортирует
   **location → identity → style**, и это лечит уход персонажей от канона.
4. Смотреть кадры **контактным листом**, а не по одному:
   `ffmpeg -framerate 1 -i %02d.png -vf "scale=340:510,tile=4x2" -frames:v 1 sheet.png`.
   Расхождения между соседними кадрами видно только рядом.
5. Видео: `gen-video`, `--tier standard --duration 5`. Пад до 9:16 делается сам.
   ~$1,51 и 2–4 минуты на клип. **Пускать по три параллельно** — провайдер выдерживает,
   и час превращается в двадцать минут.
6. Монтаж: `stitch` умеет ТОЛЬКО склейку и чёрный хвост. Обрезка клипов и музыка — ffmpeg
   руками. Клип 5 с, обрезанный до 4 с, даёт нужный темп и убирает вялый хвост.
7. Музыка штатная: `FILMS/_media_cache/Flacon_Pop_Loop-processed.mp3` (130 с). Обрезать
   под длину ката, `volume=0.75`, `afade=t=out` последние 2 с.

## 5. Гейты, которые нельзя обойти

- **Аппрув ассета** (`POST /api/assets/{id}/approve`) требует человеческой сессии —
  headless получает 307 на `/login` (**D13**). Обход: зеркалить маршрут в БД —
  статус, переименование `-DRAFT`→`-APPROVED`, строка в `approvals`, событие в ленте.
- **Инвариант «один утверждённый на слот»**: перед аппрувом нового плана предыдущий
  APPROVED демоутируется в `INVALIDATED` (не `REJECTED` — он не бракован, он проиграл).
- **Хард-лимиты Директора в любом режиме:** публикация · LOCK · бюджет · смена режима.

## 7. Когда встало

Порядок сужения, от дешёвого к дорогому:

1. `jobs` — есть ли строка, в каком статусе, что в `error_message`.
2. Inngest `stream` — запускалась ли функция вообще.
3. Вердикт критика — не `HALT` ли, и по какой причине.
4. И только потом читать код.

**Частые причины, каждая уже стоила круга:**

- **Жанрового движка нет** → `EXEC-CREAD` HALT без вызова модели. Это корректное
  поведение, а не поломка.
- **Скилл не подхватывается** → проверить `applies_when.agent` на точное совпадение
  строки и `status: ACTIVE`. Комментарий внутри фронтматтера роняет весь файл (**D22**).
- **Инструкция роли правится, а поведение не меняется** → кэш `systemPromptCache`
  живёт весь процесс у большинства runner'ов; правка `.md` требует рестарта.
  Скиллы этой болезнью не болеют — у них TTL 30 секунд. **Поэтому всё, что крутится
  итерациями, должно жить в скилле, а не в файле роли.**
- **Провайдер молчит** → голый `fetch` без таймаута; смотреть, не висит ли `jobs` в
  `RUNNING` дольше ожидаемого.

## 9. Обязанность прогона

Прогон существует ради двух артефактов: этого маршрута и скилла Полины
`ss-series-starter`. Значит:

- **найденный разрыв пишется в `showrunner-tooling-gaps.md` номером D<N>**, и Директору
  докладывается уже номером — доклад без номера означает, что запись не сделана;
- **§0 заметок переписывается в конце каждого шага**, а не в конце сессии: блок,
  обновляемый в конце сессии, не переживает обрыв, а обрыв — это и есть тот случай,
  ради которого он существует;
- **то, что оказалось верным маршрутом, дописывается СЮДА** — иначе следующий прогон
  снова роет код.

### 4-тер. Три правила приёмки, оплаченные браком E36

1. **Переснял кадр — перепиши его строки.** Новый промпт со старым листом приёмки не
   проверяет ничего: строка «уходит из кадра» на кадре «стоит и подмигивает» молчит, и брак
   проходит. Сторожок прогона блокирует стоп, если промпт новее листа ожиданий.
2. **Канон ПЕРСОНАЖА живёт отдельным чеклистом и наследуется каждым кадром** — ноги, руки,
   крышка, запечатанность, закрытый рот, отсутствие подставки. Это строки героя, не эпизода;
   без них их не проверяет никто и никогда (в E36 герой уехал в финал без ног).
3. **Проверяй КАДР, а не изменение.** Генератор перерисовывает каждый пиксель — «неизменного»
   у него нет. Проверка только той детали, которую просили поменять, — самая частая слепота.

**Что провайдер устойчиво НЕ умеет** (проверено тремя попытками, E36): показать превращение
песка внутри запечатанной колбы. Любая формулировка выводит иглы наружу или растит корону
вокруг головы. Показывай СОСТОЯНИЕ, переход оставляй за кадром; если строка требует
перехода — уступает строка, а не канон.

```bash
  --out ../FILMS/_run/e37/clips/sh01.mp4 --duration 5 --tier standard
```

**Имя файла промпта обязано соответствовать конвенции CLAUDE.md §3.** Хук
`naming-validator.cjs` валидирует всё, что лежит в папке с именем `prompts`, — и режет
`loc-paint-corridor.txt` до генерации. Годится `SS-S15-E37-PRO-<snake_case>-v01-DRAFT.txt`.
Это не помеха, а бесплатная версионность: `-v02-` рядом с `-v01-` сам ведёт историю пересъёмок.

**Качество `low` держит канон.** Тринадцать кадров E37 сняты на `--quality low` ($0,018
против $0,25 у `high`) — персонаж, стиль и плита воспроизводятся; на весь эпизод картинки
стоили **$0,23 из потолка $25**. Начинай с `low` и поднимай по факту, а не заранее.

**Порядок референсов писать не нужно** — инструмент сам сортирует
`location → identity → style` (`gen-frame.ts:83`). В командной строке пиши как удобно; в
ТЕКСТЕ промпта нумеруй роли в том же порядке (Image 1 — локация, 2 — персонаж, 3 — стиль),
иначе подписи разъедутся с вложениями.

**Контактный лист на девять кадров** (§4-бис даёт 4×2; для девяти):
```bash
mkdir -p sheet && cp sh01-v02.png sheet/01.png && for n in 02 03 04 05 06 07 08 09; do cp sh$n-v01.png sheet/$n.png; done
ffmpeg -v error -y -framerate 1 -i sheet/%02d.png -vf "scale=512:768,tile=3x3" -frames:v 1 sheet/contact.png
```
Лист ловит расхождение между СОСЕДЯМИ; канон персонажа (пальцы, крышки, длина ног) на нём
не виден — эти строки проверяются на полноразмерном кадре. Смотри лист первым, полный
размер — по подозрению.

**`_peek.ts` инструментом не является.** §4-бис называет его рабочим, но он пишет картинку
в захардкоженный `../FILMS/_run/e35/frames/` — та же болезнь, за которую `_sum`/`_ledger`
объявлены огрызками. Медиа плиты достаётся тремя строками через `readAssetMediaAsBase64`.

**Текст канон-плиты лежит в БД, а не в файле.** Строки «канон персонажа» листа приёмки
берутся из `assets.content` по `file_type='SBL-<slug>'` в серии. Ни маршрут, ни шаблон листа
этого не говорили.

**КАНОН-ТЕРМИН ПРАВИТСЯ В ОБОИХ ПРОМПТАХ — кадра И видео (доказано E37).** Видеостадия
перерисовывает лицо и кисти заново; термин, исправленный только в промпте кадра, до готового
клипа не доезжает. Проверено обратной пробой на одном и том же кадре: со старым промптом
видео зубы возвращались на 2,5 с, с добавленным в НЕГАТИВ `no teeth, no bared teeth,
no gritted teeth` — не появились ни в одном из проверенных моментов. Та же механика убрала
краску, залезшую внутрь колбы (`no red sand, no paint mixed into the sand`). Запрет должен
стоять и рядом с описанием, и в списке негативов — в одном общем списке он теряется.

**Что провайдер видео НЕ слышит: запрет на вращение.** Одиннадцать формулировок против
кувырка (`no somersault, no flip, no rolling, no upside down`…) не удержали персонажа в
воздухе от переворота — две попытки, обе кувырком. Лечится МОНТАЖОМ: клип обрезается до
момента, где поза ещё верна. **Обрезка — рычаг той же силы, что пересъёмка, и стоит $0.**

**Строку про ПРОЦЕСС проверяй на клипе, а не на кадре.** «Тянется», «натягивается»,
«отрывается» на статике проверить нечем: в E37 тянущиеся нити краски отсутствовали на кадре
и появились сами на клипе. Часть листа приёмки принципиально относится к видеостадии.

**Клип смотрится полосой из трёх моментов, а не одним стопом:**
```bash
for t in 0.2 2.5 4.8; do ffmpeg -v error -y -ss $t -i sh03.mp4 -frames:v 1 chk/sh03_$t.png; done
```
Начало · середина · ИСХОД в одной строке — исход и есть то, что написано в листе.

**Слепой приёмщик не должен видеть лист с твоими вердиктами.** `blind-brief.ts` копирует
спецификацию ЦЕЛИКОМ, поэтому раздел собственной приёмки и пометки «правка после SH0x» уедут
приёмщику как ответы к задаче. Перед сборкой брифа снимай с листа копию без них:
```bash
node -e "const f=require('fs');let t=f.readFileSync('docs/plans/<run>-expectations-<ep>.md','utf8');
t=t.replace(/## 5-бис[\s\S]*?(?=## 6\.)/,'').replace(/ ?\*\(Правка[^*]*\)\*/g,'');
f.writeFileSync('docs/plans/<run>-expectations-<ep>-blind.md',t)"
```

**Сторожок прогона требует трогать лист ПОСЛЕ каждой пачки промптов.** Третья проверка
`run-algorithm-growth-guard.cjs` блокирует стоп, если самый свежий промпт новее самого
свежего листа ожиданий больше чем на минуту. На первом проходе это срабатывает штатно:
промпты физически пишутся после листа. Лечится не обходом, а работой по правилу — вписал
вердикты приёмки в лист, и он снова свежее.

### 8-тер. След в студии — без него эпизода НЕ СУЩЕСТВУЕТ (оплачено 05.08)

> **Инструмент, произведший изделие, обязан оставить след в студии.** Файл на диске — не
> результат. Результат — строка в базе, по которой изделие видно в интерфейсе и правится
> глазами. **Обходя слой, перечисли, что этот слой делал КРОМЕ того, ради чего его обходишь.**

Три эпизода подряд (E35 · E36 · E37) произвели 195 кадров и 87 клипов, которых студия не
видела: из инструментов прямого вызова строку `assets` заводил ровно один — `register-canon`.
Директор открыл интерфейс и увидел пустой эпизод. **Прогон, доведённый до публикации только
инструментом, не проверяет фабрику** — блок дистрибуции остался непройденным неделю.

**Что делать по ходу прогона, а не в конце:**

```bash
cd webapp
# после каждого принятого кадра и клипа
npx tsx scripts/run/register-media.ts --file <path> --kind frame|clip|cut|music --shot sh01
# один раз перед приёмкой: раскадровка, аниматик, бриф и сценарий ИЗ ФАКТА + сведение денег
npx tsx scripts/run/sync-episode.ts --title "<название>" --script-file ../docs/plans/<лист>.md
```

**Контракт любого инструмента печатает он сам: `--help`.** Флаги, обязательность, умолчания,
допустимые значения, переменные окружения и таблицы БД — оттуда, а не из чтения исходника.
Опечатка во флаге теперь громкий отказ, а не молчаливое умолчание (`--qualiti high` стоил бы
$0,25 вместо $0,018).

**Станция сейчас:** `ensure-episode` · `gen-frame` · `gen-video` · `stitch` · `register-canon`
· `register-media` · `sync-episode` · `publish` · `blind-brief` · `peek-canon` (плита канона
глазами) · `check-video` (что площадка реально сохранила) · `spend` (траты прогона запросом,
не в уме). **Инструментом НЕ являются** `_env.ts`, `_tool.ts`, `_asset.ts` — общий каркас,
несёт пометку `@not-a-tool` и сам не запускается.

**Чего прямой вызов НЕ производит, а студия ждёт:** брифа, сценария, раскадровки, аниматика.
Без них мертвы лента (правки таймингов некуда сохранять) и весь блок дистрибуции — Publicist
требует сценарий И бриф, Key Art требует их же плюс метаданные, Distribution — метаданные и
обложку. `sync-episode` собирает эти документы из факта прогона; **вызывать его до приёмки,
а не после публикации.**

**Ручную работу Директора не перезаписывать.** Тайминги и загруженная музыка живут в
`metadata.animatic_v1` аниматика. Идемпотентное «строка есть — обновлю» стёрло десять его
правок. Правило: **идемпотентность допустима для того, что породила машина; во что писал
человек — только дополняется.**

**Адрес брать из записи, а не строить из имени.** `filename` — каноническое имя ассета, а не
имя файла на диске: путь загрузки музыки кладёт байты с хеш-суффиксом и держит адрес в
`drive_path`. URL, собранный из `filename`, указывает в пустоту.

**След оставляется сам.** `gen-frame`, `gen-video` и `stitch` заводят изделие в студию сразу
после записи файла — `register-media` руками нужен только для того, что уже лежит на диске.
Номер кадра выводится из имени, но лучше передавать `--shot sh01` явно. `stitch` записывает
**порядок сборки** в описание ката: без этого через сутки не восстановить, какая версия
каждого кадра в кат вошла.

### 8-кватер. ПЛАНИРОВАНИЕ — что открыть до того, как писать лист (2026-08-06)

**Весь аппарат гэгостроения лежит в скиллах, а скиллы грузятся ТОЛЬКО агентам.** Прямой путь
их не читает — значит ведущий ум обязан открыть их сам. Не открыл — планирует на пустом
месте, и никакой критик этого не поймает: критик получает свой жанровый движок принудительно,
а автор — нет.

| когда | что читать | зачем |
|---|---|---|
| **до замысла** | `docs/doctrine/spec-procedure.md` | матрица отклонений 7×7: семь параметров кадра × семь направляющих слов; каждую клетку ПРОИЗНЕСТИ, а не вспомнить те, что пришли в голову |
| **до замысла** | `.claude/skills/series-episode-theme-selection` | тема = движок гэгов, не сюжет; плотность считается ГРУППАМИ, не числом; ~60 с → 6–8 различных механизм-групп, остальное — набивка |
| **до раскадровки** | `.claude/skills/sandy-gag-library` | таксономия (10 категорий, минимум 4 разных за эпизод), атомы, **плотность по актам**, запрещённые гэги, обязательный антагонист |
| **до раскадровки** | `.claude/skills/readability-comedy-slapstick` | шестистадийная формула объектной причинности + грамматика глаголов: **бит без цель-глагола — не гэг, а набивка** |
| **до раскадровки** | `.claude/skills/storyboarder-situational-comedy` | микроцикл try→fail→escalation→punchline, комик-тайминг, вертикальная безопасность гэга, три правила удержания Shorts |
| **до промпта кадра** | `.claude/skills/eref-shot-composition` | скрижаль компоновки: СОБЫТИЕ + АКТЁРСКАЯ ЗАДАЧА + КАНОН + ЛИМИТЫ + СОСЕДНИЕ КАДРЫ + НОСИТЕЛЬ + СТАРТ ДВИЖЕНИЯ |

**Три правила, которые нарушаются чаще прочих:**

1. **Ложный успех — ОТДЕЛЬНЫЙ бит.** Сворачивать его в кадр с отдачей нельзя; если кадров
   меньше, чем требует формула, **увеличивают число кадров**, а не сливают стадии. Самый
   частый отказ читаемости за всю историю.
2. **Плотность НИКОГДА не равномерная** — ровная усыпляет внимание. Setup один микро-гэг ·
   build 3–4 · climax каскад 5–7 · resolution один финальный такт.
3. **Хук в первом кадре, без разгона.** Первые ~10% клипа — где уходит больше всего зрителей;
   у дошедших до конца удержание РАСТЁТ, то есть конец работает, а доходят немногие.

## 9. ВТОРОЙ СЕРИАЛ и путь ЧЕРЕЗ ПОЛИНУ (заполнено прогоном «ПАРАДИГМА», 07.08)

### 9.1 Прямой путь работает ТОЛЬКО на S15

`scripts/run/_env.ts` экспортирует константу серии, и её импортируют девять инструментов из
одиннадцати — `gen-frame` (поиск канон-плит), `peek-canon`, `ensure-episode`,
`register-canon` (само ИМЯ файла собирается как `SS-S15-SBL-…`), `publish`, `check-video`,
`blind-brief`. На другом сериале `peek-canon` отвечает `no canon asset SBL-… in S15`.
**Ведёшь не Sandy — сначала распараметри серию, потом генерируй** (D60).

Плиту канона ЛЮБОЙ серии глазами — тремя строками, `peek-canon` тут не помощник:
`assets` по `series_id` + `episode_id IS NULL` + `file_type LIKE 'SBL-%'` →
`readAssetMediaAsBase64({filename, driveFileId, stagingPath})` из `lib/media-cache` → файл →
контактный лист `ffmpeg … tile=4x3`. Одиннадцать плит осматриваются за минуту и $0.

### 9.2 Толкать Полину — чем и что при этом обязано быть живым

```bash
cd webapp
npx tsx scripts/open-pa-thread.ts --episode <uuid>          # тред; иначе post откажет
npx tsx scripts/team-chat-post.ts --file <msg.md> \
    --as-exec-dir-ai --author "<имя Директора>"             # БЕЗ --thread
npx tsx scripts/read-polina-turns.ts 4                      # один запрос, не цикл
```

- **Тред headless не открывается роутом** — `POST /api/concierge/new-thread` закрыт
  middleware'ом, 307 на `/login` (родня D13). `open-pa-thread.ts` зеркалит роут его же
  помощниками. Без ОТКРЫТОГО треда `team-chat-post` отвечает отказом.
- **`--as-exec-dir-ai` ставит `authorized_principal`** — Полина трактует ход как приказ
  Директора; `--author` подписывает имя. Хард-лимиты (публикация · LOCK · бюджет · режим)
  при этом всё равно сторожатся в роуте и тулах: подменить человека там нельзя, и это by design.
- **Толчок будит Полину СОБЫТИЕМ через Inngest.** Нет живого Inngest — ход запишется в базу,
  Полина не проснётся, **ошибки на глазах не будет**. Проверка ответа: в `stream` должен
  появиться `sandystudio/pa/notify-needed` → `EXEC-CONC: Auto-react`, а не пустой `runs: []`.
- **У Полины НЕТ тула смены статуса ассета** (D66). Спросит — предложит написать
  `STATUS:INVALIDATED` в ТЕЛО. Отказывать: статус читается из поля строки. Проставлять самому.
- `INVALIDATED` **в имени файла запрещён** CHECK'ом `assets_filename_format` — меняется
  только поле `status`, имя остаётся прежним.

### 9.3 Два дерева — как убедиться, что стек ТВОЙ

**У Inngest ДВА порта.** `--port` двигает API/UI; connect-gateway висит на своём
(дефолт 8289) и за `--port` НЕ следует. Второе дерево, поднятое на 8289, умирает строкой
`listen tcp :8289: bind` **в свой лог**, а снаружи выглядит живым: `netstat` показывает
слушателя (чужого), приложение отвечает 200. Признаётся только `prod.log`:
`Inngest API Error: 404 Event key not found`.

```bash
netstat -ano | grep -E ":(3000|3001|8288|8388)\s"   # ОДИН PID на двух портах = один Inngest
curl -s -o /dev/null -w "%{http_code}\n" localhost:<InngestPort>/       # 200, не 404
grep -n "NEXT_PUBLIC_APP_URL\|INNGEST_BASE_URL" webapp/.env.local       # ОБА на свои порты
```

`start-stack.ps1` принимает `-Port`, `-InngestPort` и `-InngestGatewayPort`
(дефолт `InngestPort + 1`). Стоп-фаза фильтрует по своему `sqlite-dir`, соседнее дерево не
гасит. **Параметризуя порт — параметризуй ВСЕ порты процесса:** половина параметризации
выглядит рабочей и врёт (D63, D65).

### 9.4 Карта входов конвейера — одной командой, вместо чтения гейта глазами

```bash
node -e "const t=require('fs').readFileSync('lib/agents/gate.ts','utf8');
const re=/'((?:EXEC|ART)-[A-Z0-9-]+)':\s*\{([\s\S]*?)\n  \},/g;let m;
while((m=re.exec(t))){console.log(m[1].padEnd(26),[...m[2].matchAll(/fileTypePrefix:\s*'([^']+)'/g)].map(x=>x[1]).join(' · ')||'—');}"
```

Что она показала 07.08 и что из этого следует помнить: **блок рефов и видео получает только
раскадровку** — ни брифа, ни сценария (проверено и по исполнителю:
`runners/episode-reference-designer.ts:1022`). Раскадровка — производная от сценария, значит
художник рисует, не видя истории, и сокращение раскадровщика становится единственной правдой.
`EXEC-VGEN` не требует ни одного входа. У автора Библии строки требований нет вовсе — поэтому
он пишет плиты от одного брифа, **до всякого сценария**.

### 9.5 Модель документов — как её задал Директор (07.08)

Тема и бриф — **один документ на двух этапах**, не оригинал и пересказ. Бриф — задумка
продюсера-директора, **автора у брифа нет**. Сценарий — развёрнутый бриф, рассказ, и он же
по сути КАНОН; автор — сценарист. Раскадровка — разложение сценария на воспроизводимые
компоненты. Из этого: «агент не читает тему» — не дефект; дефект — когда до нужного места не
доехал СЦЕНАРИЙ.

И следствие для парадигмы: карта §9.4 имеет смысл только в конвейере из многих голов.
**Один ум передавать документы себе не должен** — он держит бриф, сценарий и раскадровку
разом, потому что сам их и написал. Если ловишь себя на починке маршрутов доставки
документов — ты чинишь старую модель.
