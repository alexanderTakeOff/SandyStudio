## 0. Первые тридцать секунд

```bash
cd webapp
curl -s localhost:3001/api/health            # {"ok":true,...,"build":"<git sha>"}
curl -s -o /dev/null -w "inngest=%{http_code}\n" localhost:8388/
```

**`build` — это метка сборки, а не украшение** (13.08): `start-stack.ps1` вшивает в билд
короткий sha и `/api/health` его отдаёт. Вопрос «подняли ли МОЙ код» отвечается сверкой
с `git log --oneline -1`, а не памятью и не датой `.next/BUILD_ID`. Не совпало — стек
поднят со старого билда, `start-stack-nx.cmd -Build`.

Это дерево `C:\SandyStudio-nx` — порты 3001/8388, СВОИ, не master'овские 3000/8288.
Стек не поднят → из корня репозитория: **`start-stack-nx.cmd`** (без сборки, задаёт
`-Port 3001 -InngestPort 8388` сам) или `start-stack-nx.cmd -Build` (после правок кода —
флаг форвардится в `start-stack.ps1`). Голый `start-stack.cmd` без `-nx` бьёт по
3000/8288 — чужим для этой ветки. Стоп — `stop-stack.cmd` (гасит по своему дереву).
**Не поднимать серверы фоновыми job'ами** — харнесс убивает обёртку.

Позиция прогона — §0 заметок. Больше ничего читать не нужно.

**Выбираешь модель — открой МАТРИЦУ, а не спрашивай.** `docs/doctrine/generator-capabilities.md`:
что каждая модель умеет и чего НЕ умеет (проверено, с ценой опыта), журнал всех платных
вызовов и семь законов промпта. Вопрос «чем генерить» задаётся матрице; Директору задаётся
только то, что матрица знать не может. Провёл опыт — занёс строку СРАЗУ, иначе опыт не
состоялся и следующая сессия купит его заново.

## 2. Что обязано быть ДО первого шага

Пропуск любого пункта останавливает конвейер позже и дороже.

1. **Жанр серии заведён и у него есть движки.** `series.genre` должен совпадать со
   скиллами `readability-<genre>` (иначе `EXEC-CREAD` HALT'ит каждую раскадровку),
   `storyboarder-<genre>` и `eref-prompt-<genre>`. Проверка — загрузчиком, не глазами:
   `getAgentSkillManifest({agentId:'EXEC-CREAD', genre})` должен вернуть `mandatory`.
2. **`delivery_targets` эпизода выставлены.** Они управляют размером референсов и
   включают вертикально-безопасную композицию у сценариста и раскадровщика. Выставлять
   ДО запуска сценариста — иначе он пишет вслепую и всё придётся переписывать.
3. **Потолок бюджета эпизода = решение Директора**, не дефолт.
4. **Канон-минимум покрывает ПРОЧТЕНИЯ, а не объекты.** Если эпизод показывает A,
   которое оказывается B, нужны две несхожие плиты: «как выглядит A» и «как выглядит B».
5. **Локация есть.** Нет конкретного места — заводится `empty_background` (плоская
   заливка, генерится не моделью, а ffmpeg'ом: чистый фон модели не отдают).

## 3. Как узнать состояние за секунды

Не спрашивать Полину и не ждать. Идти в источник.

- **Стадии и ассеты** — один запрос к `assets` по `episode_id` с сортировкой по
  `created_at`: имя, статус, версия. Это вся картина конвейера.
- **Матрица по шотам** — `getEpisodeStateMatrix(sb, episodeId)` из
  `lib/agents/state-matrix.ts`: `ref_plan / ref_image / shot_plan / video` на каждый шот.
- **Что реально запускалось** — таблица `jobs` (`agent_id, status, error_message,
  started_at, completed_at`). Лента событий теряет часть падений, `jobs` — нет.
- **Что происходит прямо сейчас** — Inngest GraphQL, без авторизации:
  ```bash
  IJ=$(grep ^INNGEST_BASE_URL= webapp/.env.local | cut -d= -f2-)
  curl -s -X POST "$IJ/v0/gql" -H "Content-Type: application/json" \
    -d '{"query":"{ stream(query:{limit:20}) { trigger createdAt runs { status function { name } } } }"}'
  ```
  Адрес берётся из `.env.local`, а не пишется руками: 12.08 вбитый в рецепт `:8288`
  (порт МАСТЕРА) дал `000`, и из этого был сделан ложный вывод «стек лежит» — ход
  потерян на пустом месте. Порт живёт в одном месте, рецепты его читают.

## 4. Как двигать конвейер

**Событие** (`$KEY` и `$IJ` — `INNGEST_EVENT_KEY` и `INNGEST_BASE_URL` из `webapp/.env.local`;
порт руками не писать, см. §3):

```bash
curl -s -X POST "$IJ/e/$KEY" -H "Content-Type: application/json" \
  -d '{"name":"<event>","data":{...}}'
```

| Событие | data |
|---|---|
| `sandystudio/exec-sw/write-script` | `episodeId`, `revisionNote?` |
| `sandystudio/exec-srev/review-script` | `episodeId` |
| `sandystudio/exec-sb/create-storyboard` | `episodeId`, `revisionNote?` |
| `sandystudio/exec-cread/review-storyboard` | `episodeId`, `storyboardAssetId` |
| `sandystudio/exec-eref-designer/plan` | `episodeId`, `shotId`, `revisionNote?` |

**В Mode 1 реконсилятор сам стадии не поднимает** — творческий гейт ждёт человека.
Этап стартует кнопкой в UI или событием вручную.

**Референсы пускать ПИЛОТАМИ**, не веером: два самых рискованных кадра. Сойдутся —
остальное веером на том же основании. Не сойдутся — заплачено за два, а не за все.

### 4-бис. Прямые вызовы — путь C

Когда эпизод ведётся **мимо слоя агентов** (два последних прогона шли так), станции
запускаются скриптами `webapp/scripts/run/*`. Хранилище, провайдеры, медиа-кэш и леджер
переиспользуются — не вызывается только слой ролей. Запускать из `webapp/`.

| Что нужно | Инструмент | Когда брать |
|---|---|---|
| завести эпизод в базе | `run/ensure-episode.ts` | до любой генерации; выдаёт `episodeId` для всего остального |
| сгенерировать кадр | `run/gen-frame.ts` | один кадр за вызов; **промпт читается из файла** — длинный промпт не переживёт шелл |
| закрепить кадр как канон | `run/register-canon.ts` | когда принятый кадр должен стать единственным источником: копирует в медиа-кэш и заводит строку `assets`, дальше кадры цепляют его по slug |
| оживить кадр | `run/gen-video.ts` | добивает реф до истинного 9:16 своим цветом стены, потом img2vid Seedance |
| собрать эпизод | `run/stitch.ts` | склейка клипов по порядку, один энкод, чёрный хвост |
| опубликовать | `run/publish.ts` | заливка на канал серии, упаковка из паспорта канала, запись id на строку эпизода |
| достать медиа ассета глазами | `run/_peek.ts <slug>` | быстрый взгляд на то, что реально лежит в базе, а не на статус |

**Что инструментами НЕ является, хотя лежит рядом:** `_ledger.ts`, `_sum.ts`, `_music.ts`,
`_music2.ts` — одноразовые огрызки прошлого прогона с **захардкоженным `episode_id` E35**.
Читать как образец запроса можно, запускать на новом эпизоде — нельзя. Итог по деньгам
берётся запросом к `budget_log` по своему эпизоду.

**Чего в прямом пути нет вовсе:** музыки (EXEC-MGEN — заглушка) и обложки для Shorts
(API её поставить не может). Оба места закрываются руками.

**Обязательное окружение.** Все инструменты берут эпизод из `RUN_EPISODE_ID` и **без него
отказываются работать** — умолчания нет намеренно: захардкоженный id молча писал траты
нового эпизода в строку старого (2026-08-04). Ставится один раз на сессию из вывода
`ensure-episode`.

**Порядок работ, проверенный на E36 (41 с, 10 кадров, $18,4):**

1. `ensure-episode` → id. Экспортировать.
2. **Плиты локаций — ПУСТЫМИ, отдельной генерацией.** Плита, снятая из кадра с героем,
   тащит героя в каждый следующий кадр как часть фона. Лишние $0,018 дешевле этого.
   **Приёмка плиты в два шага** (решение Директора 26, 06.08): `APPROVED` — сразу после
   проверки глазами, `LOCKED` — только после первого кадра, где в этой плите постоял герой.
   Половину дефектов видно на пустой плите и дёшево (коралловое пятно без обходной дорожки в
   E37 стоило $0,018 вместо девяти кадров и девяти клипов); вторую половину — масштаб, линию
   горизонта, куда встают ноги — видно ТОЛЬКО в композиции с героем. Два шага разводят
   дешёвую проверку и дорогую, не теряя ни одной.
3. Кадры: `gen-frame` по одному, промпт в файле. Референсы указывать как
   `slug:kind`; порядок в командной строке не важен — инструмент сам сортирует
   **location → identity → style**, и это лечит уход персонажей от канона.
4. Смотреть кадры **контактным листом**, а не по одному:
   `ffmpeg -framerate 1 -i %02d.png -vf "scale=340:510,tile=4x2" -frames:v 1 sheet.png`.
   Расхождения между соседними кадрами видно только рядом.
5. Видео: `gen-video`, `--tier standard --duration 5`. Пад до 9:16 делается сам.
   ~$1,51 и 2–4 минуты на клип. **Пускать по три параллельно** — провайдер выдерживает,
   и час превращается в двадцать минут.
6. Монтаж: `stitch` умеет ТОЛЬКО склейку и чёрный хвост. Обрезка клипов и музыка — ffmpeg
   руками. Клип 5 с, обрезанный до 4 с, даёт нужный темп и убирает вялый хвост.
7. Музыка штатная: `FILMS/_media_cache/Flacon_Pop_Loop-processed.mp3` (130 с). Обрезать
   под длину ката, `volume=0.75`, `afade=t=out` последние 2 с.

## 5. Гейты, которые нельзя обойти

- **Аппрув ассета** (`POST /api/assets/{id}/approve`) требует человеческой сессии —
  headless получает 307 на `/login` (**D13**). Обход: зеркалить маршрут в БД —
  статус, переименование `-DRAFT`→`-APPROVED`, строка в `approvals`, событие в ленте.
- **Инвариант «один утверждённый на слот»**: перед аппрувом нового плана предыдущий
  APPROVED демоутируется в `INVALIDATED` (не `REJECTED` — он не бракован, он проиграл).
- **Хард-лимиты Директора в любом режиме:** публикация · LOCK · бюджет · смена режима.

## 6. Разговор с Полиной

```bash
cd webapp
npx tsx scripts/team-chat-post.ts --file <msg.md> --as-exec-dir-ai   # БЕЗ --thread
npx tsx scripts/read-polina-turns.ts 5                               # один запрос, не цикл
```

- **`--thread` не передавать никогда** — маршрут возьмёт последний открытый. Явный
  тред проверяется только на существование, не на `ended_at`, и запись в закрытый
  тред отвечает `success`, а сообщение уходит в пустоту.

- Записка на доработку у неё ограничена **2000 символов**. Больше — класть полный
  текст в Episode Start Notice (потолок 200 000, производящий агент читает его штатно),
  а в записке давать ссылку.
- Проверять её — одним запросом, не циклом ожидания. Если молчит больше пары минут,
  смотреть Inngest, а не ждать.

## 7. Когда встало

Порядок сужения, от дешёвого к дорогому:

1. `jobs` — есть ли строка, в каком статусе, что в `error_message`.
2. Inngest `stream` — запускалась ли функция вообще.
3. Вердикт критика — не `HALT` ли, и по какой причине.
4. И только потом читать код.

**Частые причины, каждая уже стоила круга:**

- **Жанрового движка нет** → `EXEC-CREAD` HALT без вызова модели. Это корректное
  поведение, а не поломка.
- **Скилл не подхватывается** → проверить `applies_when.agent` на точное совпадение
  строки и `status: ACTIVE`. Комментарий внутри фронтматтера роняет весь файл (**D22**).
- **Инструкция роли правится, а поведение не меняется** → кэш `systemPromptCache`
  живёт весь процесс у большинства runner'ов; правка `.md` требует рестарта.
  Скиллы этой болезнью не болеют — у них TTL 30 секунд. **Поэтому всё, что крутится
  итерациями, должно жить в скилле, а не в файле роли.**
- **Провайдер молчит** → голый `fetch` без таймаута; смотреть, не висит ли `jobs` в
  `RUNNING` дольше ожидаемого.

## 9. Обязанность прогона

Прогон существует ради двух артефактов: этого маршрута и скилла Полины
`ss-series-starter`. Значит:

- **найденный разрыв пишется в `showrunner-tooling-gaps.md` номером D<N>**, и Директору
  докладывается уже номером — доклад без номера означает, что запись не сделана;
- **§0 заметок переписывается в конце каждого шага**, а не в конце сессии: блок,
  обновляемый в конце сессии, не переживает обрыв, а обрыв — это и есть тот случай,
  ради которого он существует;
- **то, что оказалось верным маршрутом, дописывается СЮДА** — иначе следующий прогон
  снова роет код.

### 4-тер. Три правила приёмки, оплаченные браком E36

1. **Переснял кадр — перепиши его строки.** Новый промпт со старым листом приёмки не
   проверяет ничего: строка «уходит из кадра» на кадре «стоит и подмигивает» молчит, и брак
   проходит. Сторожок прогона блокирует стоп, если промпт новее листа ожиданий.
2. **Канон ПЕРСОНАЖА живёт отдельным чеклистом и наследуется каждым кадром** — ноги, руки,
   крышка, запечатанность, закрытый рот, отсутствие подставки. Это строки героя, не эпизода;
   без них их не проверяет никто и никогда (в E36 герой уехал в финал без ног).
3. **Проверяй КАДР, а не изменение.** Генератор перерисовывает каждый пиксель — «неизменного»
   у него нет. Проверка только той детали, которую просили поменять, — самая частая слепота.

**Что провайдер устойчиво НЕ умеет** (проверено тремя попытками, E36): показать превращение
песка внутри запечатанной колбы. Любая формулировка выводит иглы наружу или растит корону
вокруг головы. Показывай СОСТОЯНИЕ, переход оставляй за кадром; если строка требует
перехода — уступает строка, а не канон.

- **Стек поднимать НЕ нужно для прямого пути.** Скрипты `run/*` ходят в Supabase и к
  провайдерам напрямую; приложение и Inngest им не требуются. §0 с curl'ами — про путь
  агентов.
- **Лист ожиданий не сочиняй с нуля** — есть каркас: `docs/plans/_expectations-template.md`,
  включая пять правил, как писать строку «приму, если».
- **Деньги считай запросом к `budget_log` по СВОЕМУ `episode_id`.** Скрипты `_sum`/`_ledger`
  — огрызки с чужим эпизодом, см. §4-бис.

### 8-бис. Как реально вызываются инструменты (заполнено холодным прогоном E37)

**СНАЧАЛА — РЕЕСТР, а не исходники.** `docs/TOOLS.md` содержит контракт КАЖДОГО инструмента:
аргументы, обязательность, умолчания, допустимые значения, переменные окружения, читаемые и
записываемые таблицы. Он **выведен из кода**, а не написан руками, и расходиться с ним не
может: сверка живёт в тестах и валит `npm test`. Отдельный инструмент печатает свой контракт
сам — `--help`. Открывать исходник, чтобы узнать, как вызвать, больше не нужно и не следует
(это и был D59: сорок минут из ста восьми).

```bash
cd webapp
npx tsx scripts/tools-registry.ts            # сверить реестр с кодом
npx tsx scripts/tools-registry.ts --write    # пересобрать после правки инструмента
```

Маршрут называл инструменты, но не показывал ни одного вызова, и первая сессия читала все
семь файлов целиком. Вот вызовы, проверенные на живом эпизоде.

**Все команды — из `webapp/`.** `_env.ts` читает `.env.local` из `process.cwd()`; из корня
репозитория скрипт падает на `Cannot find module './scripts/run/_env'`, и сообщение не
объясняет причину.

**ДВЕ переменные окружения, обе без умолчаний** (с 07.08): `RUN_EPISODE_ID` — эпизод, на
который списываются траты, и `RUN_SERIES_ID` — сериал, в котором ищется канон и собираются
имена ассетов. Раньше сериал был захардкожен, и станция работала ровно на одном (D60).
Не задана — инструмент отказывает ДО работы и называет причину.

```bash
cd webapp
export RUN_SERIES_ID=<uuid серии>             # ищется в `series` по коду, напр. SS-S20
npx tsx scripts/run/ensure-episode.ts --code SS-S15-E37 \
  --title "Свежая краска (Wet Paint)" --ceiling 25 --theme wet_paint_floor --run cold-run
export RUN_EPISODE_ID=<id из вывода>          # без него все остальные инструменты отказывают

npx tsx scripts/run/gen-frame.ts \
  --prompt-file ../FILMS/_run/e37/prompts/SS-S15-E37-PRO-sh01-v01-DRAFT.txt \
  --refs "location_<slug>:location,character_sandy_hourglass:identity,style_s15_style_canon_2d_v1:style" \
  --out ../FILMS/_run/e37/frames/sh01-v01.png --size 1024x1536 --quality low

npx tsx scripts/run/register-canon.ts --slug location_<slug> \
  --file ../FILMS/_run/e37/frames/loc-v02.png --desc "<описание плиты словами>"

npx tsx scripts/run/gen-video.ts --frame ../FILMS/_run/e37/frames/sh01.png \
  --prompt-file ../FILMS/_run/e37/prompts/SS-S15-E37-PRO-sh01_video-v01-DRAFT.txt \
  --out ../FILMS/_run/e37/clips/sh01.mp4 --duration 5 --tier standard
```

**Имя файла промпта обязано соответствовать конвенции CLAUDE.md §3.** Хук
`naming-validator.cjs` валидирует всё, что лежит в папке с именем `prompts`, — и режет
`loc-paint-corridor.txt` до генерации. Годится `SS-S15-E37-PRO-<snake_case>-v01-DRAFT.txt`.
Это не помеха, а бесплатная версионность: `-v02-` рядом с `-v01-` сам ведёт историю пересъёмок.

**Качество `low` держит канон.** Тринадцать кадров E37 сняты на `--quality low` ($0,018
против $0,25 у `high`) — персонаж, стиль и плита воспроизводятся; на весь эпизод картинки
стоили **$0,23 из потолка $25**. Начинай с `low` и поднимай по факту, а не заранее.

**Порядок референсов писать не нужно** — инструмент сам сортирует
`location → identity → style` (`gen-frame.ts:83`). В командной строке пиши как удобно; в
ТЕКСТЕ промпта нумеруй роли в том же порядке (Image 1 — локация, 2 — персонаж, 3 — стиль),
иначе подписи разъедутся с вложениями.

**Контактный лист на девять кадров** (§4-бис даёт 4×2; для девяти):
```bash
mkdir -p sheet && cp sh01-v02.png sheet/01.png && for n in 02 03 04 05 06 07 08 09; do cp sh$n-v01.png sheet/$n.png; done
ffmpeg -v error -y -framerate 1 -i sheet/%02d.png -vf "scale=512:768,tile=3x3" -frames:v 1 sheet/contact.png
```
Лист ловит расхождение между СОСЕДЯМИ; канон персонажа (пальцы, крышки, длина ног) на нём
не виден — эти строки проверяются на полноразмерном кадре. Смотри лист первым, полный
размер — по подозрению.

**`_peek.ts` инструментом не является.** §4-бис называет его рабочим, но он пишет картинку
в захардкоженный `../FILMS/_run/e35/frames/` — та же болезнь, за которую `_sum`/`_ledger`
объявлены огрызками. Медиа плиты достаётся тремя строками через `readAssetMediaAsBase64`.

**Четыре инструмента, чей ВЫВОД или контракт уже, чем кажется** (собрано прогоном Полины
12.08, подробности с файлами и строками — в `THEO-INBOX.md`):

| Инструмент | Что делает не то | Как обойти сегодня |
|---|---|---|
| `run/ensure-episode.ts` | рождает эпизод сразу в `BRIEF_APPROVED` — брифа нет, а гейт уже выглядит пройденным; баннеры Директора показывают неправду с первой секунды | помнить, что статус на рождении ничего не значит; смотреть наличие `SPC-brief` |
| `run/set-status.ts` | ставя `APPROVED`, вытесняет LOCKED-строку того же слота в `INVALIDATED` **молча** — хард-лимит Директора снимается инструментом | перед `--status approved` проверить, не LOCKED ли текущий утверждённый |
| `run/register-canon.ts` | только PNG, и **идемпотентен по слагу** — повторный вызов затирает строку вместо новой версии; для текстовой плиты (`general_idea`) пера нет вовсе | текстовая плита — `POST /api/series/{id}/bible` (сам инкрементит версию, рождает DRAFT) |
| `run/cast-episode.ts` | печатает `asset ?` вместо uuid — «сделано» не предъявлено строкой | добирать `show-asset`, пока не починено |

**Инструмент соврал — пиши в `THEO-INBOX.md`, прогон НЕ останавливай.** Очередь Полины к
Тео (заведена 12.08): дефект инструмента, недостающее перо, врущая инструкция, правка в
sensitive-файле — то, что она не может или не должна чинить сама. Обошла, записала, пошла
дальше; Тео забирает и **удаляет закрытые** — файл живёт короткой очередью, а не архивом.
Каждый пункт несёт дату, файл:строку, чем обошли и почему не ждёт. Заголовки приходят Тео
хуком `theo-inbox.cjs` на каждом ходе — не заметить нельзя.

**Текст канон-плиты лежит в БД, а не в файле.** Строки «канон персонажа» листа приёмки
берутся из `assets.content` по `file_type='SBL-<slug>'` в серии. Ни маршрут, ни шаблон листа
этого не говорили.

**КАНОН-ТЕРМИН ПРАВИТСЯ В ОБОИХ ПРОМПТАХ — кадра И видео (доказано E37).** Видеостадия
перерисовывает лицо и кисти заново; термин, исправленный только в промпте кадра, до готового
клипа не доезжает. Проверено обратной пробой на одном и том же кадре: со старым промптом
видео зубы возвращались на 2,5 с, с добавленным в НЕГАТИВ `no teeth, no bared teeth,
no gritted teeth` — не появились ни в одном из проверенных моментов. Та же механика убрала
краску, залезшую внутрь колбы (`no red sand, no paint mixed into the sand`). Запрет должен
стоять и рядом с описанием, и в списке негативов — в одном общем списке он теряется.

**Что провайдер видео НЕ слышит: запрет на вращение.** Одиннадцать формулировок против
кувырка (`no somersault, no flip, no rolling, no upside down`…) не удержали персонажа в
воздухе от переворота — две попытки, обе кувырком. Лечится МОНТАЖОМ: клип обрезается до
момента, где поза ещё верна. **Обрезка — рычаг той же силы, что пересъёмка, и стоит $0.**

**Строку про ПРОЦЕСС проверяй на клипе, а не на кадре.** «Тянется», «натягивается»,
«отрывается» на статике проверить нечем: в E37 тянущиеся нити краски отсутствовали на кадре
и появились сами на клипе. Часть листа приёмки принципиально относится к видеостадии.

**Клип смотрится полосой из трёх моментов, а не одним стопом:**
```bash
for t in 0.2 2.5 4.8; do ffmpeg -v error -y -ss $t -i sh03.mp4 -frames:v 1 chk/sh03_$t.png; done
```
Начало · середина · ИСХОД в одной строке — исход и есть то, что написано в листе.

**Слепой приёмщик не должен видеть лист с твоими вердиктами.** `blind-brief.ts` копирует
спецификацию ЦЕЛИКОМ, поэтому раздел собственной приёмки и пометки «правка после SH0x» уедут
приёмщику как ответы к задаче. Перед сборкой брифа снимай с листа копию без них:
```bash
node -e "const f=require('fs');let t=f.readFileSync('docs/plans/<run>-expectations-<ep>.md','utf8');
t=t.replace(/## 5-бис[\s\S]*?(?=## 6\.)/,'').replace(/ ?\*\(Правка[^*]*\)\*/g,'');
f.writeFileSync('docs/plans/<run>-expectations-<ep>-blind.md',t)"
```

**Сторожок прогона требует трогать лист ПОСЛЕ каждой пачки промптов.** Третья проверка
`run-algorithm-growth-guard.cjs` блокирует стоп, если самый свежий промпт новее самого
свежего листа ожиданий больше чем на минуту. На первом проходе это срабатывает штатно:
промпты физически пишутся после листа. Лечится не обходом, а работой по правилу — вписал
вердикты приёмки в лист, и он снова свежее.

### 8-тер. След в студии — без него эпизода НЕ СУЩЕСТВУЕТ (оплачено 05.08)

> **Инструмент, произведший изделие, обязан оставить след в студии.** Файл на диске — не
> результат. Результат — строка в базе, по которой изделие видно в интерфейсе и правится
> глазами. **Обходя слой, перечисли, что этот слой делал КРОМЕ того, ради чего его обходишь.**

Три эпизода подряд (E35 · E36 · E37) произвели 195 кадров и 87 клипов, которых студия не
видела: из инструментов прямого вызова строку `assets` заводил ровно один — `register-canon`.
Директор открыл интерфейс и увидел пустой эпизод. **Прогон, доведённый до публикации только
инструментом, не проверяет фабрику** — блок дистрибуции остался непройденным неделю.

**Что делать по ходу прогона, а не в конце:**

```bash
cd webapp
# после каждого принятого кадра и клипа
npx tsx scripts/run/register-media.ts --file <path> --kind frame|clip|cut|music --shot sh01
# один раз перед приёмкой: раскадровка, аниматик, бриф и сценарий ИЗ ФАКТА + сведение денег
npx tsx scripts/run/sync-episode.ts --title "<название>" --script-file ../docs/plans/<лист>.md
```

**Контракт любого инструмента печатает он сам: `--help`.** Флаги, обязательность, умолчания,
допустимые значения, переменные окружения и таблицы БД — оттуда, а не из чтения исходника.
Опечатка во флаге теперь громкий отказ, а не молчаливое умолчание (`--qualiti high` стоил бы
$0,25 вместо $0,018).

**Станция сейчас — 14 инструментов, контракт каждого в `docs/TOOLS.md`:** `ensure-episode` ·
`gen-frame` · `gen-video` · `stitch` · `register-canon` · `register-media` · `sync-episode` ·
`publish` · `blind-brief` · `check-video` · `spend` — и **три пришедших с Ф3 (07.08)**:

- **`show-asset` — ГЛАЗА.** Показывает ЛЮБОЕ изделие, а не только плиту канона (`peek-canon`
  им и заменён): `--slug` — канон серии, `--type` — свежайшее изделие эпизода, `--id` — точная
  строка. Текст печатает дословно, картинку кладёт файлом, а **видео отдаёт ПОЛОСОЙ кадров** —
  начало · середина · исход, потому что исход по одному стоп-кадру не проверяется.
- **`write-asset` — ПЕРО.** Пишет документ эпизода САМ: сценарий, раскадровку, планы,
  метаданные. Имя собирает по конвенции из кода эпизода — руками его набирают с ошибкой.
  Новая версия заводит соседа, историю пересъёмок не затирает. `--status DRAFT` кладёт
  черновик в слот, не вытесняя утверждённое: **черновик — это АССЕТ, а не сообщение.**
  На `IMG-`/`VID-`/`AUD-` отказывает громко: медиа заводят `gen-*` и `register-media`, они
  кладут ещё и байты, а здесь вышла бы строка без файла.
- **`set-status` — СТАТУС.** Меняет ПОЛЕ строки, а не пишет надпись в тело. При повышении до
  `APPROVED` вытесняет прежнего в том же слоте тем же кодом, что и маршрут аппрува.
  `LOCKED` не ставит и не снимает — это хард-лимит Директора.

`INVALIDATED` в ИМЕНИ файла не бывает: CHECK базы знает пять статусов, шестой живёт только в
поле. `set-status` это учитывает сам.

**Инструментом НЕ являются** `_env.ts`, `_tool.ts`, `_asset.ts` — общий каркас, несёт пометку
`@not-a-tool` и сам не запускается.

**Чего прямой вызов НЕ производит, а студия ждёт:** брифа, сценария, раскадровки, аниматика.
Без них мертвы лента (правки таймингов некуда сохранять) и весь блок дистрибуции — Publicist
требует сценарий И бриф, Key Art требует их же плюс метаданные, Distribution — метаданные и
обложку. `sync-episode` собирает эти документы из факта прогона; **вызывать его до приёмки,
а не после публикации.**

**Ручную работу Директора не перезаписывать.** Тайминги и загруженная музыка живут в
`metadata.animatic_v1` аниматика. Идемпотентное «строка есть — обновлю» стёрло десять его
правок. Правило: **идемпотентность допустима для того, что породила машина; во что писал
человек — только дополняется.**

**Адрес брать из записи, а не строить из имени.** `filename` — каноническое имя ассета, а не
имя файла на диске: путь загрузки музыки кладёт байты с хеш-суффиксом и держит адрес в
`drive_path`. URL, собранный из `filename`, указывает в пустоту.

**След оставляется сам.** `gen-frame`, `gen-video` и `stitch` заводят изделие в студию сразу
после записи файла — `register-media` руками нужен только для того, что уже лежит на диске.
Номер кадра выводится из имени, но лучше передавать `--shot sh01` явно. `stitch` записывает
**порядок сборки** в описание ката: без этого через сутки не восстановить, какая версия
каждого кадра в кат вошла.

### 8-кватер. ПЛАНИРОВАНИЕ — что открыть до того, как писать лист (2026-08-06)

**Весь аппарат гэгостроения лежит в скиллах, а скиллы грузятся ТОЛЬКО агентам.** Прямой путь
их не читает — значит ведущий ум обязан открыть их сам. Не открыл — планирует на пустом
месте, и никакой критик этого не поймает: критик получает свой жанровый движок принудительно,
а автор — нет.

| когда | что читать | зачем |
|---|---|---|
| **до замысла** | `docs/doctrine/spec-procedure.md` | матрица отклонений 7×7: семь параметров кадра × семь направляющих слов; каждую клетку ПРОИЗНЕСТИ, а не вспомнить те, что пришли в голову |
| **до замысла** | `.claude/skills/series-episode-theme-selection` | тема = движок гэгов, не сюжет; плотность считается ГРУППАМИ, не числом; ~60 с → 6–8 различных механизм-групп, остальное — набивка |
| **до раскадровки** | `.claude/skills/sandy-gag-library` | таксономия (10 категорий, минимум 4 разных за эпизод), атомы, **плотность по актам**, запрещённые гэги, обязательный антагонист |
| **до раскадровки** | `.claude/skills/readability-comedy-slapstick` | шестистадийная формула объектной причинности + грамматика глаголов: **бит без цель-глагола — не гэг, а набивка** |
| **до раскадровки** | `.claude/skills/storyboarder-situational-comedy` | микроцикл try→fail→escalation→punchline, комик-тайминг, вертикальная безопасность гэга, три правила удержания Shorts |
| **до промпта кадра** | `.claude/skills/eref-shot-composition` | скрижаль компоновки: СОБЫТИЕ + АКТЁРСКАЯ ЗАДАЧА + КАНОН + ЛИМИТЫ + СОСЕДНИЕ КАДРЫ + НОСИТЕЛЬ + СТАРТ ДВИЖЕНИЯ |
| **при приёмке** | `agents/exec/creative_readability_critic.md` | R01–R06 — форма проверки читаемости, годная под любой жанр |

**Три правила, которые нарушаются чаще прочих:**

1. **Ложный успех — ОТДЕЛЬНЫЙ бит.** Сворачивать его в кадр с отдачей нельзя; если кадров
   меньше, чем требует формула, **увеличивают число кадров**, а не сливают стадии. Самый
   частый отказ читаемости за всю историю.
2. **Плотность НИКОГДА не равномерная** — ровная усыпляет внимание. Setup один микро-гэг ·
   build 3–4 · climax каскад 5–7 · resolution один финальный такт.
3. **Хук в первом кадре, без разгона.** Первые ~10% клипа — где уходит больше всего зрителей;
   у дошедших до конца удержание РАСТЁТ, то есть конец работает, а доходят немногие.

### 9.2 Толкать Полину — чем и что при этом обязано быть живым

> **С 08.08 поверхностей ДВЕ, и они не сообщаются.** Ход ЕДИНОМУ УМУ (парадигма) —
> `scripts/mind-post.ts`, §9.9. Всё, что ниже, — СТАРЫЙ консьерж: `team-chat-post`
> пишет в `concierge_turns` и будит Полину событием, но **ум это сообщение не видит
> вообще** (лифт `claude_message` в контекст есть только у старого билдера промпта,
> у `lib/mind/prompt.ts` его нет). Послать уму ход через team-chat НЕЛЬЗЯ.

```bash
cd webapp
npx tsx scripts/open-pa-thread.ts --episode <uuid>          # тред; иначе post откажет
npx tsx scripts/team-chat-post.ts --file <msg.md> \
    --as-exec-dir-ai --author "<имя Директора>"             # БЕЗ --thread
npx tsx scripts/read-polina-turns.ts 4                      # один запрос, не цикл
```

- **Тред headless не открывается роутом** — `POST /api/concierge/new-thread` закрыт
  middleware'ом, 307 на `/login` (родня D13). `open-pa-thread.ts` зеркалит роут его же
  помощниками. Без ОТКРЫТОГО треда `team-chat-post` отвечает отказом.
- **`--as-exec-dir-ai` ставит `authorized_principal`** — Полина трактует ход как приказ
  Директора; `--author` подписывает имя. Хард-лимиты (публикация · LOCK · бюджет · режим)
  при этом всё равно сторожатся в роуте и тулах: подменить человека там нельзя, и это by design.
- **Толчок будит Полину СОБЫТИЕМ через Inngest.** Нет живого Inngest — ход запишется в базу,
  Полина не проснётся, **ошибки на глазах не будет**. Проверка ответа: в `stream` должен
  появиться `sandystudio/pa/notify-needed` → `EXEC-CONC: Auto-react`, а не пустой `runs: []`.
- **У Полины НЕТ тула смены статуса ассета** (D66). Спросит — предложит написать
  `STATUS:INVALIDATED` в ТЕЛО. Отказывать: статус читается из поля строки. Проставлять самому.
- `INVALIDATED` **в имени файла запрещён** CHECK'ом `assets_filename_format` — меняется
  только поле `status`, имя остаётся прежним.
- **У Полины ДРУГОЙ комплект инструментов, чем у прямого пути** (вскрыто Ф4, 07.08).
  `docs/TOOLS.md` описывает только 14 CLI-тулов `scripts/run/*` — из чата Полины они
  **невызываемы**. Её собственные ~49 тулов живут в `lib/concierge/tools/index.ts`
  (массив `TOOLS`) и уходят проводами в слой агентов; каталога в docs у них нет — контракт
  читается из `schema` каждого тула. Практическое следствие: прежде чем просить Полину
  «сделай X инструментом Y», проверь, в ЕЁ ли комплекте Y, — иначе она честно предложит
  обходной путь через `triggerAgent`, и это не её ошибка. До закрытия Ф4 сшивки миров нет.

### 9.3 Два дерева — как убедиться, что стек ТВОЙ

**У Inngest ДВА порта.** `--port` двигает API/UI; connect-gateway висит на своём
(дефолт 8289) и за `--port` НЕ следует. Второе дерево, поднятое на 8289, умирает строкой
`listen tcp :8289: bind` **в свой лог**, а снаружи выглядит живым: `netstat` показывает
слушателя (чужого), приложение отвечает 200. Признаётся только `prod.log`:
`Inngest API Error: 404 Event key not found`.

```bash
netstat -ano | grep -E ":(3000|3001|8288|8388)\s"   # ОДИН PID на двух портах = один Inngest
curl -s -o /dev/null -w "%{http_code}\n" localhost:<InngestPort>/       # 200, не 404
grep -n "NEXT_PUBLIC_APP_URL\|INNGEST_BASE_URL" webapp/.env.local       # ОБА на свои порты
```

`start-stack.ps1` принимает `-Port`, `-InngestPort` и `-InngestGatewayPort`
(дефолт `InngestPort + 1`). Стоп-фаза фильтрует по своему `sqlite-dir`, соседнее дерево не
гасит. **Параметризуя порт — параметризуй ВСЕ порты процесса:** половина параметризации
выглядит рабочей и врёт (D63, D65).

**Деревьев ТРИ, а стеков должно быть два.** Мастер (`C:\SandyStudio`, `:3000/:8288`) и
рабочее дерево (`:3001/:8388`, поднимается `start-stack-nx.cmd`) — станки. Клон агента
(`C:\SandyStudio-polina`) — НЕ станок: это рабочая поверхность headless-сессии, туда мост
спавнит `claude -p --resume`, там переключаются ветки и правится код. Лаунчеры
`start-stack*.cmd` внутри клона **инструментом не являются** — они приехали туда клоном
репозитория и прибиты к дефолтам `:3000/:8288`, то есть к портам мастера.

Цена ошибки несимметрична: приложение и Inngest на занятых портах молча не встанут (отказ
уйдёт в лог, на экране будет «Stack up»), а **блок моста стартует безусловно** — он
проверяет лишь наличие `roles/polina.md`. Итог двойного клика в клоне: серверов ноль,
мостов два. Два моста читают одну строку Директора и оба спавнят ход — двойной ответ,
двойные деньги, гонка за один `session_id`. Стоп-фаза их не разведёт: она гасит процессы,
в чьей командной строке стоит **свой** корень, а мост из клона несёт чужой.

Проверка живости — деревом процессов, не логом (мост heartbeat не пишет):

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -match 'mind-bridge' } |
  Select-Object ProcessId, ParentProcessId, CreationDate   # ОДНА цепочка = один мост
```

Рестарт стека мост НЕ двоит (проверено живьём 09.08: старая цепочка умирает целиком,
включая npx-родителя, у которого пути дерева в строке нет). Перебилд нужен по датам, а не
по ощущению: `.next/BUILD_ID` старше самого свежего исходника — собирать, иначе нет.

**Код между деревьями ходит В ОДНУ СТОРОНУ** (13.08). `origin` клона Полины — это МОЁ
рабочее дерево, а не GitHub, поэтому `git push` оттуда отбивается
`refusing to update checked out branch`. Единственный штатный обмен: **она делает pull из
меня, я делаю fetch из неё** — `git fetch C:\SandyStudio-polina paradigm/direct-mind` и
merge у себя. `pull --ff-only` в её клоне тоже не пройдёт, когда ветки разошлись — там
rebase. Синхронизацией занимается ОДИН оркестратор (я), просить об этом ум — заводить
гонку за общую ветку.

### 9.4 Карта входов конвейера — одной командой, вместо чтения гейта глазами

```bash
node -e "const t=require('fs').readFileSync('lib/agents/gate.ts','utf8');
const re=/'((?:EXEC|ART)-[A-Z0-9-]+)':\s*\{([\s\S]*?)\n  \},/g;let m;
while((m=re.exec(t))){console.log(m[1].padEnd(26),[...m[2].matchAll(/fileTypePrefix:\s*'([^']+)'/g)].map(x=>x[1]).join(' · ')||'—');}"
```

Что она показала 07.08 и что из этого следует помнить: **блок рефов и видео получает только
раскадровку** — ни брифа, ни сценария (проверено и по исполнителю:
`runners/episode-reference-designer.ts:1022`). Раскадровка — производная от сценария, значит
художник рисует, не видя истории, и сокращение раскадровщика становится единственной правдой.
`EXEC-VGEN` не требует ни одного входа. У автора Библии строки требований нет вовсе — поэтому
он пишет плиты от одного брифа, **до всякого сценария**.

### 9.5 Модель документов — как её задал Директор (07.08)

Тема и бриф — **один документ на двух этапах**, не оригинал и пересказ. Бриф — задумка
продюсера-директора, **автора у брифа нет**. Сценарий — развёрнутый бриф, рассказ, и он же
по сути КАНОН; автор — сценарист. Раскадровка — разложение сценария на воспроизводимые
компоненты. Из этого: «агент не читает тему» — не дефект; дефект — когда до нужного места не
доехал СЦЕНАРИЙ.

И следствие для парадигмы: карта §9.4 имеет смысл только в конвейере из многих голов.
**Один ум передавать документы себе не должен** — он держит бриф, сценарий и раскадровку
разом, потому что сам их и написал. Если ловишь себя на починке маршрутов доставки
документов — ты чинишь старую модель.

### 9.6 Мост единого ума (Ф4, доведён живым прогоном «Зрачок»/«Зрачок-2», 08.08)

Панель Полины ходит в `/api/mind/chat` (не в старый `/api/concierge/chat`) за флагом
`NEXT_PUBLIC_MIND_CHAT=1` в `.env.local` — это **build-time** переменная, правка требует
пересборки, не просто рестарта. Тред = эпизод: своя лента на каждый `episode_id`, панель
переключает её сама при смене открытого эпизода в URL.

**Два мира инструментов слиты в одном цикле**, но у них разная природа:
- 14 CLI-инструментов `scripts/run/*` — идут через `lib/mind/tool-bridge.ts`
  (`invokeMindTool`), in-process, без `npx tsx` на вызов.
- 19 выживших чат-тулов (`lib/mind/chat-tools.ts`) — идут напрямую через
  `findMindChatTool().execute()`.

**Мост даёт уму глаза (D70, 08.08).** `show-asset` — CLI-инструмент, его контракт — писать
файл на диск для человека. Мост подставляет временный `--out`, если ум её не назвала,
читает записанное ОБРАТНО (`collectImages` в `tool-bridge.ts`) и кладёт как настоящий
Anthropic image-блок в тред. Работает ТОЛЬКО на native Anthropic-пути
(`CONCIERGE_ANTHROPIC_NATIVE=true`) — на compat-поверхности картинка тихо разворачивается в
текст. Если ум пишет «не могу увидеть кадр» — проверь этот флаг раньше, чем код.

**Мост держит осторожность за ум (D71).** `gen-frame`/`register-canon`, вызванные ЧЕРЕЗ
МОСТ, уходят в `DRAFT` по умолчанию, даже если инструмент сам по себе (CLI) умолчает
`APPROVED` — подмена в `applyDraftDefault()`, CLI-путь не тронут. Approve — осознанный
`set-status`, отдельным шагом, после того как кто-то (человек или слепой критик)
действительно посмотрел.

**Канон живёт на СЕРИИ, не на эпизоде (D72, доказано «Зрачок-2»).** Заводишь чистый эпизод
внутри того же сериала — канон НЕ обнуляется: старые плиты, включая раздвоенные слаги и
неверный текст (например, «pale grey-ochre» радужка вместо разноцветной — брак канона, не
рендера), остаются на месте и читаются новым эпизодом как есть. «Чистый прогон» чистит
эпизод, не серию. Слаг канон-плиты ОБЯЗАН нести категорию сам (`object_eyelid_shutter`, не
`eyelid_shutter`) — `persistAsset` теперь ищет близкий `file_type` перед вставкой и
отказывает громко, но это ловит только НОВЫЕ дубли, старые чинятся руками.

**Ум умеет вынести развилку, а не молчать.** Если свежее слово Директора в треде расходится
с уже записанным каноном — рабочий ответ ума: назвать оба источника, дать рекомендацию, и
ЖДАТЬ. Не тихо выбрать сторону. Это наблюдаемое поведение, не гипотеза — E03 остановилась
на развилке «радужка серая по канону vs разноцветная по свежему слову» без единой траты.

**Кнопка отправки в браузере ненадёжна сразу после навигации.** Клик по кнопке `Send` сразу
после `navigate` иногда не регистрируется (текст остаётся в поле, ход не уходит) — проверять
не скриншотом чата (транскрипт может не отрисоваться даже при реально идущем запросе), а
`read_network_requests` (с `clear: true`, иначе кэш соврёт) или прямым запросом к
`concierge_threads`/`concierge_turns`. Долгий ход (сценарий+раскадровка+пилот) — ждать
фоновым скриптом-опросом (`run_in_background`), не серией коротких `wait`.

### 9.7 Три станции держатся НЕ инструментом, а тем, что рядом (D73/D75, медиа-кэш, гирлянда окон, запрет экрана — 08.08)

**Реф-лукап с историей версий падает на `.maybeSingle()` (D75).** Плита с историей
(`v01 INVALIDATED` + `v02 DRAFT`, обе строки — один `file_type`) отдаёт ДВЕ строки на
запрос. Любой лукап по `file_type` в `gen-frame.ts` (реф-лукап) и `_asset.ts
persistAsset` (поиск существующей строки) берёт `.order('version',{ascending:false})
.limit(1)`, не `.maybeSingle()` — иначе падает молча ровно там, где история версий
реальна, а не на первой генерации.

**Пример имени в `--help` не может быть обрезан многоточием (D73).** `show-asset`
показывал `IMG-episode_ref…` — ум дважды промахнулся мимо реального `file_type` тем же
классом ошибки, что D68 когда-то закрыл для SCR. Правило станции: пример имени в
`--help` — всегда полный, с конкретным реальным слагом, не усечённый.

**Медиа резолвится ИМЕНЕМ ФАЙЛА в локальном кэше, не полями `drive_*` (Ш33).**
`readAssetMediaAsBase64` → `lib/media-cache.ts`: `cachedFileIfPresent(filename)` —
резолюция идёт по строке имени файла в `FILMS/_media_cache/.../bible/media/` (общий
кэш для ВСЕХ деревьев воркт ри). Для local-only ассетов (не выгруженных в Drive) поля
`drive_file_id`/`drive_path`/`staging_path` — не инструмент разрешения, они пустые и не
участвуют. Слить дубль канон-плиты = переименовать/скопировать ФАЙЛ под правильное имя,
а не UPDATE строки в базе — правка строки без правки файла ничего физически не переносит.

**Гирлянду окон держит `-NoExit`, а не живой процесс.** `start-stack.ps1` запускал окна
через `Start-Process powershell -NoExit` — окно живёт даже после того как стоп/пересборка
убили дочерний `node.exe`/`inngest.exe` (стоп целится по PID потомка, не обёртки). Без
`-NoExit` окно закрывается само, когда его команда завершается. Фильтр по пустышкам —
сразу по пути дерева (`$RepoRoot`), не по голому слову «SandyStudio»: харнесс поднимает
свой PowerShell тем же паттерном и чуть не попал под чистку.

**Браузер — БОЛЬШЕ НЕ инструмент для разговора с Полиной (запрет Директора, 08.08,
постоянный, не разовый).** Кнопка `Send` теряла клики (~6+ раз за сессию), а
`mcp__claude-in-chrome__computer` в `/context` съедал 1M+ токенов на скриншотах панели.
Штатный путь — прямой POST на `/api/mind/chat` (`{messages, threadId, episodeId}`, без
куки — кука нужна только `publish`-хардлимиту); паттерн уже есть в
`scripts/team-chat-post.ts` для старого роута (§9.2), тот же приём переносится на новый
маршрут. Экран остаётся только для того, что нельзя прочитать из базы напрямую.

### 9.8 ДВЕ машины на одном эпизоде · чем держится Timeline · как НЕ соврать себе запросом (08.08)

**Кнопки в кебабах Timeline — это СТАРЫЙ агентский конвейер, не Полина.** На одном эпизоде
живут две независимые машины: (1) единый ум — только в чат-панели через `/api/mind/chat`,
инструменты зовёт сам; (2) штатные маленькие агенты — запускаются кнопками UI через Inngest
(`EXEC-VANIM` план шота → `EXEC-VPREV` критик, `EXEC-EREF-DESIGNER` план рефа → `EXEC-EPREV`
критик). «Требуется ревизия» на карточке = критик вернул замечания и поставил
`SPC-shot_plan` в `REVISION` — цикл автор↔критик, тот самый, который парадигма и заменяет.
Кнопки к уму НЕ подключены: нажатие в UI не делает ход в треде Полины, и наоборот. Считать
случайное нажатие бесплатным нельзя — шесть таких job'ов стоили $0,50 на Sonnet.

**Timeline держится JSON-контрактом внутри сториборда, а не статусом APPROVED.**
`activeContract` (`EpisodeTimelineSection.tsx`) строит скелет через
`extractShotsFromStoryboard()` — та ищет fenced ` ```json ` блок
`{"acts":[{"shots":[{"shot_id",...}]}]}` (контракт `storyboarder@v2`). Проза без блока =
`[]` = «сториборд ещё не approved» на экране при APPROVED в базе. Гейт
`assertStoryboardApprovable()` (D76) теперь отказывает на самом переходе в APPROVED/LOCKED —
в `persistAsset` (обе ветки) и `set-status`, то есть на всех путях записи, включая
`write-asset`, которым пишет ум. Гейт защищает НОВЫЕ переходы; уже лежащую сломанную строку
он не чинит — её переписывают явно.

**`shot_id` сверяют с землёй, а не сочиняют.** Формат даёт `shotIdFor()` в `_asset.ts`:
`S20-E03-SH01` (код эпизода без `SS-`, шот в верхнем регистре). Перед тем как писать список
кадров, посмотреть, какой `metadata.shot_reference.shot_id` уже стоит на существующих
`IMG-episode_ref` — расхождение формата означает, что кадры и рефы никогда не срастутся
(тот же класс разрыва, что D72/D75, только слоем выше).

**Запрос с несуществующей колонкой возвращает НОЛЬ СТРОК, а не ошибку в глаза.**
`supabase-js` кладёт отказ в поле `error`, а `data` остаётся пустым — скрипт, который не
печатает `error`, показывает «$0 потрачено» / «записей нет» и выглядит как факт. Так уже
дважды рождалась ложная тревога за одну сессию. Печатать `error` ВСЕГДА, и сверять имена
колонок первым запросом (`select('*') limit 1` + `Object.keys`), а не по памяти. Реальные
имена, на которых спотыкались: `episodes.title_working` (не `title`), `budget_log.cost_usd`
+ `operation` + `model_or_tier` (нет `description`, нет `amount_usd`), `jobs` без
`updated_at`.

**Разовый диагностический скрипт кладут в `webapp/`, а не в `/tmp`** — иначе относительный
импорт `./scripts/run/_env` не резолвится. Импортировать `{ sb }` из `./scripts/run/_env`
(не `lib/supabase/admin`), удалять сразу после использования.

### 9.9 ХОД УМУ БЕЗ ЭКРАНА — `mind-post.ts` (построен 08.08, D77/D78)

```bash
cd webapp
npx tsx scripts/mind-post.ts --episode <uuid> --file msg.md --dry-run   # сначала ВСЕГДА
npx tsx scripts/mind-post.ts --episode <uuid> --file msg.md             # живой ход
```

- **`--episode` обязателен.** Без него роут падает в глобальный фолбэк
  `resolveOpenThreadId(null,null)` и берёт ЛЮБОЙ последний открытый тред студии, а затем
  строит по нему и промпт, и `RUN_EPISODE_ID`/`RUN_SERIES_ID`. Ум живёт в КАЖДОМ эпизоде, и
  эпизоды идут ПАРАЛЛЕЛЬНО (Директор, 08.08) — при такой работе фолбэк уводит в чужой ум
  почти наверняка. Скрипт отказывает сам, не полагаясь на сервер.
- **Память собирает КЛИЕНТ, не сервер.** Роут не грузит ходы треда из базы — массив
  сообщений целиком приходит из тела запроса; панель держит ленту у себя. Пришлёшь только
  новый ход — ум амнезик. `--history N` (умолчание 20) режет хвост, иначе контекст растёт
  бесконечно. Подряд идущие одинаковые ходы отбрасываются: это след сбойной браузерной
  отправки, а не нажим Директора.
- **`Authorization` нужен MIDDLEWARE, не роуту.** Любой `/api/*` с этим заголовком проходит
  без Supabase-куки (`middleware.ts:35-37`). Сам роут Bearer НЕ проверяет вовсе (D78) —
  заголовок обязателен просто чтобы не получить `307` на `/login`.
- **Куку не шлём сознательно.** По её наличию роут решает, разрешена ли публикация
  (`humanSession`); headless-ход обязан оставлять хард-лимит Директора закрытым.
- **Ответ — поток NDJSON**, не JSON: `{t:'tool_start'|'tool_result'|'text'|'error'}`
  построчно, id треда в заголовке `X-Concierge-Thread-Id`. Ход законно идёт МИНУТАМИ
  (`maxDuration=600`, до 32 раундов) — это не зависание.
- **Приёмка — по базе, не по потоку.** Роут пишет ровно ДВЕ строки на обмен: `director`
  ДО цикла и `assistant` ПОСЛЕ него (при ошибке — `system` с `metadata.error`). Строка
  появляется ВСЕГДА, даже при упоре в потолок раундов. Скрипт сам печатает id этой строки —
  если её нет, ход показался, но не записан.
- **Ум в режиме 3 может сам взяться за платные инструменты**, а не просто ответить текстом.
  Живой ход — это не всегда центы; смотри потолок эпизода перед отправкой.

### 9.10 ПАМЯТЬ И ДЕНЬГИ УМА — что где живёт и чему нельзя верить (08.08, D81/D83)

**Память разговора принадлежит КЛИЕНТУ, не серверу.** `/api/mind/chat` строит массив
сообщений целиком из тела запроса и НИЧЕГО не грузит из `concierge_turns` — `persistTurn`
там только бухгалтерия. Отсюда весь класс: панель держит ленту в своём стейте +
`sessionStorage`, а смена эпизода делает `setMessages([])`. Кто шлёт уму ход, тот и обязан
собрать историю (`director→user`, `assistant→assistant`) — `mind-post.ts` это делает, панель
до 08.08 при возврате в эпизод восстанавливала только ambient-пузыри и ум начинал разговор
с нуля, хотя всё лежало в базе.

**Тред панель узнаёт из `localStorage`, а не с сервера** (`sandystudio.mind.threadId.<эпизод>`).
На другом устройстве или после чистки браузера история не поднимется, хотя сервер её знает.
Резолв «тред по эпизоду» с сервера не реализован — при вопросе «а куда делась переписка»
сначала проверяй базу (`concierge_threads` по `episode_id`, `ended_at IS NULL`), а не верь
пустому экрану.

**Модель ума задаётся в UI, а НЕ в `.env`.** Живёт в `app_config`
(`scope=providers`, `key=concierge_provider`, `source=ui_edit`) и главнее переменной
окружения. `CONCIERGE_ANTHROPIC_MODEL` убран из `.env.local` 08.08 как legacy именно потому,
что расхождение двух источников стоило ложной тревоги «модель не та». Хочешь знать, на чём
реально работает ум, — смотри `app_config` или `metadata.model` последних ходов, не env.

**Деньги ума до 08.08 не писались НИКУДА.** Роут не звал `recordConciergeCost` (старый
консьерж звал), поэтому `spend` — который правило 4 промпта велит уму считать единственным
источником остатка — систематически врал в меньшую сторону. Теперь пишется пораундно
(раундов до 32 на ход, каждый оплачен отдельно). Практика: **проверяя расход, смотри
`budget_log` по `episode_id`, а не сумму, названную умом в реплике** — она берётся тем же
`spend` и наследует любые его дыры.

**Таблица цен молча подставляет ставки Sonnet незнакомой модели**
(`lib/providers/anthropic-text.ts`, `rateFor`). Порядок префиксов решает: более специфичный
обязан стоять ПЕРВЫМ. Живой случай — Opus 4.8 стоит $5/$25, а матчился на общий
`claude-opus-4` со ставками прежних поколений $15/$75, то есть счёт завышался втрое. При
смене модели ума СНАЧАЛА проверь, есть ли её префикс в таблице, и только потом верь цифрам.
Тест, списанный с той же неверной константы, ошибку не ловит — он её консервирует.

**Кэш промптов работает и от истории не зависит** — кэшируется стабильная часть системного
промпта (`systemSplit`, native-путь). Проверять живьём, не рассуждением: `cache_read_input_tokens`
/ `cache_creation_input_tokens` в `metadata` ассистентских строк. Здоровое соотношение —
чтения на порядок больше записей.

### 9.11 ЧЕМ СТАНЦИЯ ДЕРЖИТСЯ, а что рядом лежит и инструментом НЕ является (08.08)

**`show-asset` не отдаёт uuid, а `set-status` не принимает ничего кроме uuid.** Два
инструмента НЕ СТЫКУЮТСЯ: `show-asset` выбирает `id` из базы (`FIELDS`, строка 27) и не
печатает его (шапка — `filename · status · file_type · created_at`), а `set-status` требует
`--id <uuid>`. Свои свежие изделия ум видит по id из вывода `write-asset`; всё созданное
ходами раньше недостижимо. Практика до починки: снять статус со СТАРОГО ассета прямым
вызовом нельзя — id берётся запросом к базе.

**Кастинг: контракт живёт в РОУТЕ, а не в документе.** Штатное место — ассет
`SPC-episode_cast`, роут `POST /api/episodes/[id]/cast`, рождается в **REVIEW** (DRAFT
невидим очереди приёмки — `assets_in_review` считает только REVIEW/REVISION/
NEEDS_HUMAN_TWEAK). Машина читает ТОЛЬКО `metadata.cast` (массив слагов) или fenced
` ```json {"cast":[…]} ` в теле — `parseCastSlugs` (`lib/agents/episode-cast.ts`).
Markdown-таблица красива и машиной не видна вовсе; без распознанного каста загрузчик молча
откатывается на ВЕСЬ канон серии, и эпизод идёт нескоупленным, выглядя укомплектованным.
Преflight требует канон в статусе **LOCKED** — APPROVED/DRAFT не проходят.

**Инструмент несёт не только действие, но и КОНТРАКТ изделия.** `castEpisode` срезан
кил-листом Ф4 как «диспетчерский», но диспетчером он не был — он держал форму каста.
Убрали инструмент → форма исчезла, взамен остался `write-asset`, принимающий любой текст.
Правило на будущее: срезая инструмент, назови ЯВНО, кто теперь держит контракт — гейт,
скилл или другой инструмент. Иначе ум честно импровизирует, и выходит документ, понятный
только ему.

**Канон читают ДО конца, включая разделы после таблиц.** Плита
`SBL-character_bathyscaphe_turnaround` в §3 «Light signature — AVIATION CONVENTION»
фиксирует навигационные огни (два зелёных справа / два красных слева, красный слева +
зелёный справа на корме, twin floodlight спереди) и объясняет зачем — читаемость при кропе
9:16 и опознание аппарата в кувырке. Полина доложила «огней в каноне НЕТ» и дописывала их
в промпты вручную; ошибка дошла до Директора как факт. Там же §5 — известный дефект листа
v01: на видах REAR и BOTTOM огни ЗЕРКАЛЬНЫ, и записано правило «сторона берётся из таблицы
§3, никогда из картинки». Лист намеренно не перегенерируют — повтор через text-to-image даёт
ДРУГОЙ аппарат.

**У интерьерной и внешней плиты разный предмет.** `SBL-location_bathyscaphe_interior` —
интерьер, навигационных огней там нет и быть не должно. Ищешь внешнюю сигнатуру — плита
`character_bathyscaphe_turnaround`, не интерьер.

**СТАНЦИЯ ВИДЕО ДЕРЖИТСЯ ФАЙЛОМ НА ДИСКЕ, а кадр в базе — это НЕ файл (D94, 09.08).**
`gen-video --frame <path>` читает PNG с диска и падает `frame not found`, если пути нет.
`gen-frame` пишет кадр во ВРЕМЕННУЮ папку (`%TEMP%\ss-mind-*\out.png`) и регистрирует его в
студии — после чего временный файл подчищает ОС, а байты живут в медиа-кэше:
`C:\SandyStudio\FILMS\_media_cache\S<серия>\E<эпизод>\media\<filename>` (`localCacheAbsPath`,
`lib/media-cache`). Этот путь НЕ печатает ни один инструмент: `show-asset` даёт id, имя и
статус, `staging_path`/`drive_file_id` у прямого пути пустые.

Мост между дверьми существует, но не назван: **`show-asset --id <uuid> --out <путь>` кладёт
копию картинки куда скажешь и печатает абсолютный путь** — этим путём и кормится
`gen-video --frame`. То есть связка «взять кадр из базы → отдать в видео» — ДВА вызова, и
второй знает про первый только по договорённости.

Порядок, пока не починено:
1. `show-asset --type IMG-shot_sh04 --out out/SS-S20-E05/sh04.png` → печатает `картинка: <abs>`;
2. `gen-video --frame <abs> --prompt-file … --out out/SS-S20-E05/sh04.mp4 --shot sh04`.

Симптом разрыва в живом прогоне: ум берёт путь из ВЫВОДА `gen-frame` (он там был, но
временный), получает `frame not found` и начинает угадывать пути. Угадывание — признак
того, что двери не стыкуются, а не того, что ум глуп. Правка по существу — `gen-video`
должен принимать `--frame-asset <id>` и доставать байты сам; пока не сделано, держи порядок
выше и НЕ угадывай.

### 10.1 Разговор — только headless, экран запрещён

```bash
cd webapp
npx tsx scripts/mind-post.ts --episode <uuid> --file msg.md --dry-run   # ВСЕГДА сначала
npx tsx scripts/mind-post.ts --episode <uuid> --file msg.md             # живой ход
```

- `--dry-run` бесплатен и ловит три класса ошибок ДО траты: выдуманный uuid эпизода,
  отсутствующий тред, пустая память. Пропускать его нечем оправдать.
- **`--episode` обязателен.** Без него роут берёт последний открытый тред СТУДИИ — при
  параллельных эпизодах это чужой ум. Скрипт отказывает сам.
- uuid эпизода **берётся запросом**, не из головы: `episodes` по `episode_code`. Однажды
  подставил по памяти — скрипт честно отказал, но минута ушла.
- Ход ума идёт МИНУТАМИ (до 32 раундов). Это не зависание.

### 10.2 Закрытый тред = ум приходит без памяти

Тред эпизода может оказаться `ended_at != null` (закрывается панелью/скриптом; чем именно —
не выяснено). Тогда `mind-post` честно скажет «тред не найден», роут заведёт НОВЫЙ, и ум
придёт с ПУСТОЙ памятью — на вопрос «видишь ли свои прошлые ошибки» ответит неверно не по
своей вине. Лечится открытием обратно (`ended_at = null`), если разговор не окончен.
Способа адресовать закрытый тред у `mind-post` нет.

### 10.3 Приёмка — ЗЕМЛЯ, а не доклад ума

Доклад ума — гипотеза, даже честный и подробный. Порядок обратный привычному: сперва
запрос к базе, потом чтение реплики.

- Что реально лежит: `assets` по `episode_id` — `file_type`, `status`, `version`, время.
- Ход записан? — строка `assistant` в `concierge_turns` с `metadata.surface='mind-chat'`;
  `mind-post` печатает её id сам. Нет строки — ход показался, но не случился.
- Деньги — `budget_log` по `episode_id`. `episodes.budget_spent` прямой путь НЕ обновляет,
  ему верить нельзя.
- **Живой случай:** ум дал честный разбор своих ошибок и умолчал, что каст и сценарий висят
  в DRAFT непредъявленными. Один запрос дал полную картину за секунды.

### 10.4 Статус — это и есть предъявление

`DRAFT` невидим очереди приёмки (`assets_in_review` считает REVIEW/REVISION/
NEEDS_HUMAN_TWEAK). Изделие в DRAFT для Директора НЕ СУЩЕСТВУЕТ, кнопки у него нет.
Поэтому «сделано, лежит в DRAFT» = не сделано. Проверять статус, а не факт наличия строки.

### 10.5 Не подсказывать — это метод, а не вежливость

Каждая подсказка в чате СТИРАЕТ УЛИКУ: дыра, которую я заткнул словом, не будет найдена
механизмом. Мера прогона — **пройденные станции без вмешательства**, не количество ходов.
Если ум встал — это находка, а не повод помочь.

Отвечать за ум на вопросы Директора тоже нельзя: вопрос «видит ли она свои ошибки» имеет
смысл, только если отвечает она.

### 10.6 Эпизод, испорченный моими руками, для измерения НЕ ГОДИТСЯ

Если я вручную чинил артефакты эпизода (переписывал `shot_id`, переводил статусы, правил
каст), результат покажет мою работу, а не её. Такой эпизод закрывается, измерение —
на чистом. Стоимость брошенного эпизода обычно копеечная ($4 на E04) и всегда дешевле
ложного вывода о том, что ум справился.

### 10.7 Что обязано быть до первой траты

Гейт `assertEpisodeReadyToSpend` (`_asset.ts`, зовут `gen-frame`/`gen-video` ПЕРВЫМ
действием) требует: `metadata.budget_approved === true`, заданный `budget_ceiling`,
непустой `metadata.generation_config`. Ставит их ДИРЕКТОР в Episode Settings — обойти
нечем, и это правильно: до 09.08 правило держалось только его вниманием, а прямой путь
тратил бы молча.

### 9.12 Ф1 миграции СМЕНИЛА КОНТРАКТЫ медиа-инструментов (09.08 вечер)

**Версию больше НЕ называют — она вычисляется.** `register-media` потерял `--version`;

а не самоутверждают. Утверждение — `set-status --status APPROVED`, и демоушен прежнего

Если изделие не появилось в ленте мгновенно — это снова дефект, а не норма.

- **Сказать слово headless:** `npx tsx scripts/mind-say.ts --episode <uuid> "текст"`
  (из webapp/). `--cancel` — оборвать ход. Ответ печатается с cost/session.

- **Карта сессий:** `episodes.metadata.mind_session` (session_id, busy). Замок busy
  переживает мост; осиротевшие снимает старт моста.
- **Будят её и СОБЫТИЯ** (аппрув, настройки, agent_failed…) — см. WAKE_EVENT_TYPES в
  мосте; события при мёртвом мосте пропадают (v1).
- **Гейты — хуки клона** (`.claude/polina-settings.json`, АБСОЛЮТНЫЕ пути): рапорт без
  инструмента — Stop-block, контекст хода — UserPromptSubmit. **PreToolUse снят 14.08**:
  деньги и потолок держит `assertEpisodeReadyToSpend` — код инструмента, одинаковый для обеих

### 9.14 ИДЁТ ХОД ИЛИ ВСТАЛО — замок, а не лог (10.08, оплачено убитым ходом)

Единственная правда о том, работает ли ум прямо сейчас, — **замок
`episodes.metadata.mind_session.busy`** (`{pid, turn_ids, started_at}`), который мост
ставит на время хода и снимает по завершении. Он же переживает перезагрузку страницы и
одинаково честен для хода, начатого ИЗ ПАНЕЛИ и разбуженного КНОПКОЙ.

**Инструментом НЕ является:**
- **`bridge.log`** — строки `ход →` / `ход ←` идут парами, но пара соседних `←`/`→` в одну
  секунду читается как «закрылось» ровно тогда, когда на самом деле «закрылось и сразу
  началось следующее». Я прочёл так, решил, что окно свободно, и снёс стек пересборкой —
  ход Полины умер на третьей минуте, деньги за него сгорели. Лог отвечает на «что было»,
  замок — на «что есть».
- **локальный `streaming` в панели** — гаснет, как только мост ПРИНЯЛ строку; ход после
  этого идёт минуты. Для хода от события не загорается вовсе.

Перед любой пересборкой стека: прочитать замок, а не лог. Занят — ждать; пересборка убивает
дочерний процесс хода, а событие, пришедшее при мёртвом мосте, не переигрывается.

**Чей это запуск, когда деревьев несколько:** `GET http://localhost:<InngestPort>/v1/runs/<run_id>`
с `Authorization: Bearer <INNGEST_SIGNING_KEY>`; `jobs.inngest_run_id` берётся из базы. Чужой
сервер отвечает `Unable to load function run`. Логи двух деревьев неразличимы — они пишут
одинаковые строки в ОДНУ базу; `run_id` различает за один запрос.

**Реконсилер тикает по ДВУМ признакам** (`metadata.reconciler_armed` + `governance_mode ∈
{2,3}`) — статус эпизода в фильтре появился только 10.08. Флаг никто не снимает при
завершении, поэтому готовые эпизоды годами остаются заряженными: S15-E31 (COMPLETE с июля)
получил полный круг EREF на $0.71 за кадр, у которого не было рефа. Проверка одной строкой:
взведённые с терминальным статусом = мины.

**Станция кадров, как её ведёт ум (подтверждено прогоном E06):** промпт кадра пишется в
файл, дальше `run/gen-frame --prompt-file <файл> --refs <slug>:<role>,…` — рефы подаются
ФОРМОЙ `слаг:роль`, не голыми слагами; канон смотрится `run/show-asset --slug <slug> --out
<png>`; состояние — `run/show --what episode`. Пакет кадров = один bash с наборами рефов на
интерьер/экстерьер, а не N ручных запусков.

**Дыра, которую оба ума затыкают одинаково:** чтения произвольного среза базы в
`scripts/run/` НЕТ — за одну сессию Полина написала 32 разовых `*.tmp.ts`, и Тео в тот же
день столько же `_probe-*.ts`. Это не разгильдяйство исполнителя, это отсутствующий
инструмент; пока его нет, разовый скрипт — законный ход, но он ОБЯЗАН сноситься в том же
ходе, иначе попадает в индекс (уже попадал).

### 9.15 ФИНАЛЬНАЯ СБОРКА и залипший шелл ума (10.08, оплачено 40 минутами простоя)

**Станция финальной вёрстки — РУЧНАЯ, и это не временно.** `run/stitch` умеет только
встык: ни музыки, ни оверлея, ни переходов. Поэтому кат с кроссфейдами собирается сырым
`ffmpeg` — и ровно там ум напарывается на мину, описанную ниже. Пока инструмента нет,
скрипт сборки пишется файлом и запускается одной командой:

```bash
bash out/<EPISODE>/build.sh     # внутри: xfade по списку + пересвод музыки + fade
ffprobe -v error -show_entries format=duration -of csv=p=0 <итог>.mp4   # приёмка = секунды
```

Смещения xfade считаются так, чтобы N-1 переходов съели ровно (N-1)×длительность перехода:
восемь сегментов и переход 0.5с укорачивают кат на 3.5с — 48.5с превращаются в ровно 45.

**МИНА: Bash-инструмент держит ОДИН шелл на всю сессию.** Длинная inline-команда с
незакрытой одинарной кавычкой (типичный случай — `ffmpeg -filter_complex '...'`) переводит
шелл в ожидание закрывающей кавычки. Дальше **всё** уходит внутрь незавершённой строки:
падают даже `echo` и `pwd`, ошибка всегда одна — `unexpected EOF while looking for
matching '` на строке eval-обёртки.

- **Новый ход НЕ лечит.** Проверено живьём 10.08 на четырёх ходах подряд: процесс каждый
  раз новый, но `--resume` восстанавливает состояние инструмента вместе с сессией.
  (Моя гипотеза «новый ход = новый шелл» опровергнута рантаймом — записываю как ошибку.)
- **Попытка «закрыть кавычку» вручную ДЕЛАЕТ ХУЖЕ:** отправленная в шелл одиночная `'`
  сама становится новой незакрытой кавычкой. В журнале Полины ровно две команды с нечётным
  числом кавычек — та, что сломала, и та, которой она лечила.
- **Единственное лечение — НОВАЯ сессия:** убрать `session_id` из
  `episodes.metadata.mind_session`, тогда мост стартует `claude` без `--resume`. Кнопки в
  UI нет (дефект). Сохранять уму нечего: изделия в базе, роль подаётся заново, состояние
  эпизода приходит служебной строкой каждый ход — теряется только память разговора.

**Профилактика (правило, а не привычка):** сырой `ffmpeg` — ТОЛЬКО через файл
(`-filter_complex_script xfade.txt`, `cat > build.sh` и запуск), никогда длинной строкой с
кавычками. Ум приходит к этому сам со второй попытки — но правило должно быть записано,
чтобы каждый следующий не выводил его заново ценой простоя.

### 9.16 НАСТРОЙКИ ЭПИЗОДА — кто ими правда управляет (11.08)

Настройки живут в `episodes.metadata.generation_config` (`video`: provider/aspect/resolution/
quality_tier · `image`: provider/quality) плюс режимы и потолки рядом. Ставит их Директор в UI,
меняет молча, событие `episode_settings_changed` будит ум — но **разбудить не значит сообщить**.

**Инструмент обязан читать настройки САМ, теми же функциями, что конвейер.** Эталон —
`gen-frame.ts` (`readEpisodeImageConfig` + `resolveImageParams`); видео-близнецы —
`readEpisodeVideoConfig` (`lib/agents/runner.ts`) + `resolveVideoParams`
(`lib/api/resolve-generation-params.ts`). Порядок: **явный аргумент → настройка эпизода →
умолчание инструмента**, и источник печатается вслух. Различить «аргумент назвали» и «взяли
по умолчанию» умеет только `wasGiven()` из `_tool.ts` — без него настройка не может победить
дефолт, потому что они выглядят одинаково.

**Чем это было оплачено:** `gen-video` зашивал `9:16` и `720p` строками (и дублировал их в
леджер и в `recipe`), поэтому `generation_config.video` не управлял прямым путём НИЧЕМ. Ум
работал «как в прошлый раз», Директор менял настройки в UI и не понимал, почему ничего не
меняется. Своя копия резолвера — тот же дефект в профиль: два пути разойдутся в трактовке
одной настройки.

**Где смотреть за секунды:**

```bash
RUN_EPISODE_ID=<uuid> npx tsx scripts/gate-check.ts --kind context   # строка, которую ум видит КАЖДЫЙ ход
RUN_EPISODE_ID=<uuid> npx tsx scripts/run/show.ts --what episode      # значения настроек, не «есть/НЕТ»
```

Обе поверхности печатают ЗНАЧЕНИЯ. «настройки=есть» не отвечает на единственный вопрос, ради
которого их открывают: **чем именно я сейчас генерирую**.

### 9.18 СТАНЦИЯ ФИНАЛЬНОЙ СБОРКИ — монтажный лист, а не папка с файлами (11.08)

`run/stitch` без аргументов собирает кат **из аниматика**: порядок кадров, обрезки Директора
(`director_overrides`: `duration_seconds`, `trim_start_seconds`) и удалённые кадры приходят
монтажным листом — `buildStitchEdl` (`lib/api/stitch-edl.ts`), общий с агентским сборщиком.

```bash
RUN_EPISODE_ID=<uuid> npx tsx scripts/run/stitch.ts --out <файл>.mp4        # штатно
RUN_EPISODE_ID=<uuid> npx tsx scripts/run/stitch.ts --dir <папка> --order 01,02,…   # АВАРИЙНО
```

- **Штатный режим отказывается** собирать, если у кадра из листа нет APPROVED-клипа — и это
  правильное поведение: раньше он молча склеивал что было.
- **`--dir/--order` — аварийный ручной режим**, и он ГРОМКО предупреждает, что обрезки НЕ
  применяются. Причина не в лени: файлы в такой папке **уже нарезаны**, а лист считает от
  исходника — наложение даёт двойную обрезку (живьём: кадр 07 попросил 11с при файле 9.5с).
- **Обрезки живут в `VID-animatic.metadata.animatic_v1`**, пишет их роут
  `api/assets/[id]/animatic-timing`. `EpisodeTimelineSection` их НЕ правит — там только
  исключение кадров (`episodes.metadata.excluded_shot_ids`).
- Арифметику не изобретать: `computeEffectivePlayback` / `clipLengthsFromVidShotRows` /
  `isDeletedShot` в `lib/api/animatic-shotlist.ts` — SSOT, тот же, что у таймлайна в UI.
- Имена не совпадают по построению: нарезка зовётся `01.mp4`, кадр — `S20-E06-SH01`.
  Нормализация ключа обязательна, иначе обрезки МОЛЧА не находятся.

**Чем оплачено:** сборщиков было два, и прямой в базу не ходил вовсе — правки Директора в кат
не попадали, разница копилась и вылезла на седьмом кадре E06.

### 9.20 СТАНЦИЯ ВЫПУСКА — чем ставится эфир, и что НА КАНАЛЕ ДЕЛАТЬ НЕЛЬЗЯ (12.08)

Последняя станция маршрута была не описана вообще, и потому нарушена с первого же раза.

**Планирование имеет РОВНО ОДНУ форму:** `privacyStatus: 'private'` + `publishAt` (ISO).
Запланированного `unlisted` не существует — unlisted сам в public не переходит НИКОГДА.
Если в практике звучит «unlisted → scheduled», то unlisted там был стадией ПРОСМОТРА, а
выпуском всё равно был private→public по времени. Поле `publishAt` живёт в
`UploadVideoInput` (`lib/providers/youtube.ts`) и бросает, если статус не `private`: тихо
опубликовать сейчас вместо запланировать — худший класс отказа.

**Заливать — только с идентити-гардом.** `resolveChannelRefreshToken(KEY)` → `getMyChannel`

**Прибор канала — `webapp/scripts/hog-snapshot.mts`** (снимок, только квота API, $0) внутри

поверх существующей — четыре утра платный «мозг» отрабатывал дважды. Обе проверки были слепы

назови, что именно твой инструмент физически способен увидеть.** Для задач — `Get-ScheduledTask`

**Рука Полины на этой станции связана:** `.claude/hooks/polina-pretool.cjs:26` режет `publish.ts`

### 9.22 ЧЕМ РАБОТАЕТ УМ — два подписочных harness-пути (24.08)

выбор одним из двух runner-ов: `claude -p` или `codex exec --json`.
Оба пути идут по подписке: мост вычищает `ANTHROPIC_API_KEY`,
`OPENAI_API_KEY` и `CODEX_API_KEY` из окружения хода.

```bash
claude -p --model sonnet --output-format json 'ok'   # → modelUsage: contextWindow, canonicalModel
```

### 9.23 ПУЛЬТ В ТЕЛЕГРАМЕ — второй вход к Полине и второе окно в студию (12.08)

**Чем поднимается.** Сам стек: `start-stack-nx.cmd` запускает `scripts/telegram-bot.ts`
рядом с мостом, если в `.env.local` есть `TELEGRAM_BOT_TOKEN`; лог — `webapp/telegram.log`.
Гасится вместе с деревом. **Второй бот на одном токене недопустим:** `getUpdates` отдаёт
сообщение то одному процессу, то другому, и половина ходов пропадает — поэтому лаунчер
убивает старого перед стартом, а руками поднимать второй нельзя.

**Чем держится (три вещи, все в `.env.local`):**
- `TELEGRAM_BOT_TOKEN` — токен от @BotFather. Пуст → бот не поднимается вовсе (не тихо).
- `TELEGRAM_ALLOWED_CHAT_IDS` — белый список, **отказ по умолчанию**. Пуст → бот отвечает
  только «твой chat_id: X» и хода не даёт: бот с публичным именем находится поиском.
- Состояние — `FILMS/_run/telegram-bot-state.json`: offset обновлений, метки
  доставленного и `followKey` для сигнала перехода. Своего выбранного эпизода
  у пульта нет: он идёт за последним словом Директора.

**Что он делает и чем именно:**

| Направление | Чем | Что важно |
|---|---|---|
| текст Директора → Полина | `persistTurn` в тот же тред, что `mind-say.ts` | бот про мост не знает: он пишет строку, мост подхватывает по `metadata.for_bridge` |
| ответ Полины → телефон | опрос `concierge_turns` каждые 3 с | кнопки строятся из **формата нумерованных вопросов**: `callback_data` = код `031`, который Директор набрал бы руками |
| модель Полины ↔ пульт | `/model` и `/model terra` | тот же `app_config providers/concierge_provider`, что Studio Settings; кнопка меняет следующий ход, текущий не убивает |
| изделия → телефон | опрос `assets` + `ensureCachedMedia` | кадр/клип/музыка приходят сами, как только станция их предъявила; документы не шлются — их читают в webapp |
| медиа Директора → студия | `FILMS/_run/inbox` + тот же тред | пульт не сортирует файл: Директор объясняет словами, а Полина сама выбирает штатное перо, имя, слот и статус |

**Адресат обязателен (Директор, 24.08).** Одна и та же реплика видна
в webapp и Telegram; в webapp на неё может ответить Полина, в Telegram —
Директор. Любое поручение начинается с `Директор —` или `Полина —`.
Без явного адресата поручение не отправляется.

**Что рядом лежит и пультом НЕ является.** **Claude Code на смартфоне.** Приложение
поднимает сессию в облачной песочнице с клоном из GitHub — до моста, до стека `:3001` и до
рабочего дерева ей хода нет. Это второй ум в облаке, а не окно к домашней Полине; ход через
него стоит минуты и подписочные деньги, а уведомление приходит «задача завершена», а не
репликой. Туннель наружу Директор отверг 12.08 — студия не торчит в интернет, связь
пульта **исходящая** (long polling).

**Приветствие при старте — не украшение.** Бот пишет «Пульт на связи · <эпизод>» первому в
белом списке: молчащий пульт неотличим от упавшего, а рестарт стека иначе невидим с телефона.

### 9.24 ПЛИТА КАНОНА — чем пишется целиком, и почему её нельзя было залочить (12.08)

**Одним вызовом — и лист, и текст.** У `register-canon` появился `--text <файл.md>`: тело
плиты (то, что приёмщик читает как канон) и картинка едут вместе. До 12.08 пера для ТЕКСТА
не было вовсе — его писали мимо инвентаря, прямым вызовом роута `POST /api/series/{id}/bible`,
и лист с текстом расходились по разным версиям. `--desc` — это КОРОТКОЕ описание строки,
не канон; путать их дорого (10.08 `--desc` затёр текст плиты целиком).

```bash
cd webapp
RUN_SERIES_ID=<uuid> npx tsx scripts/run/register-canon.ts \
  --slug character_<name> --file <лист.png> --text <тело.md> --version v03 --status REVIEW
```

**Замок работает и правку не теряет.** Касание LOCKED-строки (байты, текст, статус) уходит
в НОВУЮ версию `max+1` со статусом REVIEW, текст наследуется, залоченная строка цела.
Инструмент печатает это предупреждением — читай его, а не догадывайся.

**БЕЗ РЕЗЕРВНОЙ КОПИИ НА DRIVE ПЛИТУ НЕ ЗАЛОЧИТЬ.** Гейт финализации отказывает:
*«media lives only in the local cache and would be lost on the next cache clear»*. До 12.08
`persistAsset` клал байты голым копированием в кэш и на Drive не грузил НИКОГДА — значит ни
одну плиту, заведённую этим инструментом, залочить было нельзя, и узнавал об этом Директор
на кнопке. Теперь обе дороги (канон и материалы эпизода) идут через `persistBinary`, а
провал загрузки печатается громко. Проверка одной строкой: `drive_file_id` у строки не пуст.

**Правка ПИКСЕЛЯМИ, а не перегенерацией.** Лист канона перегенерировать нельзя — повтор
через провайдер даёт другой аппарат. Точечная правка: `sharp` → raw RGB → перестановка
каналов в окне вокруг дефекта. Порог отделять по ОТНОСИТЕЛЬНОЙ насыщенности (`min/max`), а не
по абсолютной разнице: абсолютный красит корпус (он не строго серый) либо оставляет
цветное кольцо гало. Окно — вокруг точки с запасом на гало, не «вся ячейка» (заденет
тёплые участки корпуса).

**Что рядом лежит и инструментом приёмки НЕ является — ИНБОКС ДИРЕКТОРА.** На 12.08 он
показывает 25 строк REVIEW, отсортированных СТАРЫЕ ПЕРВЫМИ, при 2364 непросмотренных: окно
стоит на 20 июня, за окном 2339 изделий, включая всё сегодняшнее. Свежая плита туда не
попадает. Пока это не исправлено, предъявлять изделие Директору нужно строкой (id + имя +
статус) или картинкой в пульт, а не словами «положил в инбокс».

### 9.25 ТРИ ЗАКОНА ПИСЬМА, которые инструменты теперь держат сами (13.08)

**Замок Директора выше инварианта слота.** У канона серии слот занимает статус LOCKED,
поэтому утверждение новой плиты РАНЬШЕ вытесняло залоченную в INVALIDATED — молча, строкой
в общем выводе. Теперь `demoteSiblingApproved` (общий чокпоинт `set-status` и `persistAsset`)
**отказывает и называет строку**. Снятие — только осознанное:

```bash
npx tsx scripts/run/set-status.ts --id <uuid> --status approved --unlock yes --reason "<почему>"
```

Флаг печатает снятие ОТДЕЛЬНЫМ решением с основанием. Без флага — отказ; это не помеха, а
единственное место, где хард-лимит Директора виден до того, как замок слетел.

**Названная версия — приказ завести СОСЕДА, а не переименовать.** `write-asset --version v02`
поверх живого `v01-DRAFT` раньше возвращал тот же uuid: строка переименовывалась, v01 исчезал
вместе с возможностью сравнить автора с критиком. Теперь названная версия всегда рождает
новую строку; **без** `--version` черновик по-прежнему итерируется на месте. Правило одно:
назвал версию — просишь историю.

**`duration_seconds` в правках аниматика — ПОТОЛОК, а не точная длина.** Фактическая длина
куска = `min(duration, клип − trim_start)`, и считает её ОДНА функция —
`computeEffectivePlayback` (`lib/api/animatic-shotlist.ts`), общая для ката, плеера и
агентского пути. Ум дважды (E06 и E07) прочёл поле как точную длину, увидел вылет за конец
клипа, счёл противоречием и «починил» сдвигом `trim_start` — в кат попала середина кадра
вместо конца. **Арифметику не пересчитывать и не «чинить» противоречие: его нет.** Если
`trim_start + duration` вылезает за конец клипа — так и задумано, хвост обрежется краем.

**Кнопка панели исполняет только СВЕЖИЙ и машиночитаемый план.** `assertPlanIsFreshAndExecutable`
(`lib/api/plan-regen-guard.ts`) отказывает, если у шота есть версия новее переданной, и
отдельно — если план написан прозой без JSON-контракта: такой план исполняет УМ через
`gen-frame`, а не конвейерный агент. До 12.08 кнопка запускала исполнителя по произвольной
версии — на E07/SH05 это была отменённая v01.

### 9.26 ЭФИР: ЧЕГО НЕЛЬЗЯ ЗАПЛАНИРОВАТЬ и чем узнаётся прошлое ролика (13.08)

Дополняет §9.20. Три факта об инструментах выпуска, каждый оплачен отказом или ложным
срабатыванием.

**`publishAt` не работает для ролика, который УЖЕ БЫЛ ПУБЛИЧНЫМ.** Ответ —
`400 invalidPublishAt`, и он приходит одинаково на +45 минут и на +8 дней, то есть дело не
во времени и не в формате. Ролик, снятый в private из public, запланировать нельзя вообще —
его можно только опубликовать прямым переводом статуса. Проверять это надо ДО того, как
обещать Директору расписание: «в столе лежит N готовых роликов» и «N дней эфира» — разные
утверждения, и второе может оказаться ложью.

**`videos.update?part=status` ЗАМЕЩАЕТ весь объект статуса, а не патчит его.** Отправив
только `privacyStatus` + `publishAt`, молча теряешь `selfDeclaredMadeForKids`, `license`,
`embeddable`, `publicStatsViewable`. Порядок обязателен: прочитать текущий `status` → слить →
отправить. Тот же класс, что «число из агрегата» (§9.19): частичная запись туда, где API
ждёт целое.

**Прошлое ролика знает только НАШ снимок, не YouTube.** Data API отдаёт текущий статус и
`publishedAt` (момент ЗАЛИВКИ, он есть и у private) — но никогда не отвечает «был ли этот
ролик публичным вчера». Единственный источник — ряд `docs/distribution/snapshots/*.json`,
где у каждой строки есть `state` (`public` / `scheduled` / `private-draft`) на дату снимка.
Именно он показал, что 06.08 в 09:39 четыре ролика ушли из эфира одним действием, и что до
снятия они висели публичными по трое суток с 0–3 просмотрами. **Прибор, который никто не
читал пять суток, оказался единственным свидетелем.** Отсюда практическое: снимок стоит
квоты и нуля денег — снимать чаще, чем кажется нужным, потому что состояние восстановлению
не подлежит.

**Детектор дублей — превью + 8×8 хеш, и он ВРЁТ на вертикали.** Материал сверяется по
авто-миниатюре (`snippet.thumbnails`), сведённой в 8×8 серых через
`ffmpeg -vf scale=8:8,format=gray -f rawvideo -`, дальше расстояние Хэмминга. Точный дубль
даёт d=0 — метод рабочий. Но вертикальный ролик в миниатюре 16:9 обрамлён чёрными полями,
и они занимают большинство из 64 пикселей: два РАЗНЫХ вертикальных эпизода дают d=4 и
читаются как дубль. **Хеш даёт кандидатов, вердикт даёт глаз** — пары склеиваются в одну
картинку через `hstack` и просматриваются. Либо кропать центр до хеширования.

### 9.27 УДАЛЕНИЕ ЗАПИСИ — чем держится и чего в `run/` НЕТ (20.08)

**Инструмент один:** `DELETE /api/assets/[id]` — его дёргает «Delete» в меню карточки
(`AssetCard.tsx`). Физическое удаление строки; файл на Drive остаётся сиротой (30 дней в
корзине). В `scripts/run/` ножа нет — `set-status` двигает статус, но не стирает; из
headless удаление = тот же роут через `curl` с кукой Директора, либо строка в базе руками.

**Закон — ЧЁРНЫЙ список:** защищены только `APPROVED` и `LOCKED`. Всё остальное — `DRAFT /
REVIEW / REVISION / REJECTED / INVALIDATED / NEEDS_HUMAN_TWEAK / TEST` — стирается. До 20.08
роут держал БЕЛЫЙ список из четырёх и отстал от enum: карточка предлагала Delete, сервер
отвечал «Cannot delete asset in status INVALIDATED». Класс: два списка одного закона в двух
местах (UI чёрный, API белый) — теперь оба чёрные, константа `PROTECTED_STATUSES` в роуте.

**LOCKED-канон** ножом не берётся и не должен: «soft-archive cleanup script» из текста отказа
— это `scripts/cleanup-s14-style-canon.ts`, одноразовый, под конкретную серию (05.12). Общего
инструмента снятия LOCKED-плиты нет; путь — `set-status` в `INVALIDATED` через демоушен

### 9.28 ПУЛЬТ ИДЁТ ЗА СЛОВОМ ДИРЕКТОРА — у телеграма нет своего эпизода (21.08)

### 9.29 СТАНЦИЯ РЕЧИ — чем говорит клон человека, и что инструментом ещё НЕ является (25.08)

**СМОУК ШЁЛ МИМО СТАНЦИЙ 7–8, И ЭТО НЕ МАРШРУТ (25.08).** Ниже описан разовый разведочный
путь «канон-плита → аватар». Он оплачен тремя сутками брака: канон отвечает на вопрос «кто
это», а «что снято» отвечает РЕФЕРЕНС эпизода (`IMG-episode_ref`, станции 7–8 таблицы §1).
Анимируется реф, не канон. Плита, поданная вместо кадра, забирает у нас постановку целиком:
модель воспроизводит её фон и крупность и не слушает промпт о камере (§9.30). Читая эту
секцию, помни: это заметка о СМОУКЕ, маршрут задаёт таблица станций.

**Штатного инструмента НЕТ** — станция разведана смоуком (Ш102–Ш105), провайдеры не
написаны. До постройки путь — одноразовый скрипт поверх fal-очереди (паттерн Ш94/Ш102:
`queue.fal.run/<slug>` сабмит → поллинг → результат; request_id и response_url — НА ДИСК,
шелл живёт 10 минут, а Kling-липсинк жуёт 12).

**Карта моделей (проверено смоуком, не доками):**
| Что | Модель fal | Цена | Урок |
|---|---|---|---|
| Клон голоса | `minimax-tts/voice-clone` | ~$1 разово | возвращает ТОЛЬКО `custom_voice_id`, речи не отдаёт |
| Речь клоном | `minimax/speech-2.8-hd` | $0.10/1К зн | `voice_setting.voice_id` + `language_boost: Russian`; эмоция — `voice_setting.emotion` ПАРАМЕТРОМ, не промптом |
| Губы к звуку | `kling-video/lipsync/audio-to-video` | $0.014/5с | правит ТОЛЬКО губы — остальное манекен; живость обязан нести базовый клип |
| Человек целиком | `kling-video/ai-avatar/v2/standard` | $0.056/с | плита+голос → живое тело/руки/дыхание ОДНОЙ ступенью; губы сводит сама |
| То же, глубже | `bytedance/omnihuman/v1.5` | $0.16/с | руки+тело+камера промптом, якорь идентичности; 25.08 fal отдавал 504 |
| Очки/крупный план | `sync-lipsync/v3` | $8/мин | 25.08 fal отдавал 504 — вердикта нет |

**Три закона входа, оплаченные браком:**
1. **Референс img2vid/аватара — ОДИН кадр, не контактный лист.** Лист turnaround дал
   «сетку канона» в первых кадрах — модель якорится на картинке буквально. Кроп ракурса
   ffmpeg'ом; референс открывается ГЛАЗАМИ (Read) до платного вызова.
2. **Эмоция — в ДВУХ местах:** голос (`emotion` у TTS) + тело («not smiling, indignation»
   в промпте аниматора). Одно без другого = улыбка под гневный текст.
3. **Большие файлы в fal — через сторадж, не data-URI:** `rest.alpha.fal.ai/storage/
   upload/initiate`, JSON-тело `{file_name, content_type}` (в query — 422), затем PUT на
   `upload_url`. `rest.fal.run` не резолвится. Мелкое (<±1МБ суммарно) data-URI ест.

**Рядом лежит и инструментом НЕ является:** HeyGen (Digital Twin, альфа-канал WebM —
кандидат под «обращение к камере», требует аккаунта и consent-видео Директора);
эмо-канон S22 (паспортные кропы в футболке — для ВИДЕО-референса не годятся, годится
turnaround в костюме); `webapp/tmp/emocanon/*` Полины — черновики, не изделия.

### 9.31 СТАНЦИЯ РЕЧИ — воспроизводимый путь и его пределы (25.08, второй заход)

Дополняет §9.29 фактами живого прогона: там была карта моделей, здесь — вызовы.

**Голос клоном, дугой по тактам.** Одна фраза = один вызов TTS с одними параметрами,
поэтому ровный голос — не свойство клона, а отсутствие дуги. Такт синтезируется отдельно
(`voice_setting.speed` / `vol` / `emotion`), паузы между тактами клеятся тишиной и сами
являются частью дуги.

```bash
# 1) такты по одному → beat_*.mp3   (fal-ai/minimax/speech-2.8-hd, ~$0,008 за такт)
#    voice_setting: { voice_id: <клон>, speed, vol, emotion }, language_boost: 'Russian'
# 2) склейка ЧЕРЕЗ ФАЙЛ, не длинной командой (§9.15):
ffmpeg -v error -y -f lavfi -i anullsrc=r=32000:cl=mono -t 0.6 -c:a libmp3lame -q:a 4 pause.mp3
ffmpeg -v error -y -f concat -safe 0 -i list.txt -c:a libmp3lame -q:a 2 -ar 32000 -ac 1 speech.mp3
```

**Эмоция — ПАРАМЕТР, и она шире образца.** Клон, снятый с мягкого голоса, отдаёт `angry`
с настоящим железом в тембре: модель переносит манеру, а эмоцию накладывает поверх. Диапазон
образцом не ограничен — не подбирай образец «под настроение», подбирай параметр.

**Аватар — одна ступень, живая.** `fal-ai/kling-video/ai-avatar/v2/standard`, вход
`{image_url, audio_url, prompt}`, ~3 минуты на 18 с, $0,056/с. Даёт тело, дыхание, моргание,
сводит губы сам. **КАМЕРУ НЕ ДВИГАЕТ** — заказ хода камеры промптом он игнорирует (проверено
замером: фон 1,7 против лица 16,7). Нужен ход камеры — это ДРУГОЙ инструмент, а не другая
формулировка.

**Файлы в fal — через сторадж:** `POST rest.alpha.fal.ai/storage/upload/initiate` с телом
`{file_name, content_type}` → `PUT upload_url` → `file_url` в запрос.

**`request_id` пишется на диск ДО первого поллинга.** Харнесс убивает фоновые задания
(случилось 25.08 на третьей минуте аватара), задание провайдера при этом продолжает
считаться — по сохранённому id результат забирается синхронно. Без файла ход был бы оплачен
и потерян.

**Пера для записи ТРАТЫ в инвентаре нет.** `run/spend` только ЧИТАЕТ `budget_log`. Генерация
вне штатного слоя обязана позвать `recordCost` (`lib/budget`) разовым скриптом:
`{jobId:null, episodeId, agentId:'DIRECT-RUN', apiProvider:'fal_ai', modelOrTier, operation,
costUsd}`. Не позвал — себестоимость эпизода занижена, и `spend` соврёт в меньшую сторону.

### 9.32 «ДВИГАЛОСЬ ЛИ» — глазом НЕ проверяется, только числом (25.08, оплачено ложным докладом)

Полоса из трёх моментов (§8-бис) отвечает на «что происходит», но НЕ на «двигалось ли»:
между двумя стоп-кадрами глаз видит различие и достраивает движение, которого нет. 25.08
я так доложил Директору ход фона, которого не было.

```bash
# 12 кадров по всему клипу
for t in 1.0 2.4 3.8 5.2 6.6 8.0 9.4 10.8 12.2 13.6 15.0 16.4; do
  ffmpeg -v error -y -ss $t -i clip.mp4 -frames:v 1 mo/f_$t.png; done
# затем sharp: extract(область) → greyscale → raw, средний |a-b| между соседними кадрами
```

Сравниваются ДВЕ области: фон (край кадра) и лицо (центр). Итог читается отношением, а не
абсолютом: фон ≫ лицо — камера едет; лицо ≫ фон — камера стоит, движется человек. На клипе
25.08 вышло 1,7 / 4,2 против 16,7 — то есть штатив, а заказано было селфи.

**Правило станции:** где строка приёмки говорит «ходит», «покачивается», «дрожит» — рядом
обязан стоять замер. Иначе строка проверяется впечатлением и пропускает ровно тот дефект,
ради которого написана.

### 9.33 ПРОМПТ — три вопроса ПОСЛЕ написания, и они РЕЖУТ, а не добавляют (Директор, 25.08)

> «Убери всё лишнее из промптов. Не ужесточать формулировки, а выкидывать лишнее — тогда
> побольше самостоятельности и поменьше противоречащих друг другу указаний.»

Написал промпт — пройди по нему ещё раз тремя вопросами:

1. **Как это прочитает модель БУКВАЛЬНО?** Каждое существительное она вправе нарисовать.
   «Рука с телефоном покачивается» — заказ руки с телефоном, а не хода камеры; так в кадр
   25.08 приехал второй телефон, снятый со стороны.
2. **Как это можно понять НЕ так, как мы хотели?** У фразы есть второе прочтение, и модель
   возьмёт то, что чаще встречалось в подписях.
3. **Что изменится, если строку УБРАТЬ?** «Ничего» или «не знаю» — строка лишняя.

**Не называй предмет, которого не должно быть в кадре.** Запрет несёт то же существительное,
что и заказ, и работает через раз; слово «селфи» уже содержит и дистанцию, и руку, и оптику.

**Модель новая, а привычка старая.** Описывать каждое шевеление требовалось поколение назад;
сегодняшний генератор от подробной анкеты глохнет — живой кадр 25.08 дала проза в 1540 байт,
а развёрнутый паспорт в 2400 с пятнадцатью запретами дал мёртвый. **Паспорт кадра — способ
ПРИНЯТЬ решения и проверить их валидаторами до денег, а не способ ИЗЛОЖИТЬ их модели.**

### 9.34 СВЯЗКА «ЖИВОЙ КЛИП + ГУБЫ» — чем снимается говорящий человек В ДВИЖЕНИИ (25.08)

§9.29 давал аватар одной ступенью. Он годится только для обращения в камеру: **камеру он не
двигает** (проверено дважды замером). Человек, который ИДЁТ и говорит, снимается связкой.

```bash
cd webapp
# 1) действие — seedance даёт ход камеры, тело и второго актёра; речи у него нет
RUN_SERIES_ID=… RUN_EPISODE_ID=… npx tsx scripts/run/gen-video.ts \
  --frame ../FILMS/_run/<эп>/frames/<кадр>.png \
  --prompt-file ../FILMS/_run/<эп>/prompts/SS-…-PRO-<slug>-v01-DRAFT.txt \
  --duration 5|10 --tier standard --shot <sh> --out ../FILMS/_run/<эп>/clips/<имя>.mp4
# 2) губы — sync-lipsync/v3 поверх готового клипа (fal, ~$0,15)
#    вход {video_url, audio_url}; движение базового клипа НЕ трогает
```

**Липсинк выбран, вопрос закрыт:** `sync-lipsync/v3`. На одном и том же клипе и звуке Kling
дал «синхронизации нет вообще», sync v3 — «синхронизация идеальная» (вердикты Директора).
Оба движение сохраняют; выбор решался слухом, не замером.

**Цена seedance — $1,51 за 5 с и $3,02 за 10 с** (720p standard). §4-бис говорил «~$0,51» —
это неправда, и на ней можно было спланировать бюджет вчетверо мимо.

**Второй живой объект и контакт РАБОТАЮТ.** Корова вошла в кадр, герой сбился, поискал
глазами ответ, похлопал её и повернул в кадр — всё с первого дубля. Условие одно: сценарий
подан ДЕЙСТВИЯМИ подряд, без описания того, что должно получиться.

### 9.35 АСПЕКТ КАДРА — подрезка, а НЕ долив (25.08, оплачено двумя дефектами разом)

`gen-video` приводит реф к аспекту рендера сам. До 25.08 он делал это **доливом**: кадр
1024×1536 (2:3) при рендере 9:16 получал 284 пикселя краевого цвета СВЕРХУ. Последствий два,
и корень у них один:

1. **Полоса уезжает в модель и остаётся в клипе** серым полем над головой. Директор увидел
   её в двух роликах подряд, прежде чем причину нашли.
2. **Герой занимает 84% кадра**, модель перерисовывает лицо мельче — и оно ПЛЫВЁТ.

Теперь `fitToAspect` режет: 1024×1536 → 864×1536, ровно 9:16, полос нет, лицо крупнее.
Долив остался запасным путём при потере больше `MAX_CROP_SHARE` = 25% (горизонтальный кадр в
вертикальный рендер теряет 62% — там резать нельзя, выбросишь сцену).

**Правило станции: служебная полоса — не служебная.** Всё, что подмешано в референс ради
формата, модель считает частью кадра и воспроизводит. Подгонка обязана УБИРАТЬ лишнее, а не
ДОБАВЛЯТЬ своё.

### 9.36 ЧТО ЗАДАЁТСЯ ГДЕ — крупность на РЕФЕ, действие в ВИДЕО (25.08)

`seedance` оживляет поданный кадр и **камеру ближе не переставляет**: просьба «голова и шея
заполняют кадр» на поясном рефе не сработала — вышел тот же поясной. Поэтому:

| Что задаём | Где | Чем |
|---|---|---|
| крупность, оптика, свет, кожа, канон | станция РЕФА (`gen-frame`) | паспорт кадра + короткая проза |
| движение, действие, второй актёр, контакт | станция ВИДЕО (`gen-video`) | сценарий ДЕЙСТВИЯМИ |
| губы | липсинк | ничего не задаётся, кроме дорожки |

Заказ крупности в промпте видео — потраченные деньги: следующий кадр придёт той же
крупности, что реф.

### 9.37 ЗВУК УЛИЦЫ — ставится ПОСТОМ, платить не за что (26.08)

Клонированный голос приходит студийно-сухим и на уличном кадре читается как «лицо живое,
голос из кабины». Пространство добавляется фильтрами над готовым файлом:

```bash
ffmpeg -y -i in.mp4 -filter_complex "[0:a]highpass=f=120,equalizer=f=220:t=q:w=1.2:g=-3,aecho=0.85:0.5:23|41|67:0.10|0.07|0.05,lowpass=f=9500[voice];anoisesrc=d=11:c=pink:a=0.006,highpass=f=180,lowpass=f=2500[amb];[voice][amb]amix=inputs=2:weights=1 0.35:duration=first[a]" -map 0:v -map "[a]" -c:v copy -c:a aac -b:a 192k out.mp4
```

Главный слой — **ранние отражения** (`aecho`, задержки 23/41/67 мс = стены на 4–12 м).
Затухания и задержки разделяются `|`, а не `:` — на `:` фильтр падает «No option name».

**Ремесло и пороги типа кадра живут в скилле** `speech-avatar-agitprop` §0-бис и §0-тер:
чем снимается каждый тип, порог фон/лицо и торс/фон, где задаётся крупность, почему
дорожка готовится под клип. Здесь — только вызовы.

### 9.38 СВЕДЕНИЕ ЗВУКА В КЛИП — три вещи, без которых он «немой» (26.08)

Смешение голоса с фоном тремя фильтрами даёт файл, у которого звук ЕСТЬ, а на телефоне его
НЕТ. Три причины, все три чинятся в одной команде:

1. **`amix` просаживает уровень.** Даже с `normalize=0` сумма выходит тише исходника —
   26.08 средний упал с −26,8 до −31,9 дБ. Лечится `loudnorm=I=-16:TP=-1.5:LRA=11` в конце
   цепочки: −16 LUFS — уровень, к которому приведены YouTube и телефонные плееры.
2. **Моно 32 кГц** приезжает из TTS и живёт до конца, если не сказать иначе. Часть плееров
   такую дорожку не играет вовсе. `aresample=48000` на КАЖДОМ входе + `-ar 48000 -ac 2`.
3. **Стерео** нужно явно: `aformat=channel_layouts=stereo`.

```bash
ffmpeg -y -i clip.mp4 -i amb.mp3 -filter_complex "[0:a]aresample=48000,<обработка голоса>[voice];[1:a]aresample=48000,volume=0.10[amb];[voice][amb]amix=inputs=2:duration=first:normalize=0,loudnorm=I=-16:TP=-1.5:LRA=11,aformat=channel_layouts=stereo[a]" -map 0:v -map "[a]" -c:v copy -c:a aac -b:a 192k -ar 48000 -ac 2 out.mp4
```

**Приёмка звука — числом, а не ухом:** `ffmpeg -i out.mp4 -af volumedetect -f null -`.
Средний ниже −25 дБ = на телефоне будет «тихо или ничего»; целимся в −20…−16.

**Клип, собранный ремуксом, у зрителя может МОЛЧАТЬ при технически исправной дорожке.
Не гадай — собери эталонно:** видео перекодировать (не `-c:v copy`), `-movflags +faststart`
(moov в начало, иначе он уезжает на мегабайты вглубь), `-shortest` (аудио не длиннее видео),
стерео 48 кГц. 26.08 два файла с ОДИНАКОВЫМИ кодеком, частотой, каналами и длительностью вели
себя по-разному — один играл, другой молчал; объяснения в свойствах дорожки не нашлось, а
эталонная сборка вылечила. И всегда клади рядом mp3 того же микса: он играет всегда и
отделяет дефект файла от дефекта плеера.

**Атмосферу генерит `fal-ai/thinksound` ПО ВИДЕО** (~$0,05, 1–4 мин). Вход у него — это
техзадание: увидит говорящий рот — сочинит речь на несуществующем языке (поймано 26.08).
Показывать надо ТОЛЬКО то, что должно звучать: кроп верхней полосы кадра без лица.

### 9.40 СТАНЦИЯ ЗВУКА — ПЕРЬЯ ЕСТЬ (27.08). §9.39 закрыт

Разрыв «знаем как, нечем» закрыт двумя инструментами. Он стоил немого клипа:
Полина довела эпизод до видео и встала, потому что положить звук было нечем.

```bash
cd webapp
# 1) речь тактами — дуга собирается кусками, монотонность это её отсутствие
npx tsx scripts/run/gen-speech.ts \
  --line "Узнавание@0.95 | Переворот@0.90:0.9 | Цена@0.88 | Призыв@0.95:1.05" \
  --voice <id клона> --out ../FILMS/_run/<эп>/audio/line.mp3 --pad-to 10.1
# 2) звук на клип: губы, атмосфера ПО ВИДЕО, сведение с проверкой уровня
npx tsx scripts/run/dub-clip.ts --clip <клип>.mp4 --voice line.mp3 \
  --out <готовый>.mp4 --lipsync yes|no --ambience yes --ambience-level 0.05
```

**`--lipsync no` — когда говорит НЕ тот, кто в кадре.** Голос за кадром, диктор,
мысли героя: губы двигать нечему, а липсинк исказит лицо ради несуществующей речи.

**Уровень фона решает Директор, не инструмент.** 0,05 — «не тишина», 0,15 — двор
слышен как событие. Умолчание тихое: фон, который заметен, спорит с речью.

**`dub-clip` меряет уровень САМ** и говорит, если средний ниже −25 дБ. Но приёмка
изделия — всё равно `measure-clip`: он же ловит немоту, которая до 26.08 проходила
как «нечего судить».

**Что рядом лежит и инструментом НЕ является:** одноразовые скрипты в scratchpad от
смоуков 25–26.08. Они писались до появления перьев, не пишут в леджер и не
оставляют следа в студии. Брать из них можно ЗНАНИЕ (какая модель, какие
параметры), запускать — нельзя.

### 9.39 СТАНЦИЯ ЗВУКА ПЕРЬЕВ НЕ ИМЕЕТ — рецепт есть, инструмента нет (26.08)

Инвентарь `scripts/run/` — двадцать инструментов: кадр, видео, канон, статус, сборка,
публикация. **Ни одного для речи, липсинка, эмбиенса и сведения звука.** Всё, что описано в
§9.31–9.38, выполнялось одноразовыми скриптами, которые пишутся и удаляются в том же ходе.

**Что это значит практически.** Ход, пришедший по маршруту, найдёт в нём готовые команды —
и не найдёт инструмента, который их исполняет. У Полины руки есть
(`Bash, PowerShell, Read, Write, Edit, Skill, WebSearch, WebFetch` — константа `ALLOWED_TOOLS`
в `mind-bridge.ts`), то есть `npx tsx scripts/run/*` она запустить может. Упрётся не в права,
а в отсутствие пера.

**Пока перьев нет, станция звука — работа Тео руками.** Поручать её другому исполнителю
нельзя: он будет писать одноразовый скрипт с нуля, без записи в леджер и без следа в студии,
то есть повторит все три дефекта, за которые заплачено раньше.

**Чего не хватает (минимум два пера, не четыре — по анти-аддитивности):**

| Перо | Что берёт на себя | Из чего собирается |
|---|---|---|
| `gen-speech` | клон голоса, такты со своими `speed`/`vol`, паузы дугой, склейка, дотяжка тишиной под клип | §9.31 |
| `dub-clip` | липсинк (`sync-lipsync/v3`), эмбиенс по видео с кропом входа, сведение с `loudnorm` и проверкой уровня | §9.34 · §9.37 · §9.38 |

Оба обязаны, как остальные: печатать контракт по `--help`, звать `recordCost`, оставлять
след `register-media`, отказываться без `RUN_EPISODE_ID`.

**Правило: рецепт в маршруте — это ещё не инструмент.** Записанный вызов повторяет ТОТ, кто
его написал; всем остальным нужно перо. Разрыв «знаем как, нечем» не виден, пока работу
делает автор рецепта, и вскрывается ровно в момент передачи.

### 9.43 ЖАНР — ПЕРВЫЙ ВОПРОС, а движки включаются САМИ (28.08)

**Закон (Директор, 28.08):** жанровые движки не выбираются руками и не назначаются
раннером — они включаются автоматически, как только назван жанр серии. Поэтому жанр
входит в ПЕРВЫЕ вопросы ассистента к Директору при заведении серии, наравне с каналом и
форматом. Спросить его позже — значит дать сценаристу и раскадровщику работать вслепую.

**Проверка — загрузчиком, не глазами.** Назвав жанр, ассистент обязан убедиться, что у
него есть движки, и назвать пустоты вслух:

```bash
cd webapp
npx tsx -e "import('./lib/agents/load-skills').then(async m=>{for(const a of ['EXEC-SW','EXEC-SB','EXEC-CREAD','EXEC-EREF-DESIGNER']){const r=await m.getAgentSkillManifest({agentId:a,genre:'<жанр>'});console.log(a, r.available.map(s=>s.slug).join(', ')||'— ПУСТО')}})"
```

Пусто у `EXEC-CREAD` — критик будет HALT'ить каждую раскадровку (штатное поведение, не
поломка). Пусто у `EXEC-SB`/`EXEC-EREF-DESIGNER` — работа пойдёт, но без движка, и
этого никто не заметит: **отсутствие движка молчит громче, чем HALT.**

**Новый жанр заводится СТРОКОЙ В СКИЛЛЕ, а не правкой раннера.** До 28.08 у дизайнера
рефов стояла своя карта `genre -> скилл` на два жанра; серия с жанром `doc` (S22) не
получала ни постановочного движка, ни паспорта кадра, хотя оба `hard` и отскоуплены
ровно на эту роль. Карта удалена — плейбуки берутся из манифеста по
`applies_when.agent` + `genre`. Вторая копия закона всегда отстаёт от первой.

**Потолки полки подняты в тот же день:** тел на вызов 24 000 -> 120 000 символов, скиллов
на вызов 5 -> 8. Прежние числа резали молча: у EXEC-SB × comedy библиотека гэгов
выбрасывалась ЦЕЛИКОМ, а паспорт кадра доезжал третью. Обрезка и выброс теперь печатают
`[skills] TRUNCATED` / `[skills] DROPPED` — молчаливое усечение было тем самым классом
отказа, который дороже всего стоит.

### 9.44 ВЕДЁШЬ УМ КАК И.О. ДИРЕКТОРА — чем говорить и чем принимать (28.08)

Прогон E03 вёлся так: Директор на дистанционке, Тео командует умом от его имени. Ниже то,

чего не было в докладе: статус DRAFT вместо предъявленного REVIEW и совпавшую крупность двух
кадров при разных числах в паспорте.

**Деньги ума в потолок НЕ идут.** `budget_log` несёт и счета провайдеров, и оценку
подписочных ходов (`model_or_tier` содержит `subscription-estimate`); гейт
`assertEpisodeReadyToSpend` сверяет с потолком только `splitLedger().direct`
(`lib/budget-split.ts`). Сырая сумма по эпизоду — НЕ расход эпизода; читая её как расход,
получаешь ложную тревогу (оплачено 28.08 неверным докладом Директору).

### 9.46 КЛОН ПУБЛИЧНОГО ЧЕЛОВЕКА НЕСЁТ АКУСТИКУ СВОЕГО ЗАЛА (28.08)

Голос, снятый с выступления на форуме, приходит с реверберацией зала — и на уличном кадре
это слышно сразу: человек стоит у реки, а звучит из-под потолка. Директор поймал на слух с
первого прослушивания. **Клон переносит не только манеру, но и ПОМЕЩЕНИЕ.**

**Второе, что слышно на длинной дорожке: паузы между тактами — абсолютный ноль.** В природе
такого не бывает; между фразами всегда звучит место. Дыра читается как обрыв записи.

Оба лечатся ПОСТОМ, ffmpeg, за ноль долларов. Проверять надо на дорожке ЦЕЛИКОМ: превью в
две секунды не показывает ни пауз, ни зала (28.08 первый вердикт был вынесен по 1,9 с и
оказался несравнимо беднее того, что дала полная дорожка).

| Слой | Чем | Что делает |
|---|---|---|
| уличная атмосфера | `anoisesrc=c=pink` (вода/ветер) + `c=brown` (дальний город), под ВСЮ дорожку | закрывает дыры, маскирует хвосты зала |
| подавление хвостов | `compand` с быстрым порогом ниже уровня речи | режет послезвучия между словами |
| срез «зальности» | два узких выреза `equalizer` на ~2,1 и ~3,4 кГц + `lowpass=9000` | снимает окраску зала, не трогая разборчивость |
| БЛИЗКАЯ стена | `aecho` 18/29/44 мс | ставит поверхность в 3–7 м; ухо берёт БЛИЖАЙШЕЕ отражение за истину, и дальний зал уходит на второй план |

Последняя строка — главная: **дальнюю акустику не вычищают, её ПЕРЕКРЫВАЮТ ближней.**
Дешевле и надёжнее, чем пытаться «вычесть» реверберацию.

**Чего у станции пока НЕТ.** `run/dub-clip` умеет атмосферу (генерацией по видео), липсинк
и сведение с `loudnorm` — но подавления реверберации, срезов зальной середины и ранних
отражений в нём нет. Пока не добавлено — это ffmpeg руками, и **обязательно через
файл-скрипт**, не длинной строкой с кавычками (§9.15).

**Приёмка — числом:** все варианты сводятся к одному уровню (`loudnorm I=-16`) и
сверяются `volumedetect`; сравнивать на слух дорожки разной громкости бессмысленно —
громкая всегда «лучше».

### 9.47 ЛОГИЧЕСКОЕ УДАРЕНИЕ СТАВИТСЯ ТАКТАМИ, А НЕ ПЕРЕПИСЫВАНИЕМ ТЕКСТА (28.08)

«Это НАШ дом» и «это наш ДОМ» — разные высказывания: первое утверждает принадлежность,
второе называет объект. Директор поймал это на слух в готовой дорожке.

Провайдер речи ударением не управляет — но им управляет РАЗБИВКА:

```bash
# слово выносится отдельным тактом со своей скоростью и громкостью, пауза сокращается
npx tsx scripts/run/gen-speech.ts --line "Это@0.95 | наш@0.78:1.15 | дом.@0.90" --gap 0.10 …
# мягче: ударное слово внутри такта на пониженной скорости, пауза ПЕРЕД следующим
npx tsx scripts/run/gen-speech.ts --line "Это наш@0.82:1.12 | дом.@0.95" --gap 0.16 …
```

Умолчание `--gap 0.5` для ударения слишком велико — пауза в полсекунды внутри короткой
фразы читается как обрыв, а не как акцент. Для акцента 0,10–0,18.

**Варианты ударения генерируются ИЗ КЛОНА заново**, а не обработкой готовой дорожки: закон
опоры (§9.46) действует и здесь.
